在 `ConcurrentLinkedDeque` 中，频繁向队列尾部添加元素确实可能导致 CPU 占用较高的问题。这是因为它采用了无锁的 **CAS（Compare-And-Swap）** 操作，在高并发场景下会引发竞争，从而导致性能下降。


## **推荐方案**

- **单线程线程池**：如果插入顺序重要，适合使用单线程化队列。
- **分段锁或分片队列**：如果高并发下性能问题严重，可以使用分段锁或分片设计。
- **Disruptor**：如果需要极致性能，并愿意承担一定学习成本，可以考虑引入 Disruptor。

这些方案可以根据具体的业务需求灵活选择。**行为的复杂性和代码的维护成本也是需要考虑的关键因素。**

### **为何单线程 + 无界队列适合这种场景？**

1. **避免多线程切换的开销**：
    
    - 单线程池内部只有一个线程，因此无需多线程的上下文切换，减少了 CPU 开销。
2. **任务按照提交顺序执行**：
    
    - 单线程池保证了任务按 FIFO 顺序执行，无需担心任务执行顺序紊乱。
3. **无锁化设计**：
    
    - 单线程池处理任务时只会有一个线程运行，完全不涉及锁竞争。
4. **低复杂性**：
    
    - 使用无界队列时，不需要关心队列满的情况，且单线程的实现逻辑相对简单。
