


我们通过反射调用了 `Person` 类的 `getName` 方法，并通过直接方法调用获取了相同的结果。在这个例子中，反射调用涉及获取方法对象、访问控制检查等操作，而直接调用则直接执行方法。

在实际应用中，应该根据具体的需求和性能要求来选择使用反射还是直接方法调用。在大多数情况下，静态绑定（直接方法调用）通常比动态绑定（反射调用）更为高效。



`AccessController.doPrivileged` 是 Java 中的一个安全管理工具，用于在有安全管理器（Security Manager）的环境中执行一段代码，并忽略当前访问控制上下文的限制。它的使用通常涉及到处理敏感的、需要特殊权限的代码块。

在 Java 中，如果存在安全管理器，它会控制对系统资源（如文件、网络访问等）的访问。`AccessController.doPrivileged` 的目的是允许某段代码在获取一些特殊权限时绕过安全管理器的检查。

### JIT优化, 可见性和参数检查， 数组遍历， 包装和拆包(Object)


1. **动态解析与 JIT 优化：** 静态编译语言如 Java 在运行时进行动态解析，即查找和确定调用的方法或字段。这个过程通常无法被 JIT 编译器优化，因为 JIT 通常在静态绑定的情况下进行优化。相比之下，静态绑定的调用（直接方法调用）可以更容易地受益于 JIT 优化。
    
2. **参数的包装与拆箱：** 在反射中，方法的参数需要包装成 `Object[]` 类型，这带来了额外的装箱开销。然后，在方法的真正执行过程中，这些参数需要被拆箱成真正的类型。这种装箱和拆箱的操作不仅消耗时间，还可能引发额外的垃圾收集（GC）压力，因为会创建和丢弃大量临时对象。
		在反射中，当参数需要被传递给方法时，需要将原始类型的参数包装成对应的包装类型，以便能够以 `Object` 类型的形式传递。这个过程就是装箱（Boxing）。而在方法内部执行时，又需要将这些包装类型的参数还原成原始类型，这个过程就是拆箱（Unboxing）。这两个过程中都可能涉及到创建和丢弃临时对象。
		具体来说，装箱过程中会创建包装类型的对象，而拆箱过程中可能会丢弃这些对象。例如，将基本类型 `int` 装箱成 `Integer` 对象，然后在方法内部将 `Integer` 对象拆箱为 `int`。这个过程中就产生了临时对象。
3. **数组遍历：** 反射调用需要遍历数组以获取方法或字段。这个遍历过程也会引入性能开销，尤其是在频繁的反射调用中。

4. **可见性和参数检查：** 反射调用需要进行访问控制检查以确保对方法的可见性。此外，参数也需要进行额外的检查，以确保它们与方法的签名匹配。这些检查会增加反射调用的开销。
	1. 反射调用还需要确保传递的参数与方法的签名匹配。这包括参数的类型、数量等。在调用时，系统需要进行参数检查以确保反射调用的正确性。如果参数不匹配，将引发 `IllegalArgumentException` 或类似的异常。这些检查可能导致额外的开销。
	2. **可见性检查：** 反射调用需要确保在运行时访问的类、字段或方法是可见的。这涉及到对 Java 中访问修饰符（`public`、`private`、`protected`、包私有等）的检查。例如，如果要通过反射调用一个私有方法，系统需要检查当前执行代码的访问权限是否足够。这样的检查可能导致一些性能开销，特别是在频繁进行私有方法的反射调用时。
