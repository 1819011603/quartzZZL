


### Java 泛型不足


**泛型** 是一种编程语言特性，允许编写与数据类型无关的代码。这样，程序可以在编译时确定类型，减少代码重复，提高类型安全性。

- **协变**（Covariance）：表示可以安全地将**子类型**的对象赋值给父类型的引用。例如，如果 `String` 是 `Object` 的子类型，那么 `List<String>` 也可以看作是 `List<Object>`（满足子类型替换原则）。
- **逆变**（Contravariance）：与协变相反，表示父类型可以安全地替换为子类型。
- **不变**（Invariance）：泛型类型默认是不变的，即使 `String` 是 `Object` 的子类型，`List<String>` 和 `List<Object>` 是完全不同的类型。


## **逆变与协变的对比**

| **概念** | **定义**       | **适用场景**   | **示例**                           |
| ------ | ------------ | ---------- | -------------------------------- |
| **协变** | 子类型可以替换父类型   | **数据读取**场景 | `List<? extends Number>`         |
| **逆变** | 父类型可以替换子类型   | **数据写入**场景 | `List<? super Integer>`          |
| **不变** | 泛型类型之间没有继承关系 | 泛型默认行为     | `List<Number>` ≠ `List<Integer>` |
|        |              |            |                                  |

与 C++ 和 C# 等成熟语言相比，Java 泛型存在以下不足：

1. **类型擦除**：泛型在运行时被擦除，导致无法获取类型信息，限制了高级功能（如反射、序列化等）。
2. **泛型与数组不兼容**：无法创建泛型数组，影响了开发的灵活性。
3. **不支持基本类型**：泛型只能用于引用类型，导致装箱/拆箱的性能开销。
4. **协变与逆变受限**：语法复杂且限制较多，不如 C# 简洁直观。
5. **不变性**：泛型默认不变，无法在子类和父类泛型之间进行自动转换。


Java 不支持创建泛型数组，因为泛型类型在运行时被擦除，数组的类型检查依赖于运行时的类型信息。

- **示例**：
    
    `List<String>[] lists = new ArrayList<String>[10]; // 编译错误`
    
- **原因**：数组具有运行时的类型检查机制，而泛型会在运行时擦除类型信息，无法保证类型安全。
    
- **解决方案**：使用集合（如 `List`）代替数组，或使用 `@SuppressWarnings` 忽略编译器警告，但这并非理想的解决方案。

### **1.4 泛型和协变/逆变限制**

Java 的泛型支持协变（`? extends T`）和逆变（`? super T`），但其实现比较受限。

1. **不能添加元素到协变类型中**（`? extends T`）：
    
    `List<? extends Number> list = new ArrayList<Integer>(); list.add(42); // 编译错误`
    
    - **原因**：编译器无法确定 `?` 的具体类型，无法确保类型安全。
2. **不能安全地读取逆变类型的元素**（`? super T`）：
    
    `List<? super Integer> list = new ArrayList<Number>(); Number num = list.get(0); // 编译错误`
    
    - **原因**：编译器无法确定逆变泛型中存储的具体类型。

### 为什么 `clazz.cast(obj)` 可以绕过编译时检查？

在 Java 中，编译器在编译阶段进行类型检查。一般来说，如果我们想要将一个 `Object` 类型转换成某个特定类型，需要使用显式类型转换。例如：String str = (String) obj;


但是，编译器必须在编译时知道 `String` 的类型。而 `clazz.cast(obj)` 则是在运行时执行类型检查。Java 的泛型使用的是**类型擦除**机制，泛型类型在编译时会被擦除，JVM 在运行时并不知道泛型的具体类型。因此，当我们使用反射的 `cast()` 方法时，编译器只会检查它的返回类型是否符合预期，而不在乎运行时的实际类型是什么。这种机制可以绕过编译时的静态检查，延迟到运行时.

### `clazz.cast(obj)` 的运行时类型检查过程

`clazz.cast(obj)` 的实现类似于以下逻辑：

1. `clazz.isInstance(obj)`：检查 `obj` 是否是 `clazz` 的实例。
2. 如果是，将 `obj` 转换为 `clazz` 类型，并返回该值。
3. 如果不是，抛出 `ClassCastException`。

```java

import java.lang.reflect.Type;  
  
public class TypeCastingUtil {  
  
    @SuppressWarnings("unchecked")  
    public static <T> T cast(Object obj, Type type) {  
        // 检查 Type 是否为 Class 类型  
        if (type instanceof Class<?>) {  
            Class<T> clazz = (Class<T>) type;  
            return clazz.cast(obj);  
        }  
        throw new IllegalArgumentException("不支持的 Type 类型: " + type.getTypeName());  
    }  
}
```

```java
import static com.google.common.base.Preconditions.checkArgument;  
  
import java.lang.reflect.ParameterizedType;  
import java.lang.reflect.Type;  
  
/**  
 * Captures the actual type of {@code T}.  
 * * @author Ben Yu  
 */abstract class TypeCapture<T> {  
  
  /** Returns the captured type. */  
  final Type capture() {  
    Type superclass = getClass().getGenericSuperclass();

    return ((ParameterizedType) superclass).getActualTypeArguments()[0];
```

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

// 定义一个带有两个泛型参数的类
class A<B, C> {
}

// 一个子类来继承泛型类 A 并指定具体的类型参数
class MyClass extends A<String, Integer> {
}

public class GenericTypeDemo {
    public static void main(String[] args) {
        // 创建一个 MyClass 的实例
        MyClass myClassInstance = new MyClass();

        // 获取泛型父类的信息
        Type superclassType = myClassInstance.getClass().getGenericSuperclass();
        
        if (superclassType instanceof ParameterizedType) {
            // 将父类类型强转为 ParameterizedType 以获取泛型参数
            ParameterizedType parameterizedType = (ParameterizedType) superclassType;

            // 获取泛型参数列表
            Type[] typeArguments = parameterizedType.getActualTypeArguments();

            // 分别获取 B 和 C 的类型
            Type typeB = typeArguments[0];  // B 的类型 (String)
            Type typeC = typeArguments[1];  // C 的类型 (Integer)

            System.out.println("B 的类型: " + typeB.getTypeName());
            System.out.println("C 的类型: " + typeC.getTypeName());
        }
    }
}
```

### 1. **泛型擦除**

Java 的泛型在编译期间会被擦除（即类型擦除），这意味着泛型参数的具体类型信息不会保留到运行时。例如，`List<String>` 和 `List<Integer>` 在编译后都变成了 `List`。这就是为什么在运行时无法直接判断 `List` 的泛型参数类型。

### 2. **Signature 标识**

编译器确实会将泛型信息保存到字节码文件中的“**Signature**”标识符后面，这些信息用于编译期的类型检查和某些反射操作。但是这些信息在运行时是不可直接访问的。

### 3. **匿名内部类与 `TypeToken`**

为了克服类型擦除带来的问题，Java 引入了一个技术叫做“**匿名内部类**”来保留运行时的泛型信息。

#### 具体实现：

- 当你通过匿名内部类 `new TypeToken<List<String>>() {}` 创建 `TypeToken` 实例时，Java 会隐式地将这个匿名内部类的泛型信息（即 `List<String>`）保存下来。由于匿名内部类会生成一个独立的子类，Java 编译器会为这个子类保留泛型的实际类型参数。
- 因此，`TypeToken<List<String>> typeToken = new TypeToken<List<String>>() {};` 创建的匿名子类保留了运行时泛型类型。

### 4. **获取泛型类型信息**

`TypeToken` 的设计目的是为了绕过类型擦除，能够在运行时获得泛型的实际类型参数。它通过反射机制，比如 `getSuperclassTypeParameter(this.getClass())`，来从字节码文件中提取出泛型信息，并将其保留在 `TypeToken` 的子类中。

### 5. **总结**

- 如果你直接 `new TypeToken<List<String>>()`，编译器会擦除泛型信息，这就是为什么我们需要用匿名内部类来声明，以确保 `List<String>` 类型在运行时被保留并能通过反射获取。
- `TypeToken` 解决了 Java 泛型擦除的问题，通过反射和匿名内部类的结合，在运行时仍然能够保留和获取泛型类型信息。
