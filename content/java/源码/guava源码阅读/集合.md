##### 不可变

- **集合的不可变性**: 当我们说一个`ImmutableCollection`是不可变的，这意味着你不能通过任何方式改变集合中的元素引用。这包括添加、删除或替换元素。集合一旦创建，其内容（即对元素的引用）就固定了。
    
- **元素本身的不可变性**: 然而，`ImmutableCollection`的不可变性并不自动保证集合中元素本身的不可变性。如果集合中的元素是可变的对象，那么这些对象的状态仍然可以被修改。


在源码注释中，提到了`ImmutableList`一个首要的特性:[`Shallow immutability`](https://github.com/google/guava/blob/0f025e5d5d39a5d1ab709917f725d48a8464df50/guava/src/com/google/common/collect/ImmutableCollection.java#L57-L70), 这里的`Shallow`用的非常精髓，让我们仔细品味一下。

在Java标准库中，`java.util.Collections`已经提供了一系列的`UnmodifiableCollection`实现，比如`UnmodifiableList`，但是这些实现有个严重的问题，当源collection被修改时，对应的`UnmodifiableCollection`也会受到影响，仿佛连体婴儿一般。不同于`UnmodifiableCollection`这样的妖艳贱货，`guava`中的`ImmutableCollection`由于使用了深拷贝，可以不受源Collection修改的影响。

相对于`UnmodifiableColletion`提供的表面的不可变性(surface immutability), `ImmutableCollection`更深一层，但为什么不用`Deep`而说是`Shallow`呢？因为它们都无法真正摆脱一个幽灵:`mutable data`。Collection 本身固然可以实现为`Immutable`, 但是Collection所包含的每个元素，却仍然可能是`mutable object`。

1. immutable,

```
具体来说，thread-hostile 代码或库可能具有以下特征：

1. 不是线程安全的：在多线程环境中可能导致数据竞争或其他并发问题。
    
2. 使用了全局变量或静态数据：这可能导致多个线程之间的意外交互。
    
3. 假设单线程执行：代码可能依赖于特定的执行顺序，在多线程环境中无法保证。
    
4. 缺乏适当的同步机制：没有使用锁、信号量等同步原语来保护共享资源。
    
5. 可能导致死锁或其他线程安全问题：在多线程环境中使用时可能引发严重的运行时错误。
```



不可变量与生俱来的线程安全性，使得函数式编程语言，天然适应大规模并发的场景。相对而言Java在这方面处于劣势，Java并发程序的编写，测试和调试都会遇到很多的陷阱和挑战。理论上来说，在Java中定义`Immutable Class`并不困难，如《Effective Java》Item15所述，需要遵循5条原则:

1. 不要提供任何改变对象状态的方法(比如set方法)。
    
2. 让该类无法被继承(public final class XXX)。
    
3. 所有的属性都声明为final。
    
4. 所有的属性都声明为private。
    
5. 如果内部有任何属性引用了可变对象，访问这些属性是需通过防御式拷贝(defensive copy)。 访问这些属性有被修改的风险, 直接返回属性的拷贝则不会修改原始的对象.



######  `isPartialView`的用途


**可以看到，`copyOf`方法是比较智能的，在参数已经是`ImmutableCollection`类型的情况下，直接复用原来的`collection`即可，其它情况下，通过`construct`方法，底层调用`Arrays.copyOf`做深拷贝。**



isPartialView()方法返回true表示该集合是另一个集合的部分视图,而不是一个独立的完整集合。这主要用于以下场景:

- 子集:例如,一个列表的子列表。
- 特殊视图:如Map的keySet()或values()返回的集合。

```java


public static <E> ImmutableList<E> copyOf(Collection<? extends E> elements) {  
  if (elements instanceof ImmutableCollection) {  
    @SuppressWarnings("unchecked") // all supported methods are covariant  
    ImmutableList<E> list = ((ImmutableCollection<E>) elements).asList();  
    return list.isPartialView() ? ImmutableList.<E>asImmutableList(list.toArray()) : list;  
  }  
  return construct(elements.toArray());  
}
```

- **性能优化**: 当一个集合是不可变的，它可能通过某种方式与其源集合共享结构以节省内存。例如，如果你从一个不可变列表中创建一个子列表，这个子列表可能实际上并不复制数据，而是引用原列表的一部分。这种情况下，子列表就是原列表的一个"部分视图"。
    
- **标识共享**: `isPartialView` 返回 `true` 表示这个不可变集合实际上是另一个更大集合的一部分。这意味着对集合的任何修改（如果允许的话）可能会影响到原始集合或者其他共享这个视图的集合。
    
- **安全性与一致性**: 在多线程环境中，如果一个线程在操作这个集合的同时，另一个线程可能在操作原始集合或其他共享视图的集合，了解是否是部分视图可以帮助判断是否需要额外的同步措施或者是否需要创建一个完全独立的副本。
    







### 子视图

```java

/**
 * SubList类是ImmutableList的一个子类，表示不可变列表的子列表。
 */
class SubList extends ImmutableList<E> {
  // 子列表的起始偏移量
  final transient int offset;
  // 子列表的长度
  final transient int length;

  /**
   * 构造一个新的SubList实例。
   *
   * @param offset 子列表的起始偏移量
   * @param length 子列表的长度
   */
  SubList(int offset, int length) {
    this.offset = offset;
    this.length = length;
  }

  /**
   * 返回子列表的大小。
   *
   * @return 子列表的长度
   */
  @Override
  public int size() {
    return length;
  }

  /**
   * 返回子列表中指定位置的元素。
   *
   * @param index 元素在子列表中的索引
   * @return 子列表中指定位置的元素
   * @throws IndexOutOfBoundsException 如果索引超出范围
   */
  @Override
  public E get(int index) {
    checkElementIndex(index, length);
    return ImmutableList.this.get(index + offset);
  }

  /**
   * 返回子列表的一个子列表，范围从fromIndex（包括）到toIndex（不包括）。
   *
   * @param fromIndex 子列表的起始索引（包括）
   * @param toIndex 子列表的结束索引（不包括）
   * @return 子列表的一个子列表
   * @throws IndexOutOfBoundsException 如果索引超出范围
   */
  @Override
  public ImmutableList<E> subList(int fromIndex, int toIndex) {
    checkPositionIndexes(fromIndex, toIndex, length);
    return ImmutableList.this.subList(fromIndex + offset, toIndex + offset);
  }

  /**
   * 返回子列表是否是部分视图。
   *
   * @return true表示子列表是部分视图
   */
  @Override
  boolean isPartialView() {
    return true;
  }
}
```

实际开发中我们也可以利用Map<E, Integer>来实现计数功能，但它和Multiset还是有很大区别的，首先Multiset也不是Map<E, Integer>类型的结构，区别如下：

    1、Multiset中的元素出现的次数只能为正数，前面说了原因。如果E的出现次数为0，那么E将不出现在multiset中，是不能在elementSet()和entrySet()的视图中；

    2、multiset.size()返回这个集合的大小，相当于在multiset中元素的出现的总数。如果想得到multiset中不同元素出现的总数，可以利用elementSet().size()来实现；

    3、multiset.iterator()可以遍历multiset中的所有元素，所以iteration遍历的次数就等于multiset.size()；

    4、Multiset支持添加、删除元素，设置元素出现的次数；setCount(elem, 0)相当于移除elem的所有元素；

    5、multiset.count(elem)方法中的elem如果没有出现在Multiset中，那么它的返回值永远都是0。
