CPU负载：

假设一个售票人员一分钟最多可处理10个游客， 那么一分钟内如果只有2个游客， 则CPU的负载为0.2 ； 如果遇到国庆高峰假期，突然来了30个游客， 则一分钟内的负载为 30 / 10 = 3 , 来50个游客就是 50 / 10 = 5

基础计算方法明白后， 我们来找点乐子：

售票室网络特别卡，导致售票人员工作4分钟， 等待网络刷新票6分钟， 此时CPU利用率为40%。 然后又赶上了高峰期， 来了90个游客， 所以CPU负载为 9 。也就是CPU利用率很低，但CPU负载特别高。

### linux 计算每核平均cpu 负载
```
在 Linux 中，每核平均 CPU 负载是通过将系统的负载平均值与 CPU 核心数进行比较计算得出的。具体来说，在 Linux 中可以使用 uptime 命令来获取系统负载平均值，并手动计算每核平均 CPU 负载。

假设我们已经使用 uptime 命令获取了系统的负载平均值，分别为 1 分钟、5 分钟和 15 分钟内的平均活跃进程数（load average）。然后，我们可以按以下方式计算每核平均 CPU 负载：

获取 CPU 核心数：

首先，使用以下命令获取系统的 CPU 核心数：

nproc

计算每核平均 CPU 负载：

对于每个时间间隔（1分钟、5分钟、15分钟），将 load average 除以 CPU 核心数即可得到每核平均 CPU 负载。例如，如果 load average 分别为 2.5、2.0 和 1.5，而 CPU 核心数为 4，则每核平均 CPU 负载分别为 2.5 / 4 = 0.625、2.0 / 4 = 0.5 和 1.5 / 4 = 0.375。

虽然 Linux 没有专门的命令直接提供每核平均 CPU 负载，但可以通过简单的计算来获得这个指标。
```




`uptime` 命令显示的平均负载（load average）是系统活跃进程数的平均值，具体来说是在过去 1 分钟、5 分钟和 15 分钟内运行队列中的平均进程数。

在 Linux 系统中，这个平均负载是通过计算运行队列中的进程数量来得到的。运行队列是指正在等待 CPU 时间片的进程队列。当运行队列中的进程数超过了 CPU 核心数时，就可能会出现性能瓶颈，系统的响应速度可能会变慢。

具体地，平均负载的计算方式为：

- 对于过去 1 分钟、5 分钟和 15 分钟内的平均负载，分别是运行队列中的平均进程数。
- 例如，load average: 0.52, 0.48, 0.51 表示过去 1 分钟、5 分钟和 15 分钟内的平均活跃进程数分别为 0.52、0.48 和 0.51。

这些数字反映了系统负载的状况，可帮助管理员了解系统的繁忙程度。通常情况下，平均负载应该保持在 CPU 核心数量的范围内，超过这个范围可能意味着系统负载过重，需要进一步排查和优化。

`vmstat` 是一个性能分析工具，它提供了系统的虚拟内存、进程、CPU 和系统调度等方面的详细统计信息。以下是 `vmstat` 命令输出中各个字段的含义以及与 CPU 负载平均值相关的指标：

`vmstat` 输出的各字段含义如下：

- **Procs**：包含了进程相关的统计信息。
    
    - `r`: 正在运行或者等待CPU的进程数。
    - `b`: 不可中断的睡眠状态进程数。
- **Memory**：包含了内存相关的统计信息。
    
    - `swpd`：交换到磁盘的内存大小。
    - `free`：空闲内存大小。
    - `buff`：用作缓冲的内存大小。
    - `cache`：用作缓存的内存大小。
- **Swap**：包含了交换空间的统计信息。
    
    - `si`：每秒从磁盘交换到内存的大小（swap in）。
    - `so`：每秒从内存交换到磁盘的大小（swap out）。
- **IO**：包含了I/O操作相关的统计信息。
    
    - `bi`：每秒读取的块数。
    - `bo`：每秒写入的块数。
- **System**：包含了系统调度和上下文切换等相关的统计信息。
    
    - `in`：每秒产生的中断数。
    - `cs`：每秒上下文切换次数。
- **CPU**：包含了CPU使用情况相关的统计信息。
    
    - `us`（user）：用户空间占用CPU的时间百分比。
    - `sy`（system）：内核空间占用CPU的时间百分比。
    - `id`（idle）：CPU处于空闲状态的时间百分比。
    - `wa`（waiting）：等待I/O操作完成所消耗的CPU时间百分比。
    - `st`（stolen）：被偷走的CPU时间百分比（由虚拟化环境中的其他虚拟机消耗）。

与 CPU 负载平均值相关的指标主要是 `us`、`sy`、`id` 和 `wa`。其中，`us` 和 `sy` 表示 CPU 使用率，`id` 表示空闲 CPU 时间，`wa` 表示等待 I/O 的 CPU 时间。这些指标可以帮助我们理解系统中 CPU 的负载情况，特别是在 `vmstat` 命令的输出中，这些指标可以帮助分析系统的 CPU 利用率和性能瓶颈。

在现代服务器中，逻辑 CPU 核心数通常比物理 CPU 核心数量多。这是因为现代 CPU 支持超线程（Hyper-Threading）技术，这种技术可以让每个物理 CPU 核心模拟出多个逻辑 CPU 核心。这意味着每个物理 CPU 核心能够同时处理多个线程，从而提高了 CPU 的利用率和性能。

使用超线程技术带来的好处包括：

1. **更高的并发处理能力：** 当多个线程需要被执行时，超线程技术使得 CPU 能够更有效地处理这些线程，从而提高系统的并发处理能力。
2. **更好的资源利用率：** 在某些情况下，即使一个线程正在等待某些资源（比如内存或者I/O），CPU 也可以继续执行其他线程，从而更充分地利用了 CPU 的计算能力。

总之，超线程技术通过在每个物理 CPU 核心上模拟多个逻辑 CPU 核心，提高了系统的并发处理能力和资源利用率，从而改善了系统的整体性能。因此，现代服务器通常会配置具有多个逻辑 CPU 核心的 CPU，以提供更好的性能和响应能力。

####  sar 如何收集cpu信息

sar 命令可以用来收集系统性能数据，包括 CPU 使用率。要收集 CPU 信息，您可以使用以下命令

```
sar -u 5 10
```
这条命令将每 5 秒钟收集一次关于 CPU 使用率的数据，共收集 10 次。
