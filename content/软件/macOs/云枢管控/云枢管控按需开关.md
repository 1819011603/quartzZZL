# 云枢(EagleYun)管控按需开关

个人电脑上装了公司的合规软件「云枢」,关不掉、杀掉又自动复活。这篇记录它为什么关不掉、怎么做成一键开关,以及注意事项。

> 场景:偶尔在家用个人电脑办公,装了云枢连内网。不想让它 7×24 常驻采集,只在真正办公时开启。

---

## 它是什么

`/Applications/Yunshu.app`(界面)背后真正跑的是 `/opt/.yunshu/` 里的 **EagleYun 鹰云 SASE 零信任终端管控套件**,以 root 常驻。从 `/opt/.yunshu/config/` 能看出它开着:

- 文件/文件系统事件审计(`fsevents.db`、`process_config`、160MB 的 `ddr_trace_db.db`)
- 剪贴板管控与记录(`clipboard_policies_config`)
- 敏感数据 DLP 扫描(`sensitive_config`)
- 文件/打印水印(`file_water_config`、`PrinterMarkEnable`)、窗口事件(`wmevents.db`)
- MDM 纳管(`mdm_config`)、pf 防火墙规则(`pf.conf`)
- 安装时把 SIP 关掉了(`csrutil status: disabled`)

## 为什么关不掉(自我唤醒)

**反篡改设计:两个特权守护互相看门**,`kill` 掉进程会被秒级复活。

| launchd 配置 | 身份 | 作用 |
|---|---|---|
| `/Library/LaunchDaemons/com.eagleyun.sase.servicemanager.plist` | root | 跑 `YunshuManager`,`KeepAlive=true` 自动重启 |
| `/Library/LaunchDaemons/com.eagleyun.sase.helper.plist` | root | 跑 `/Library/PrivilegedHelperTools/com.eagleyun.sase.helper`,**监视主服务、被停就重新拉起** |
| `/Library/LaunchAgents/com.eagleyun.endpoint.agent.plist` | 用户会话 | 前台 agent |

只 `bootout` 一个 → 另一个把它 bootstrap 回来(`launchctl print` 里 `runs=2` 就是复活痕迹)。
**必须:先 `disable` 两个(让复活时 bootstrap 失败)→ 再一起 `bootout` → 杀进程 → 收前台 App。**

## 怎么用(已做成脚本 + Alfred)

三个文件(本目录有副本,实际使用的在家目录 `~/`):

| 文件 | 作用 |
|---|---|
| `~/yunshu-toggle.sh` | 核心开关(含前台 App 收尾),需 root |
| `~/yunshu-gui.sh` | 弹 macOS 图形密码框、给 Alfred/双击 调的包装 |
| `~/Downloads/Yunshu-Toggle.alfredworkflow` | Alfred workflow 包 |

### 命令行用法

```bash
sudo ~/yunshu-toggle.sh off      # 下班/私人时间 → 停掉,不再采集
sudo ~/yunshu-toggle.sh on       # 要在家办公 → 打开,恢复内网访问
sudo ~/yunshu-toggle.sh status   # 看现在跑没跑
```

### Alfred 用法

双击 `Yunshu-Toggle.alfredworkflow` 导入(**需 Alfred Powerpack 付费版**)。呼出 Alfred(⌥Space)输入关键词 `yunshu`:

```
yunshu off      关闭云枢(私人时间)
yunshu on       打开云枢(在家办公前)
yunshu          留空 = 只查状态
```

`on`/`off` 会弹 macOS 管理员密码框授权,执行完右上角通知结果。`yunshu` 查状态不需密码。

> 没有 Powerpack 就用 `~/yunshu-gui.sh off` 做成双击的 `.command` 文件,或 macOS 快捷指令,效果一样。

## 重要提醒

- **`off` 时内网大概率连不上**——它就是零信任网关。顺序永远是先 `on` 再干活。
- **重启会自动把它拉回来**(plist 的 `RunAtLoad`)。开机后想保持关闭,重跑一次 `off`。
- 脚本**只停用、不删文件**,完全可逆,不会触发「文件被删」的完整性告警。
- **`off` 动作可能被服务端上报;MDM 也可能远程重新装/启回来**(有 `mdm_config`)。若 `off` 完又莫名"运行中",说明 watchdog 层级更深(系统扩展/自愈线程/远程下发),本地已很难干净关掉。
- 从个人设备角度,「只在办公时段开启管控」是合理边界;真被问到,理由很硬。最省心的长期解法仍是:办公挪回工作机,个人电脑别常驻。

## 恢复到「它自己管自己」

```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/com.eagleyun.sase.servicemanager.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.eagleyun.sase.helper.plist
# 或直接重启,脚本没改任何文件
```

## 排查命令备忘

```bash
# 谁在跑
pgrep -fl -i yunshu
launchctl list | grep -i -E "eagle|yunshu"
# 主服务 launchd 状态(runs/pid/keepalive)
sudo launchctl print system/com.eagleyun.sase.servicemanager | grep -E "state|pid|runs"
# 全盘找相关 launchd 配置
grep -rli -E "yunshu|eagleyun" /Library/LaunchDaemons/ /Library/LaunchAgents/ ~/Library/LaunchAgents/
```
