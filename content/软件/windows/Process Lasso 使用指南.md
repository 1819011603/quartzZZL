## 一、理解它在做什么

Windows 默认的进程调度是"平等竞争"，任何程序突然爆发都能抢占系统资源，导致前台卡死。

Process Lasso 的价值在于**主动干预这个竞争**，核心逻辑是：

- **ProBalance**：检测到某进程 CPU 突刺时，临时降低其优先级，保护前台响应性，平息后自动恢复
- **优先级规则**：告诉系统"谁更重要"，资源紧张时优先保障
- **CPU 亲和性**：把后台程序赶到效率核，把性能核留给你正在用的软件
- **模式切换**：日常让它自动管理，高负载任务时解除限制全速运行

> **平衡模式 = ProBalance 工作**，是日常最优解。性能模式是关掉 ProBalance，适合游戏或渲染等单一高负载场景。

---

## 二、基础设置

**选项 → 常规**

- 随 Windows 启动，后台服务模式运行
- 启动时最小化托盘，不打扰日常使用

**模式选择原则**

| 场景 | 模式 |
|------|------|
| 日常办公、开发、浏览器 | 平衡模式 |
| 游戏、视频渲染、跑测试 | 性能模式 |
| 笔记本省电 | 省电模式 |

---

## 三、ProBalance 配置

**选项 → ProBalance**

- 启用 ProBalance ✓
- 勾选"不约束前台进程"✓（核心，保护你正操作的窗口）
- 启用事件日志 ✓（方便后期排查哪些程序频繁触发）

**从 ProBalance 排除的进程**（右键进程 → 排除）

这些是系统核心，降优先级会造成音频爆音或界面异常：

```
audiodg.exe      音频引擎
csrss.exe        Windows 子系统
dwm.exe          桌面窗口管理器
```

**如何判断 ProBalance 在工作**

托盘图标右键 → 查看日志，如果能看到某进程被临时压制的记录，说明一切正常。

## 四、优先级规则

**操作路径**：右键进程 → 始终设置优先级 → 下次启动自动生效

**思路**：前台主力拉高，后台闲置拉低，中间层保持普通。

| 进程类型 | 推荐优先级 | 说明 |
|----------|-----------|------|
| 浏览器（chrome / msedge） | 高于普通 | 保证网页流畅 |
| 开发 IDE（pycharm64） | 普通 | 启动时不抢前台 |
| 游戏主进程 | 高 | 全力保障帧率 |
| Steam 客户端 | 低于普通 | 挂后台不占资源 |
| 各类更新程序（\*update\*） | 低 | 安静更新 |
| 云盘同步（OneDrive 等） | 低 | 不干扰操作 |

**调整建议**

- 不确定的程序先保持"普通"，观察一段时间再调
- 优先级设"高"要谨慎，只给真正需要的程序，否则多个高优先级互相竞争反而乱
- 系统进程（svchost、explorer）不要动

## 五、CPU 亲和性（12600KF 专属）

12600KF 的核心结构：

```
P-Core × 6（超线程） = 逻辑处理器 0-11    高性能核，负责复杂任务
E-Core × 4           = 逻辑处理器 12-15   效率核，适合轻量后台
```

**操作路径**：右键进程 → 始终设置 CPU 亲和性

**分配原则**

| 类型 | 分配核心 | 典型进程 |
|------|---------|----------|
| 后台/低优先进程 | E-Core（12-15） | OneDrive、各云盘、\*update\*、SearchIndexer、steam |
| 前台主力进程 | P-Core（0-11） | 浏览器、PyCharm、游戏、剪辑软件 |
| 不确定的 | 全部核心（默认） | 保持默认即可 |

**调整建议**

- 亲和性规则比优先级规则影响更底层，设置前确认进程名称正确
- 某些多进程软件（如 Chrome）有多个子进程，只设主进程即可，子进程跟随
- 游戏时可临时把后台进程全部推到 E-Core，P-Core 全留给游戏

## 六、内存整理

**智能内存整理（选项 → 内存）**

- 32GB 内存场景：**建议关闭自动触发**
- 频繁自动 Trim 会把 Standby 缓存清掉，下次访问反而要重新从磁盘加载，得不偿失

**何时手动 Trim 有价值**

- 打开 PyCharm / 大型软件之前
- 某程序崩溃后内存没有释放
- 感觉系统开始变慢，内存占用明显偏高时

**操作**：托盘右键 → 修剪所有进程工作集

## 七、场景解决方案

### 开 PyCharm 时浏览器卡死

**原因**：JVM 启动产生 CPU/IO 突刺，抢占浏览器资源

**方案**：
1. ProBalance 启用，自动压制 PyCharm 启动突刺
2. pycharm64.exe 优先级设"普通"，浏览器设"高于普通"
3. 启动前手动 Trim 一次，给 JVM 留出干净内存

### 后台更新/同步导致卡顿

**原因**：更新进程和同步进程在后台悄悄跑满 IO 和 CPU

**方案**：
1. 所有 `*update*.exe` 设低优先级 + E-Core 亲和性
2. 云盘同步进程同上处理
3. SearchIndexer.exe 设 E-Core，避免索引时影响前台

### 游戏掉帧或卡顿

**原因**：后台进程竞争 P-Core，或 ProBalance 误压制了游戏进程

**方案**：
1. 切换到性能模式（关闭 ProBalance）
2. 游戏主进程设高优先级 + P-Core 亲和性
3. 将后台进程手动推到 E-Core

---

## 八、维护习惯

- **每周看一次 ProBalance 日志**：频繁被压制的进程，考虑直接设低优先级
- **新装软件后检查一次**：是否有后台服务偷跑 CPU
- **不要随意调系统进程**：svchost、lsass、explorer 保持默认
- **规则越少越好**：只给真正有问题的进程设规则，过度干预反而乱
