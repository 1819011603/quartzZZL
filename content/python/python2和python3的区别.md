


Python 2 和 Python 3 之间存在许多主要区别，以下是其中一些主要的区别：

1. print 语句：在 Python 2 中，print 是一个语句，而在 Python 3 中，print 是一个函数。
    
2. 整数除法：在 Python 2 中，整数除法会向下取整，即结果也是整数。而在 Python 3 中，整数除法会产生浮点数结果。
    
3. Unicode 字符串：在 Python 2 中，字符串默认为 ASCII 编码，而在 Python 3 中，字符串默认为 Unicode 编码。
    
4. xrange() 函数：在 Python 2 中，xrange() 函数用于生成范围内的整数序列，而在 Python 3 中，xrange() 被移除，range() 函数返回一个类似于 Python 2 中 xrange() 返回的可迭代对象。
    
5. 输入函数：在 Python 2 中，使用 raw_input() 函数获取用户输入，而在 Python 3 中，使用 input() 函数获取用户输入，返回的是字符串。
    
6. 不等运算符：在 Python 2 中，不等运算符可以使用 <>，而在 Python 3 中，不等运算符只能使用 !=。
    
7. 字典视图对象：Python 3 引入了字典视图对象，允许动态查看字典的内容而无需复制。这在 Python 2 中是不存在的。
    
8. 异常处理语法：Python 3 的异常处理语法更加简洁，使用 as 关键字来捕获异常实例。
    
9. 其他语法改变：Python 3 还进行了一些其他的语法改变，如去除了 long 类型，引入了非本地名称空间的解析等。
    

总的来说，Python 3 在语言的设计上更加一致、清晰，并且更加现代化，但是这也导致了 Python 2 和 Python 3 之间的代码不兼容。因此，需要谨慎选择使用 Python 2 还是 Python 3，并根据实际需求进行迁移。



####  字符串默认为 ASCII 编码 有什么不方便的地方
字符串默认为 ASCII 编码在某些情况下可能会导致以下问题：

1. 不支持非 ASCII 字符：ASCII 编码只支持 7 位字符，因此不支持许多非 ASCII 字符，如中文、日文、俄文等。如果字符串中包含这些字符，则会导致编码错误或乱码。
    
2. 编码转换麻烦：当需要处理包含非 ASCII 字符的字符串时，需要手动进行编码转换，这会增加代码的复杂性和难度。
    
3. 不适合国际化和多语言支持：对于需要支持多语言的应用程序，ASCII 编码的字符串显然无法满足要求，因为它无法表示大多数非拉丁语系的字符。
    
4. 难以处理特殊字符：某些特殊字符（如换行符、制表符、回车符等）在 ASCII 编码中有特殊的表示方式，而在其他编码中可能有不同的表示方式，这可能导致处理这些字符时出现问题。
    

综上所述，字符串默认为 ASCII 编码可能会限制字符串的表示能力，尤其是对于需要处理多语言和特殊字符的应用程序来说，使用 Unicode 编码会更加灵活和方便。因此，Python 3 默认将字符串视为 Unicode 编码，这样可以更好地支持各种语言和字符集。


### 使用u字符串不就支持了吗

在Python 2中，确实可以通过在字符串前添加 `u` 前缀来表示 Unicode 字符串，例如 `u"你好"`。这样可以将字符串明确地标记为 Unicode 编码，从而避免了在处理非 ASCII 字符时可能出现的问题。

然而，Python 3已经在语言级别上将字符串默认视为 Unicode 编码，因此不再需要使用 `u` 前缀来表示 Unicode 字符串。在Python 3中，普通的字符串即是Unicode字符串，例如 `"你好"` 就是一个Unicode字符串。这样可以简化代码，提高可读性，并且更符合当今国际化和多语言支持的需求。
