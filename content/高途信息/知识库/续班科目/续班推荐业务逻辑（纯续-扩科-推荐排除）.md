# 续班推荐业务逻辑（纯续 / 扩科 / 推荐排除）

> 一句话：老师端一个「推荐列表」= **纯续 + 扩科（+ 加购）**；**扩科**再被「**推荐排除**」按"对方授课模式在读"过滤一层。
> 计算收口在 **cart**；student-data 不产出推荐，只提供"哪些学科算在读"和花名册展示字段。
> 字段级口径见 [大班与小班续班科目字段口径.md](大班与小班续班科目字段口径.md)；商品接口清单见 [../续班商品/续班商品链路接口清单.md](../续班商品/续班商品链路接口清单.md)。

## 一、推荐列表里的三类（`recommendType`）

| 类型 | code | 是什么 | 关系来源 | 例 |
|---|---|---|---|---|
| **纯续** | 1 | 学员**当前课程的后置课程**（同一门课升到下一阶段） | course-center **续班关系**（前置课→后置课，`calculateRenewalType=1`） | 五年级语文 → 六年级语文 |
| **扩科** | 2 | **后置课程同学年+学期**的**其它学科**课程 | 续班计划里配的**扩科商品** `(年级, 学科, 商品)`；cart 按"后置课程年级"匹配 | 续语文时顺推六年级数学/英语 |
| **加购** | 3 | 额外加购品（膨胀券 / 组合等） | 推荐节点配置 | 券 / 组合 |

- **谁算**：cart（`com.gaotu.renewal.RenewalService#getRenewalDetail`，**7 参重载**才加载扩科配置 → `ExpandSubjectRecommendService#recommend`）。
- **谁展示**：B 端 `POST /product-b/b/renewMaster/recommendProductList`（`RenewalProductServiceImpl#recommendProductList`，只是把 cart 结果转列表）；C 端 `GET /cart/web/renewal/cart`。返回 `gradeClazzList[].clazzDetailDTOList[]`，关键字段 `productSkuNumber / productType / recommendType / subjectNames / signUp / grade`。
- **productType 值**：2 大班课 / 6004 小班课 / 51 组合 / 8014 膨胀券 / 23 联报。
- ⚠️ **别把花名册的「续班扩科科目」当成推荐**：student-data 的 `renewalExpansionSubject` / `smallRenewalExpansionSubject` 只是**展示列**（`SmallRenewalSubjectService` 算，subtract 口径），**与推荐无关**；推荐只在 cart 算。

### 配置与读侧
- 计划扩科节点 `gaotu.node_config.ext_config`：`{expandSubject, excludeMode, forceBuy, allowDuplicate, beginTime, endTime}`（type=6 节点）。
- 扩科商品 `gaotu.renewal_expand_subject_recommend`：`renewal_number, node_number, grade, subject, product_type, product_number`（**按计划号读，忽略 node_number**）。
- 排除读侧（student-data）：`RenewalInReadSubjectService#listOtherModeInReadSubjects(userId, currentRoomType, schoolYearId, schoolTermId)`。

## 二、「推荐排除」(`excludeMode`) 要解决什么问题

- **问题**：扩科商品是老师手配的 `(年级,学科)`，**不区分大/小班、可随意选** → 出现**跨授课模式重复推荐**：学员在小班已经在读数学，扩科却把数学又推一遍 → 老师/家长看到"读过的又被推"，重复、困惑、易退款。
- **解法**：小班计划的扩科 → 排除该学员**大班在读**学科；大班计划的扩科 → 排除该学员**小班在读**学科。
- **枚举/粒度**：`0=【无排除】 / 1=【排除不同授课模式在读】`，**续班计划级**；历史计划 `excludeMode` 为空 → 默认按 `0`（无排除）回显，**兼容不刷数**；另有全局降级开关 `renewal.expand.exclude.switch`（false 一键回退无排除）。
- **代码**：cart `ExpandSubjectRecommendService`（`recommend` 小班重载 :53 / 大班重载 :104）：先按"后置课程年级"过滤扩科配置行，再 `isExcluded`——命中排除集则 `continue` 不推该门；`queryExcludeSubjects` 仅在 `excludeMode=1` 且开关开时调读侧，异常降级为"不排除"。

## 三、排除的"在读"读什么

- `listOtherModeInReadSubjects(userId, 当前模式, 学年, 学期)`：只保留**与当前（前置）课程"同学年+学期"**的在读记录。
- **只按学年+学期，不卡年级**；另过滤：成人 / 非正价课 / 有赠课标签(`studying.subject.course.tag.exclude.list`) / 纯预售 / 上课形式(`renewal.inread.operation.modes`)。
- 数据源：`dws_fuwu_clazz_user_subject`（大班在读）/ `dws_small_clazz_user_subject`（小班在读）。

## 四、为什么这么设计

- **纯续** = 保**留存/连续性**：学员本来在读，最先保证他接着上。
- **扩科** = 提**客单/多学科**：续班窗口顺带推其它学科。
- **推荐排除** = 保**推荐干净**：不把学员已在（另一模式）读的学科重复推，减少打扰与重复购买。
- 三者**叠加**：列表 = 纯续 + 扩科（+ 加购），扩科再被排除过滤。

## 五、⚠️ 口径不一致：同一份"在读"被两种口径用（排查重点）

| 用途 | 口径 | 结果 |
|---|---|---|
| **展示**（花名册跨模式列：小班页 `largeStudyingSubject` / 大班页 `smallStudyingSubject`） | 同学年+学期+**同年级** | 年级不交 → **列为空** |
| **推荐排除**（cart 读 `listOtherModeInReadSubjects`） | 同学年+学期，**不卡年级** | 年级虽不交，**照样被排除** |

- 实测（2026-10-27，学员 `7651551266`，小班计划 `586116340522184704`）：扩科配了 4 门（`grade11/12` × 语文(5)/英语(4)），学员大班在读"初一语文"(`587172789704818688`, grade21)，计划 `excludeMode=1`：
  - 读侧 `listOtherModeInReadSubjects(7651551266, 小班, 2026, "C") = [5]`（**不卡年级**）→ 语文×2 被排 → **扩科只剩英语×2**（产品期望 4 门）。
  - 花名册 `586084334251927552` 的「大班在读科目」列因"年级不同"却显示为空。
  - 即**「跨模式花名册列为空（卡年级）、扩科却按不卡年级的读侧把它排掉」**，同一份读侧数据两种口径。
- **要不要让排除也卡年级** = 产品要拍板的口径（改 cart 属业务变更）。

## 六、排查提示

- **扩科少推了几门** → 逐条核：① 扩科配置 `renewal_expand_subject_recommend` 是否配全；② 计划 `ext_config.excludeMode`（1 会排）；③ 学员"对方模式在读"读侧 `listOtherModeInReadSubjects` 返回哪些学科；④ 后置课程年级是否覆盖配置行的 `grade`。
- **复现**：cart 7 参 `getRenewalDetail(userId, renewalNumber, getContext, fromBCart, appointUserId, sellerId, includeBCart)`（**5 参重载不加载扩科配置 → 扩科恒空**）；B 端 `RenewalProductServiceImpl#recommendProductList`（ACL 桥，project=product-b）。配置缓存 1800s，改配置后下一轮才生效。
- **扩科恒空**常见坑：后置班无商品 SKU（`saleStatus=40`）/ 计划推荐节点 `renewal_link.product_type≠6004` / 前置→后置续班关系缺失。
