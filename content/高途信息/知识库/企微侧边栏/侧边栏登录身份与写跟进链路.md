## 登录身份链路（显示成谁由它决定）

`GET /crmApp/scrm/wk/auth/ticket`（jsApiTicket）→ `GET /crmApp/scrm/wk/auth/account?code&corpId&appId`
（[WkAuthController#account](/Users/gaotu/IdeaProjects/JavaProject/crm-service/server/src/main/java/com/gaotu/crm/server/app/controller/scrm/WkAuthController.java)）：

1. **cookie 账号优先**：webview 已有登录态且 redis `CRM_WK_ACCOUNT_<accountId>` ≠ `"1"` → 直接用 cookie 账号，
   企微 OAuth code（能解析机器人现归属人）被忽略。
2. 仅当 CAS `batchGetAccountRole` 返回 `status==1`（离职/停用）才写 redis 标记 24h
   （`crm.wk.account.account.expireTime` 默认 1440 分钟），下一次 /account 才走 code。
3. Apollo `wk.account.avatar.map` 可强制改写 accountId（线上 `{}`）；`robot.info.switch` 只补 hookId/logicId。
4. 返回 token + casToken（CAS 角色/权限），角色按 `wkRoleOrder` 过滤，cookie 无角色时默认第一个。

**已知坑（2026-11-16 实锤）**：机器人转号后原归属人的 webview 会话残留给新使用人；原归属人在职（status=0）
时 redis 标记永远不设置 → 持续以旧身份登录、写跟进落旧创建人。处置：侧边栏退出重登清会话；
代码层「code 与 cookie 不一致以 code 为准」未实施。
