# 天工2 数仓任务与代码（大数据平台）

> **非页面条目**。查「某张 Hive 表哪来的 / 天工任务怎么跑 / 任务代码从哪来」时看这里。
> 工具：`~/.claude/skills-cold/tiangong-datawork/`（CLI `scripts/tiangong_cli.py`，经 baijia-proxy 调 `tiangong2.baijia.com`）；机制详解见该 skill 的 `references/task-execution.md`。

## 天工2 是什么

大数据数仓平台 `tiangong2.baijia.com`。三个后端入口，别混：

| 入口 | 前缀 | 用途 |
|---|---|---|
| 开发子应用（任务树） | `/api/dp` | 建/查任务、任务脚本、同步配置、发布 |
| 元数据平台（数据地图） | `/md-admin` | 找表、表详情/DDL、血缘、预览 |
| 调度 / 执行 | `/api/nezha` | 执行周期、日志、执行节点 |

后端 `dp-admin` **不在青舟**（老 ECS + Jenkins 部署）；执行器 nezha-executor 也是 ECS，不在 k8s。

## 任务类型

`1 数据同步 / 2 Hive / 3 Spark / 4 Python / 5 Shell / 6 Kyuubi / 7 Lakehouse(云器/ClickZetta) / 8 HiveV2 / 9 KyuubiV2`。
**没有 Kibana**（最易与 Kyuubi 混）。

## 执行机制（一句话）

**所有任务最后都被编译成一个 shell 命令，由 nezha-executor 在 ECS 节点上跑**：

1. dp-admin 发布时把任务**编译成 stage**（脚本 + 一条 `startCommand`）
2. executor 建工作目录（`executions/<taskExecutionId>/<taskId>/<stageName>`）、写 `stage.prop`/`stage.env`、用 `shell.tpl` 包壳执行
3. 判成功看 stage-log 末尾 `exit_code: 0` + YARN `final status: SUCCEEDED`

各类型编译成什么：Hive=pyhive python（`hivesql.tpl`）；数据同步=DataX 配置/老 Waterdrop(Spark)/现网 Flink JDBC sink；Spark=pyspark；Python/Shell=用户脚本；Kyuubi=kyuubi；Lakehouse=`template/lakehouse.py`（python3.8 提交 clickzetta）。

## 任务代码从哪来：任务树「资源管理」

任务树根节点 **`资源管理`**（`nodeType=3`）。资源类型（`resourceType`）：`1 jar / 2 zip / 3 file`（传文件）/ **`4 git`**（只填 git 地址，平台从 git 拉代码到执行节点）。Shell/Python 阶段编辑器有**「资源」下拉**，一个阶段绑一个资源。

**资源管理接口**（前端 `dp-fe/src/services/{resourceManage,tree,dataDevelop}.js` + `components/general/{resourceManage,newModal,container/menuTree/nodeMenu}`）：

| 用途 | 方法 | 路径 | 入参 | 返回 / 说明 |
|---|---|---|---|---|
| 资源树列表 | POST | `/api/dp/menu/listMenus` | form `projectId, nodeType=3, parentId(-1=根), taskId=0` | 资源树；节点 `id` = 后续 `menuId` |
| 扁平资源列表 | GET | `/api/dp/resource/listResources` | query `projectId` | `[{resourceId, name}]` |
| 资源详情 | GET | `/api/dp/resource/get` | query `menuId` | `resourceName/resourceType/fileInfoName/fileInfoType/gitPath/creator` |
| 用到该资源的任务 | POST | `/api/dp/resource/task/list` | **JSON** `{menuId,pageNo,pageSize}`（form 报「系统异常」） | `[{taskId,taskName,taskType,...}]` |
| 新建 / 上传资源 | POST | `/api/dp/resource/new` | **FormData** `resource(文件), name, projectId, parentId, resourceType, [isHdfs], [gitPath]` | jar/zip/file 传文件；git 只传 gitPath |
| 更新资源 | POST | `/api/dp/resource/update` | **FormData** `resource, projectId, menuId, resourceType, [isHdfs], [gitPath]` | 同上传 |
| 发布（用到该资源的全部任务） | POST | `/api/dp/dataDevelop/batch/publishTask/resource` | form `menuId` | 批量发布 |
| 下载文件资源 | GET | `/api/dp/resource/download` | query `id`(=menuId) | 仅文件类（jar/zip/file） |

- `isHdfs`（仅 jar）：`1 oss / 2 hdfs`
- `menuId` = 资源树节点 `id`，**不是** `taskId`（两者不同，混用会 404 / 查空）
- **没绑资源的任务**：代码在执行节点本地目录（如 `/data/<user>/...`），平台/git 都查不到 —— 只能看 stage-log，或找任务负责人

## 查执行节点（代码在哪台机器）

```bash
curl -sk -x http://127.0.0.1:8888 https://tiangong2.baijia.com/api/nezha/stage/listStageExecutions \
  -H 'content-type: application/json' --data-raw '{"taskExecutionId":<id>,"pageNo":1,"pageSize":10}'
# → data[].executorInfo = "<执行器组>-<IP>"，例：us_online_gpu03-10.224.197.13
```

执行器池（`tx-bj-bdg-nezha-executor*`，ECS）：gpu01-04 + 01-16（IP 见青舟 cmdb 搜 `nezha-executor`）。

## 常用查询

```bash
CLI=~/.claude/skills-cold/tiangong-datawork/scripts/tiangong_cli.py
python3 $CLI table <表名关键词>       # 找表（元数据平台）
python3 $CLI table-detail <tableId>   # DDL / 字段 / 血缘
python3 $CLI search <关键词> 31       # 任务树搜任务（project 31 = 策略组_数据）
python3 $CLI periods 31 <nezhaId>     # 执行周期
python3 $CLI stage-log <stageExecutionId>   # 运行日志（stageExecutionId 取自 execution-detail）
# 读任务脚本（CLI 无子命令，直接 curl）：
curl -sk -x http://127.0.0.1:8888 https://tiangong2.baijia.com/api/dp/dataDevelop/getShell \
  -H 'content-type: application/x-www-form-urlencoded' --data-raw 'taskId=<taskId>'
```
