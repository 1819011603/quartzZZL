# 续班关系配置 · 批量删除续班关系把计划下关系全删了

> **只解决**：续班计划详情页用「+ 批量修改续班关系」→「删除续班关系」上传 Excel 后，
> 计划下续班关系（前置/后置产品）**全部消失**，或删掉了预期之外的前置课程。
> 单条「后置产品-删除」引起的现象不在此列。

## 接口与语义（先认清「删除」是怎么删的）

- 页面入口：详情页「续班关系」tab →「+ 批量修改续班关系」弹窗（前端 `gaotu-fe-promotions` `src/pages/continuationClasses/detail/Relations/BatchSettingRelations/index.js`）。
- 接口：`POST /product-b/b/renewMaster/courseRelation/batchFollowRelation`（青舟 id=2734274），入参 `{operationType(1添加/2删除), excelUrl, renewalMasterNumber}`。
- 后端 `product-server` `RenewalServiceImpl#batchFollowRelation`：
  - 解析 Excel 三列「前置课程id / 后置课程id / 是否计算可续」（`CourseRelationExcelDTO`）。
  - **只用「前置课程id」列**（`getPreCourse()`）经 `courseAclService.listByBizNumbers` 换成本计划前置课程 number；「后置课程id」列不参与计划侧解绑。
  - 删除（operationType=2）时 `unbindPreCourse` → `deletePreCourseRelations(plan, 前置课程列表)`，把这些**前置课程从计划里整体软删**（`renew_master_course_relation.isdel=1`）。
  - 同时调 course-center feign `/feign/course/batchFollowRelationByDto` → `SnowBallServiceImpl#deleteCourseRelationClient`，按 (前置,后置) 对删 `course_relation_map`。
- ⇒ **删除是「按前置课程整体解绑」**：Excel 里出现的前置课程，连同它在计划下的**所有**后置关系一起消失。
- 页面「后置产品」由选中「前置产品」在 `course_relation_map` 的关系派生，前置空了后置自然空。

## 判定：为什么「全没了」

1. 拿计划 number 查计划当时的前置课程总数与本次删除数是否相等：
   `SELECT COUNT(*) FROM gaotu.renew_master_course_relation WHERE renew_master_number=<plan> AND isdel=0`
   vs 操作记录 `course_center.clazz_data_operation_record`（`operation_type=2`，最新一条）的 `number_cnt`。
2. 若「删除数 == 计划当时前置课程数」→ 本次上传的 Excel「前置课程id」集合 = 计划全部前置课程，删除结果正确，属「文件本身含全部」；不是删多了。
3. 逐行核对：Excel「前置课程id」列 vs
   `SELECT pre_course_number FROM gaotu.renew_master_course_relation WHERE renew_master_number=<plan> AND update_time>='<删除时间>'`。
4. 定位删除时间/操作人：`course_center.clazz_data_operation_record`（`operation_name='续班关系'`、`operation_type=2`）的 `create_time` / `upload_user_email_prefix` / `number_cnt`。

## 恢复（线上数据变更，需业务确认后再执行）

1. 计划前置课程关系回滚：
   `UPDATE gaotu.renew_master_course_relation SET isdel=0 WHERE renew_master_number=<plan> AND update_time='<删除时间>' AND isdel=1`（先 SELECT 复核行数=number_cnt）。
2. 被误删的 `course_relation_map` 命中行回滚：
   `UPDATE course_center.course_relation_map SET isdel=0 WHERE isdel=1 AND update_time='<删除时间>' AND relation_type=1`
   （再用移除该计划前置课程号 + 文件「后置课程id」核对范围；两库不同集群不能 JOIN）。
3. 复核：页面刷新，或调 `POST /b/renewMaster/productRelationList` 看前置产品是否回来；必要时等 MQ 同步/缓存过期。
4. 新方案：若只想删某个「后置产品」，走单条「后置产品-删除」（course-center `POST /b/course/deleteRelation`），**不要用批量删除**。

## 验证

- 结论成立：删除数(`number_cnt`) == 删除前该计划 `renew_master_course_relation isdel=0` 行数，且这些行的 `pre_course_number` 与 Excel「前置课程id」列一一对应。
- 恢复成立：`isdel` 改回后，`productRelationList`/页面重新出现对应前置产品及其后置课程。
