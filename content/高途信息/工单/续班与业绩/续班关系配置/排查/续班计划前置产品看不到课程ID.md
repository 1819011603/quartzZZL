# 续班关系配置 · 续班计划前置产品看不到课程ID

> **只解决**：OES 续班计划详情页「前置产品/后置产品」树只显示课程名称（且名称被截断），页面本身没有可复制的课程/产品 ID 入口，需要拿到具体 ID 去核对或联动其它系统。
> 下游判单/风控说命中续班关系但配置查不到，走 [`判单命中续班关系但配置查不到.md`](判单命中续班关系但配置查不到.md)，与本文无关。

## 判定入口

- 前提：已知续班计划 ID（详情页 URL 的 `n=` 参数，或页面「计划ID」字段）。
- OES 前端页面本身不渲染课程 ID，属于前端展示缺失，不是权限或数据问题；有页面查看权限即可用接口直接取到 ID，不需要额外申请。

## 排查

直接调用该详情页背后的接口，用真实登录态（浏览器登出的 Cookie 需替换）：

```bash
curl -s --url 'https://mi.gaotu100.com/product-b/b/renewMaster/productRelationList' \
  -H 'accept: application/json' \
  -H 'content-type: application/json;charset=UTF-8' \
  -b '<浏览器当前登录 Cookie>' \
  --data-raw '{"number":"<续班计划ID>"}'
```

返回体 `data` 是一棵 `学年 -> 学期 -> 年级 -> 科目 -> 课程列表` 的树，叶子节点即课程，字段：

- `number`：产品的数字 ID（页面不显示的就是这个）
- `bizNumber`：业务编号（如 `14YWSY26QU6IP1`），人可读、与页面名称一一对应
- `courseName`：课程名称，与页面前置/后置产品树的展示文案一致

按年级/科目定位到目标分支后，逐条对照 `courseName` 取 `number`/`bizNumber` 即可，不需要额外查库或代课。

## 验证

- 取到的 `bizNumber` 能在页面对应分支的课程名称里找到完全匹配的一条，说明取值无误。
- 页面「前置产品」「后置产品」两棵树结构一致，都能用同一个接口查到；后置产品同理按 `courseName` 匹配即可。
