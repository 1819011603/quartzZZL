# 续班与业绩

续班关系、可续判定、业绩归属与排行榜、续班大促保障相关的线上问题与配置。

## 模块

- [业绩归因](业绩归因/README.md) - 4 条，已解决/待处理/非缺陷，含排查方法：覆盖判不出归属人、排行榜显示 0、可续分母、判单开关与回溯、业绩类型判单顺序（`续班→扩科→召回→新签`，含「为什么是召回不是扩科」的逐步判定与 SQL），以及多笔支付订单归属按首笔支付时间判定（非尾款）的口径；案例结论是判可续只要课程维度有续班关系配置即可，不要求后置课程已建班。另有 2026-10-15 案例：小班续班服务页学员全判「不可续未续」= 业绩归属判的 `不可续-无续班关系(4)`，根因是该课续班关系 `calculate_renewal_type=2(不计算)` 被过滤，属课程配置待改（非展示/筛选 bug）；页面「续班轮次=不可续」与「续班状态」是两回事。2026-10-16 案例：某单业绩类型为「召回」而非「扩科」属判单顺序正常结果——扩科卡在「同辅导筛选」（保护期内前置订单二讲老师均非本单 seller），召回命中取 sellerId。另有 2026-10-16 案例（待处理）：大班某辅导班学员全判不可续 = 该辅导班在 `performance_regular_can_renewal_sign_x` 无可续标记、学员的标记锁在**旧辅导班**（转班后未重算），大班花名册 ES `largeCanRenewal` 按当前辅导班取不到即落 0，属数据待重算（非班级配置/展示 bug）。
- [续班关系配置](续班关系配置/README.md) - 3 条，已解决/非缺陷：怎么用 course-center 接口/表独立核验两门课之间是否有续班关系；`course_relation_map` 查不到不代表未命中，判单服务"前置续班课程"策略在当前订单是系列课时还有一条不依赖该表、也不看主讲也不校验年级的"同学部+同科目"兜底分支（会导致跨年级续班归属）；另有一条是 OES 续班计划详情页前置/后置产品树不显示课程ID时，直接调 `productRelationList` 接口取 `number`/`bizNumber` 即可，非权限问题。
- [续班关系导出](续班关系导出/README.md) - 1 条，已解决：按续班计划ID批量导出「前置课程↔后置课程」对照表（课程ID/名称/年级学科学年/部门）。口径：计划前置课程(`renew_master_course_relation`) × 其 `course_relation_map`(`relation_type=1`) 后置课程；两个库不同集群不能跨库 JOIN；**续班计划ID 常被 JS 精度截断（末两位变 00）**，脚本按前 15 位前缀自动修正。含可复用脚本 `Scripts/导出续班关系.py`。
