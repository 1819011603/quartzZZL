数据源多为 `prometheus`（promql）；`prometheus(default)` = 面板未显式写数据源、走 Grafana 默认。

### ⚠️ 延时口径更正（2026-10-29）

三个「延时」指标都来自 `student_data_es_upsert_time_seconds`（heading名 `Mon.ES_UPSERT`，tag：`index`/`monitorKey`/`result` = `MonitorUtil.esTimer`）。**但它不是"ES 调用耗时"，是端到端延时**：

- 埋点值 = `esSaveTime - CURRENT_TIME_MILLIS`；`esSaveTime = System.currentTimeMillis()` 在 ES `update()` **之后**（`AdsSubclazzUserSyncService.java:279,412`）；
- `CURRENT_TIME_MILLIS` 来自**消息体**，由上游生产者打入 —— 对 `presaleStatus`：`PresaleSubjectServiceImpl.sendSubclazzStatusUpdate` 写入 `CURRENT_TIME_MILLIS = messageBornTime`（`PresaleSubjectServiceImpl.java:741-759`）。
- 所以 `monitorKey=presaleStatus` 量的是跨：
  `ODS 源消息 bornTime → PresaleSubjectServiceImpl（合流订金班+膨胀券、重算 presaleStatus，发 ADS 消息）→ ADS topic student_data_ads_large_subclazz_user_ordered（生产实例 gaotu-fuwu `BcfK60rM`，组 GID_student_data_ads_subclazz_user_ordered_prod）→ AdsSubclazzUserSyncConsumer → ES update()` 的**整条管线延时**。
- 含后缀的 `monitorKey`（`_messageTime`/`_messageStartDeliverTime`/`_messageBeginHandleTime`/`_adsMessageBornTime`/…）分别是不同的起点，用于拆各跳。

**定位方向**：延时飙高要在**整条管线**上拆（上游消费/生产 + ADS 排队 + 本消费者 + ES），不能只看 ES。2026-10-29 复测：ADS 组 `GID_student_data_ads_subclazz_user_ordered_prod` 24h 堆积 max=1、ES 控制台无异常 → 两跳都排除，瓶颈待继续往上拆（上游 `PresaleSubjectServiceImpl` 或 ODS 消费）。

## 稳定性/SLA 面板（非 promql；`marcusolsson-json` 数据源）

`KNHjDP5Hz` 与预报名版 `wXhDkxZDk` 的 SLA 面板，body 里列 `serviceName + apiList`，跳 belong 的 SLA 详情。核心接口：

- **订单模块**：`order.gaotu100.com` → `/web/order/batch/canCreateOrder`、`/web/order/batch/canCreateOrder/v2`、`/web/order/canCreateOrderNoCreate`、`/feign/order/promotion/queryPromotionHistoryByUser`、`/web/order/batch/prepare`、`/web/order/batch/createOrder`；`course-app.gaotu100.com` → `/course/mic/lecturesTimeConflict`
- **支付模块**：`newpay` → `/cashier/*`（cashierZhifuAuth / createOauthUrl / getOpenid / getOrderCashierInfo / getOrderCashier / queryThirdPay）
- **商品/优惠模块**：`product.gaotu100.com`、`cart.gaotu100.com`、`promotion-app/c.gaotu100.com` 各接口（见原文）

## 异常/业务指标面板

- `V9vnMl2Nk` B龙—异常总盘 / `mYr3f6pHz` 异常码：`sum by (errorCode, errorMsg)(increase({__name__=~"Order_*/Promotion*_error_V1___total", env="prod", handleType="RPC", errorCode!~"600|16"}[1m]))`
