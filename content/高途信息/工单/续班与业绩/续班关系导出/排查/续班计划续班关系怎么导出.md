# 续班关系导出 · 续班计划续班关系怎么导出

> **只解决**：给一批续班计划ID，导出其「前置课程 ↔ 后置课程」对照表（课程ID、课程名称、年级学科学年、部门）。
> 续班关系「配得对不对 / 判单为何命中」走 [`判单命中续班关系但配置查不到.md`](../../续班关系配置/排查/判单命中续班关系但配置查不到.md)，与本文无关。

## 判定入口

- 需求方说的「续班计划ID」= `gaotu.renew_master.number`（OES 续班计划管理页 `.../continuation-classes/detail?n=<number>`）。
- 页面佐证（接口与页面口径）：知识库 `promotions/continuation-classes/_page.md` —— 「续班关系」tab = `productRelationList`（前置树）+ `listCoursesByPreCourseNumber`（按前置查后置）。
- ⚠️ **ID 常被精度截断**：17 位大整数超过 JS 安全整数，飞书/前端复制出来末尾两位常变 `00`（`18124921738300480` → `18124921738300400`）。查不到先怀疑这个，**不要**先怀疑查询写法。

## 数据链路

两个库**不在同一集群，不能跨库 JOIN**（`mysql_query` 定位：`gaotu` → cluster 71 `gaotu-center-prod`；`course_center` → cluster 317 `gaotu-course-prod`）：

```
gaotu.renew_master.number
  → gaotu.renew_master_course_relation.pre_course_number           计划下的前置课程 (isdel=0)
  → course_center.course_relation_map
        relation_type=1(续报课程) AND isdel=0 AND relation_number=前置课程
        → course_number = 后置课程
课程名称/部门: course_center.course (name, department_id=末级部门)
年级/学科/学年: course_center.course_school_relation (relation_type 2=年级 3=学科 5=学年, isdel=0)
名称字典: course_center.course_center_dictionary (courseGrades / courseSubjects / schoolYears)
部门名称: course-center 部门树(medusa) → GET /course-center/b/common/department/tree
```

## 排查（导出步骤）

1. 直接跑脚本（已封装上面全链路 + ID 截断修正 + 分页）：
   ```bash
   ~/.local/mcp-servers/venv/bin/python \
     "$(dirname "$0")/../Scripts/导出续班关系.py" <计划ID...> --out /tmp/xuban_relations.csv
   ```
   脚本会打印每个被修正的计划号，**汇报时必须告诉用户改了哪些号**。
2. 落成飞书电子表格（ID 列必须 `dtypes=object`，否则 17 位大数字被数值化丢精度）：
   ```bash
   cd /tmp && python3 - <<'PY'
   import csv, json
   r = list(csv.reader(open('/tmp/xuban_relations.csv')))
   h, d = r[0], r[1:]
   json.dump({'sheets':[{'name':'续班关系','columns':h,'data':d,'dtypes':{c:'object' for c in h}}]},
             open('/tmp/xuban_payload.json','w'), ensure_ascii=False)
   PY
   lark-cli sheets +workbook-create --as user \
     --title "续班计划续班关系导出_$(date +%Y%m%d)" --sheets @xuban_payload.json
   # 回读校验：lark-cli sheets +csv-get --url <url> --sheet-id <id> --range A1:J3
   ```

## 常见坑

- **ID 精度截断**（见上）：`CAST(number AS CHAR)` 也查不到时就是号本身不存在；用**前 15 位前缀**在 `renew_master` 找唯一候选，并核对计划名是否成套、id 是否连号。
- **DMS 单次查询上限 1000 行**，必须 `LIMIT/OFFSET` 分页；`GROUP_CONCAT` 默认截断 1024 字符，别拿它拼 IN 列表。
- **ID 一律当字符串**：课程ID 17 位，落表用 `dtypes: object`，`+csv-put` 会数值化。
- **`course_relation_map` 方向**：`relation_number`=前置、`course_number`=后置（[`判单命中续班关系但配置查不到.md`](../../续班关系配置/排查/判单命中续班关系但配置查不到.md) 里 step3 的字段说明是反的，以本文为准，已由案例 `2026-09-23` 交叉验证）。
- **只取 `relation_type=1`**（续报课程）；`relation_type=0` 是推荐课程、`calculate_renewal_type=2` 是预报名，是否纳入按需求定。
- **部门 = 组织部门**（`course.department_id` 末级 → 部门树名称），不是「学部」（`course_school_relation` type=1 的 k12Departments）；需求方说「学部」才换。
- 一个计划前置课程可能几十门、每门再挂几十门后置，**导出常达数千行**（9 个计划 4372 行、15 个计划 6402 行均用**单 sheet** 交付，`+workbook-create` 无压力；行数特别大或需求方要按计划分表时才拆多 sheet）。
- 需求方常给**飞书 wiki 表格链接**（如「27续班计划」，`wiki/<token>` 是 sheet 节点）：先用 `lark-cli drive +inspect --url <wikiURL>` 解出 sheet token，再 `sheets +workbook-info` + `+csv-get` 取续班计划ID 列（该表 B 列；给的是整列计划号集合，非手工单号）。

## 验证

- 行数 = Σ(计划的前置课程 × 各自后置课程数)；抽样若干计划的计划名/课程名与 OES 页面一致。
- 飞书表格建完后用 `+csv-get` 回读首尾行，确认 ID 未被截断（17 位完整）。
