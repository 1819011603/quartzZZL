# 续班推荐加购 · 纯续与扩科同一班级重复展示

> **只解决**：续班购物车里**同一个班级（同一 `productSkuNumber`）出现两次**（一条 `recommendType=1` 纯续、一条 `recommendType=2` 扩科）。
> 商品完全不展示 / 只展示部分 → 走 [`续班链接加购商品不展示`](续班链接加购商品不展示.md)。

## 判定入口

- 对象：C 端 `GET /cart/web/renewal/cart`；服务层 = cart 7 参 `com.gaotu.renewal.RenewalService#getRenewalDetail(userId, renewalNumber, getContext, fromBCart, appointUserId, sellerId, includeBCart)`（大班路径 `getLargeClassRenewalDetail`，小班路径 `RecommendMergeService#merge` + `convertToRenewalCartVO`）。
- 看返回 `data.gradeClazzList[].clazzDetailDTOList[]`：同一 `productSkuNumber` 是否出现多条，各自 `recommendType` / `subjectNames`。
- 无登录态用反射桥复现（`baijia-invoke` → `invoke_service`，`project=cart`）。

## 排查

去重分两级（大班 `getLargeClassRenewalDetail` 5a/5b；小班 `RecommendMergeService` Step1/Step2，同一套口径）：

- **商品级（5a）**：key = `productId + "_" + 配置年级`（纯续无配置年级 → `_null`）。**同一商品被配在不同"配置年级"时 5a 不拦**（`553a29f9 [fix] 年级去重` 引入，为支持"同一商品配在多个年级各保留一条"）。
- **(年级,学科)（5b）**：仅当 `allowDuplicate=false`（B 端扩科配置「**重复推荐**」= 否，默认）时生效；比较的是**扩科配置的 (年级,学科)** 与纯续**真实 (年级,学科)**。

**漏判条件**：同一个班级既是纯续后置班、又被配到扩科，但扩科的**配置年级/学科**与该班真实值不一致 → 5a（key 不同）、5b（值不同）都不命中 → **重复展示**。

- `configuredGrade` 仅由扩科设置：`ExpandSubjectRecommendService:151/:200` `result.setConfiguredGrade(recommend.getGrade())`；加购/纯续为 `null`。
- 扩科/加购的商品配置见 `gaotu.renewal_expand_subject_recommend`（按计划号读）。

## 验证

- 调 `getRenewalDetail` 后，同一 `productSkuNumber` 只应剩**最高优先级一条**（纯续 > 扩科 > 加购）。
- 注意：当前口径下 5a/5b 都按"配置值"比较，**配置与真实不一致属配置错误**，需与产品确认"同商品多年级"是否要合并展示，再决定改不改代码。
