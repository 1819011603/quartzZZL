# 续班服务窗口期 · 续班服务显示非续班期

> **只解决**：某辅导班在「班级花名册 → 续班服务」被判成「非续班期」，但实际应在续班计划窗口内。
> 判单配置的「保护期 / 可续讲次」（performance-attribution）与本「续班期」不是一回事，别改错配置。

## 判定入口

「续班期 / 非续班期」是页面班级选择器的筛选 `renewalPeriodStatus`（1=续班期 / 0=非续班期），判定字段是 ES **`subclazz_search`** 的 `renewalPlanStart <= now <= renewalPlanEnd`。这两个字段来自**续班计划**（`RenewalMaster`），由 clazz-distribution-management 同步写入。

- 页面接口（student-center，网关前缀 `component/student-center`）：班级选择器 `POST /filter/clazz/list`（入参 `FilterComponentRequest.renewalPeriodStatus`）；主列表 `POST /roster/renewal/page` 查的是 `ads_large_subclazz_user_index`。
- 「这个页面有哪些接口」用 `gaotu-ticket-triage` 的 `scripts/kb_page_interfaces.py 续班` 取。
- 先分辨是「**只有某个辅导班丢**」还是「整班/整课都丢」。

## 排查

1. 查 ES `subclazz_search`（student-prod，实例 `es-cn-4xl3gu6ls0007l185`，bean `subclazzEsClient`）：按 `clazzBizNumber` / `clazzNumber` 取该班全部辅导班文档，看 `renewalPlanId / renewalPlanStart / renewalPlanEnd`。正常应同绑一个 `renewalPlanId`；**字段为 null 的那条辅导班就是受害者**。
2. 拿该 `subclazzNumber` 查 SLS（服务 `clazz-distribution-management-gaotu100-com`，logType=app，当日窗口）：
   - `start construct es object, subclazzNumber: <x>`（`SubclazzEsServiceImpl.doConstruct`）= 该辅导班被重刷过；
   - `listRenewalMasterByClazzNumbers error`（`EsQueryRenewalPlanService`）= 刷的时候调续班计划失败，被 catch 吞成空 → `doConstruct` 的 `else` 分支把 `renewalPlan*` 置 null。
3. 对比同班其他辅导班的 `updateTime`：**同一批写入、只有它缺字段** = 同步时下游抖动。

## 恢复

用 xjob 触发 `handler=esBacktrackHandler`（prod job id `4514`「辅导班列表回溯es数据」），参数 `{"subclazzNumbers":"<辅导班号>"}`（整班/多班传逗号分隔）重刷，重写 `renewalPlan*`。

## 验证

- ES 该文档 `renewalPlanId/Start/End` 已写入且 `renewalPlanStart <= now <= renewalPlanEnd`；班级选择器里该班落到「续班期」。批量回刷后按计划维度复核：其覆盖的课程/班级无「缺计划」文档。
- 不算通过：xjob `handleCode=200`、触发成功、写入接口返回成功 —— 一律以 ES 字段回读为准。

## 根因与根治

`EsQueryRenewalPlanService.listRenewalMasterByClazzNumbers` 曾把下游异常吞成空 list，`SubclazzEsServiceImpl.doConstruct`（`else` 分支）再据空**有损清空** `renewalPlan*` —— 一次下游抖动就会把在续班期内的辅导班打成非续班期。根治：查续班计划失败时**抛异常**（让 MQ 重试/跳过），不要吞异常返回空。
