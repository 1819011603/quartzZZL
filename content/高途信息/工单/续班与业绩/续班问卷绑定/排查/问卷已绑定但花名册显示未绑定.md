# 续班问卷绑定 · 问卷已绑定但花名册/EES 显示未绑定

> **只解决**：OES 续班流程里问卷显示「已绑定」，但二讲花名册/EES 的「续班问卷状态」列显示「未绑定」（`renewalQuestionnaireStatus=0`），点发问卷提示「暂未绑定续班预报名问卷」。
> 已知问卷 ID 问它绑在哪个计划 / 计划删除后绑定没删全，走 [`问卷绑在哪个续班计划.md`](问卷绑在哪个续班计划.md)。
> 家长已填但花名册显示「未发送/未提交」，走 [`../../续班问卷状态/README.md`](../../续班问卷状态/README.md)。

## 判定入口

- 「问卷已绑定」是**绑定层**（`questionnaire.process_number → process_config.renewal_number → renew_master`）成立；花名册「未绑定」是**匹配层**（`renew_master_course_relation.questionnaire_number`）没算出。两层独立，绑定成功 ≠ 花名册可发。
- 花名册 `renewalQuestionnaireStatus` 值域 `RenewalQuestionnaireStatusEnum`：`0 未绑定 / 1 未发送 / 2 未提交 / 3 已提交`。显示「未绑定」= 0。
- 与**学员是否可续无关**：`renewalQuestionnaireStatus` 只由「续班计划是否发布 + 问卷是否匹配到前置课程」决定，可续状态只影响「续班状态/续班轮次」列。

## 排查

### 1. 先确认匹配层是否为空（直接原因）

花名册状态由 student-data `RenewalQuestionnaireStatusServiceV2#buildData` 算：续班计划未发布或 `matchResult` 为空 → 写 0（未绑定）。`matchResult` 走 product-b，判定条件是 `renew_master_course_relation.questionnaire_number` 非空。

```sql
-- 该计划下每个前置课程的问卷匹配号；=0 或 NULL 就是没匹配上
SELECT number, renew_master_number, pre_course_number, questionnaire_number, isdel, update_time
FROM gaotu.renew_master_course_relation
WHERE renew_master_number = <续班计划number> AND isdel = 0;
```

也可直调确认（`baijia-invoke`，`project=student-data`，需带真实 classNumber）：
`QuestionnaireAclService#queryQuestionnaireMatchResult(clazzNumber, renewalNumber)` → 返回 null = 未绑定，返回 `{number,bizId,bindTime}` = 已匹配。

### 2. 匹配层为空的原因：问卷配置的【部门/年级/学科】与前置课程不一致

`calculateRenewCourseRelation`（product-server `QuestionnaireService`，由 product-task `QuestionnaireChangeConsumer` 在 `process_questionnaire_bind` 时触发）按规则把问卷挂到计划的前置课程：

- 规则 = 问卷的 `questionnaire_ext`（`DEPARTMENT` / `COURSE_GRADE` / `COURSE_SUBJECT`）转成条件，与**前置课程**的 `departmentIdPaths` / `grades` / `subjects` 做 `allMatch` 匹配（`DefaultRuleMatcher`）。
- 命中 → 写 `questionnaire_number = 命中的问卷号`；**不命中 → 写 0**（`QuestionnaireService#calculateRenewCourseRelation`），随后 product-b `matchResult` 返回 null → 花名册「未绑定」。
- 部门是 `contains`（问卷配任一段即可命中）；**年级、学科是精确包含**（课程年级集合必须包含问卷年级）。

两个口径先对齐再下结论：

```sql
-- 问卷配的 部门/年级/学科（看 is_del=0 的）
SELECT relation_type, relation_value FROM gaotu.questionnaire_ext
WHERE questionnaire_number = <questionnaire.number> AND is_del = 0;
```

```sql
-- 计划前置课程的 年级/学科/部门（course_center）
SELECT number, name, gradeIds, subjectId, adultDepartment FROM ...  -- 用 baijia-invoke 调 CourseAclService#getFullCourseInfoByNumbers 更稳
```

- 典型不一致：**前置课程是初三(23)，问卷配的是初一(21)/初二(22)** → 年级不匹配 → 未绑定。部门 `courseGrades` 字典：21 初一 / 22 初二 / 23 初三 / 31 高一…
- 问卷绑定页选【年级】时，口径必须与**前置课程年级**一致（不是续班计划名/目标年级）。

### 3. 修复

在 OES 续班流程里**解绑后按正确【部门/年级/学科】重新绑定**（或直接改对年级再绑），触发 `process_questionnaire_bind` → 重算 → `renew_master_course_relation.questionnaire_number` 写入 → student-data 收到 `preCourse_questionnaire_change` 重算花名册。

## 验证

- `renew_master_course_relation.questionnaire_number` 非 0，且等于 `questionnaire.number`。
- `QuestionnaireAclService#queryQuestionnaireMatchResult(clazzNumber, renewalNumber)` 返回非 null。
- ES `ads_large_subclazz_user_index`（别名，物理 `_v2`，集群 `es-cn-smw4b9m200004w3hn`）按 `clazzNumber` 聚合 `renewalQuestionnaireStatus`：从全为 `0` 变为 `1`（未发送）/`2`/`3`，才算花名册已生效。
