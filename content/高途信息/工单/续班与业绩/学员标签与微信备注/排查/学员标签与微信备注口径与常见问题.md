# 学员标签与微信备注 · 显示与保存、标签筛选搜索

> **只解决**：**花名册**（大班 `clazzRosterOL` 等默认花名册）与 **续班服务**（大班 `continuationService` / 小班 `microContinuationService`）两个页面共有的「学员标签」「微信备注」——列空、编辑保存后列表不展示、加「备用标签」提示「无好友关系」、「微信备注」列不显示、以及「学员标签」筛选框搜不到选项。
> 这是字段口径与配置的通用排查；具体某次事故见 `../案例/`。

## 判定入口（先分清哪一层）

1. **读侧（列不显示/显示值不对）**：student-center 列表接口 + GAIA 字段配置（`ees_data`）。
2. **写侧（保存报错/保存后不展示）**：FE `SettingTags` → student-center `/batchOperate/tag/save` → 落库 / 写 ES / 推企微。
3. **筛选搜索**：选项字典接口 + 前端 GAIA 组件。

快速定位：直调列表接口看返回里有没有该字段、值是什么；再看是字段缺失（读配置）还是值本身为空（数据/维度）。

## 读侧：字段来源与配置

- 大班列表：`POST /roster/renewal/page`，`identification=continuationService`（带 `b_client: EES`）。
- 小班列表：`POST /roster/small/renewal/page`，`identification=microContinuationService`。
- **学员标签**：ES（`ads_large_subclazz_user_index` / `ads_small_clazz_user`）的 `studentTags`（标签 ID 列表）经 GAIA `studentTagNames` 转成名称返回。
- **微信备注**：ES `wechatRemark`（keyword，值是 list，`FieldsConvertDataQueryServiceImpl` 拼成逗号串返回）。**取值维度 = 该班班主任（ES `assistantAccountId`）× 学员**，不是登录查看人、也不是全班汇总。

**读配置两个坑（`ees_data`）**：

- `es_query_config`：identification 必须登记 `studentTags`（必要字段）+ `studentTagNames`（额外字段）+ `studentTags`（筛选），否则 `GaiaEsMappingService#getNeedFromEsFields` 不取 `studentTags`、`FieldsConvert` 无处生成 `studentTagNames` → **列恒空**。大班 `continuationService` 曾缺（小班均有），test 已补齐、**prod 待补同款**。
- `student_field_config`：**`wechatRemark` 不能登记**。它是 ES 原生字段（注册名 == ES 原始字段名），一旦登记会被当「需 ODS 补的字段」从 ES `fetchSource` 剔除且无人补值 → **列恒空**；`studentTagNames` 可以（注册名 ≠ 原始字段名 `studentTags`）。清理：
  `DELETE FROM ees_data.student_field_config WHERE identification IN ('continuationService','microContinuationService') AND field_name='wechatRemark'`

> 修完配置有 Caffeine 本地缓存（≤5min）才生效。

## 写侧：`/batchOperate/tag/save` 的分流

FE `SettingTags/TagsModal` 提交 `POST /component/student-center/batchOperate/tag/save`（body：`clazzStudents`、`studentTags`（ID 数组）、`type`、`userIds`、`scene`）。后端 `UserClazzMarkBiz#saveTagDetail` 按标签类型分流：

- **业务标签**（关注程度/报名意向/…/学员放假时间，value 1–43）：`batchSaveTags` 落库 `user_clazz_mark_info` + 双写原表 + 写 ES（`markInfoSync2Es`）→ **列可见**。
- **临时/备用标签**（「临时标签（重要：勿动）」组 value=20，含**备用1–备用20** value 101–120）：走 `TemporaryStudentTagServiceImpl#saveTags` → **不落库、不写 ES**，只「借业务标签壳子、直接推企微官方」→ **列不可见**（设计如此，不是丢数据）。

**「无好友关系」**：`saveTags` 先取老师企微 ID（空→「未获取到老师的企微ID」），再查 (accountId × userIds) 的好友关系（过滤 `isFriend`），为空即抛「无与老师有好友关系的学员」→ 页面显示「无好友关系」。
- `accountId` = **登录操作的这个老师本人**（`loginUser.getAccountId()`），与班主任是谁无关。
- 好友关系经 linkup `getWechatRelationInfoByUsers`；核对：acl 桥 `FriendRelationServiceImpl#getFriendRelations([userId], accountId, false)` 看 `wechatRelationContacts[].friend`。
- 常见原因：① 登录老师不是该学员的企微好友（好友是班主任/别的老师）；② linkup 当时没有这条关系（未建立/未同步，稍后即恢复）；③ 代课/切角色导致 accountId 不是本人。

## 筛选搜索：选项字典与前端组件

- 选项来源：`POST /fairy/student-center/subclazz/learnSituation/getAllStudentTags` → `studentTag` 字段的 `filterDropdown.filters`（**两级嵌套**：15 个业务组 + 「临时标签(备用1–20)」组，每组含子项）。所有页面（大班/小班续班、1v1、默认花名册）**共用同一份**。
- **搜索框由 GAIA「标签+分组多选筛选」组件实现，只按 `value`（标签 ID）过滤、不按 `label`/名称过滤** → 按名称（如「备用1」「需强关注」）搜不到。**属该 GAIA 组件的问题**（组件负责人），不是花名册/续班服务本身；换任一 tab 表现一致。
- 若怀疑是字典缺项：对照 `getAllStudentTags` 返回里有没有该标签名（在 = 组件搜索问题；不在 = 字典/配置缺项）。

## 验证

- 读侧：直调列表接口，返回里出现 `studentTags`/`studentTagNames`/`wechatRemark` 且值符合预期（不再整字段缺失）。
- 写侧：业务标签保存后 ES `studentTags` 落值且列表可见；备用标签保存成功仅代表推企微成功，**不代表**列表可见。
- 「无好友关系」：acl 桥回读 (登录老师 accountId × 学员) `friend=true` 时为通。
- 配置改动后等 Caffeine 缓存过期（≤5min）再看页面。
