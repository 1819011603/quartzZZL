# 业绩归因 · 判单开关溯源与回溯补数据

> **只解决**：已确认真因是 `is_attribution=0`，要查谁改的 / 要回溯补数据。
> 判不出归属人的通用排查走 [`查不到归属人.md`](查不到归属人.md)，与本文无关。

## 判定入口

先确认真因确实是判单开关（`performance_attribution_setting.is_attribution=0`），再往下走。

## 排查

### 1. 追「判单开关是谁改的」

1. 变更时间 + 前后值：查 `performance_attribution_setting_log`（按 clazz_number）
2. **操作人**：该表不存，去 SLS 捞同一秒的
   ```
   queryStr: "<clazzNumber>" and ("setting/modify" or "uid")
   ```
   命中 `LogCommonFilter start request log path[/performance/management/setting/modify]`，请求头里 `uid` / `cas_name` / `cas_department` / `gaotu-cas-authorization`（含 `cosplay` 标识是否代课）就是操作人。页面为 `mi.gaotu100.com/ark/app-yunfan/newJudgeConfig`
3. **初始值不是人写的**：建班 MQ → `insertAttributionSettingByClazzNumber` → `judgeOriginalClass` 自动算。规则：**只有 `course_type` 30专题课/40系列课 才 =1**；K12 再排除垫班/艺术班/克瑞斯/内部培训/爱马仕/赠课/模拟课堂标签。日志为 `非专题课、系列课不判单，clazzNumber: X` + `插入判单配置：{...}`

### 2. 回溯补数据（线上写操作，动手前必须让用户确认）

> **本节尚未完成实际执行验证。** 使用前先验证方式 A 的 session 鉴权、Excel 表头校验、trigger 耗时与失败表现；验证后直接更新本节的当前操作口径。

底层统一入口：`BackOrderAttributionService.backOrderAttributionByOrderNumberList(request, BACKTRACK)`。会重建凭证、识别 `isTransfer`、串联调出退款+支付判单+退款判单，并递归回溯调课子单。

#### 方式 A：BOSS 三步流程（正式运营路径，推荐）

基路径 `/performance/management/`（SnowBallController）：

1. `POST /snowball/back/upload` — multipart 上传 Excel，返回 url
2. `POST /snowball/back/create` — body `{backName, filePath, backType, backCondition}`
   - `backType`：**1=判单回溯** / 2=可续回溯
   - `backCondition`：1=按订单回溯 / 2=按班级回溯
   - ⚠️ 从 **session** 取 accountId（`TEACHER_DETAIL_SESSION_KEY`），不是 `uid` 头 —— 必须带浏览器登录态，裸调会 NPE
3. `POST /snowball/back/trigger` — body `{id}`，异步跑（`@Async("commonTaskExecutor")`）

**Excel 模板只有一列**，表头必须是 `订单号或班级bizNumber`（`AttributionBackExcelDto` index=0）。状态在 `/snowball/back/list` 看：0待处理/1处理中/2处理完成/3处理失败。失败会发邮件。

#### 回溯前的前置检查

- 判单开关现在必须已是 `is_attribution=1`，否则回溯照样被 `filterAttributionCredentials` 滤掉，白跑
- 调课单要继承，父单必须还有 `trade_status=1` 的行（`selectPaidAttributionByOrderNumbers` 只认 1）
- 只回溯这些订单状态：大班课 2/6/7/9；solo/small/新课时包 CONFIRMED/COMPLETED

### 3. 已知系统性坑（遇到先怀疑这个）

**编程 / 魔法编程学院（KA业务线-AI素养学部）这条线的课程全是 `course_type=20 体验课`**，自动规则一律判成"不判单"，每个班都得运营手工去云帆后台开。开得快没事，开得慢就漏——而且 **`is_attribution` 由 0 改 1 不会回补历史订单**，窗口期内的单永久无归属。

排查到"某班配置 07-xx 才改开"时，别停在单笔单：**查该班从建班到改开这整段窗口的所有订单**（从订单侧取 order_number 再反查业绩表）。
