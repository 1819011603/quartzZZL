# 业绩归因 · 可续状态判「不可续」

> **只解决**：学员被判成不可续（页面「续班状态」/ES `smallCanRenewal` 为不可续，如「不可续-无续班关系」），要查是哪一步判的、为什么。
> 判不出归属人 / 排行榜显示 0 走 [`查不到归属人.md`](查不到归属人.md)、[`判单正常但排行榜显示0.md`](判单正常但排行榜显示0.md)。

## 判定入口

- 可续状态 `smallCanRenewal` 的上游是 **performance-attribution（业绩归属）**，不是 student-center/student-data 自算；值域 `CanRenewalStatusEnum`：`1可续-未续 / 2可续-已续 / 8可续-后置课程退款` = 可续，其余（3/4/5/6/…/16/17）= 不可续。
- 最直接的入口：**按订单查可续原因接口**。

## 排查

1. **按订单查原因（最快）**：
   `POST https://sd.baijia.com/feitu/performance/management/suda/performance/regular/canRenewalSignReason`（sd 网关，带 `traffic-env`）
   body `{"orderNumberStr":"<订单号>","pager":{"current":1,"pageSize":10,"pageNum":1}}`
   → 返回 `signResult`（如 `不可续-无续班关系`）+ `reasons[]{step,reason,detail}`（如 `未配置后置续班课程`）。
2. 拿 `(subclazzNumber, userId)` 查上游判定：`invoke_service` 调 student-data `PerformanceSyncAclService#getCanRenewalDto` → `canRenewalStatus` / `roundIdx`。
3. reason=`未配置后置续班课程` 时，查该课续班关系与 `calculate_renewal_type`：
   - `CourseNotNormalQueryApiFeignClient#listBeContinuationCourseByNumberList([courseNumber])` → 后置课程；
   - `#listBeContinuationCourseInfoByNumberList([courseNumber])` → `calculateRenewalType`；
   - 表 `course_center.course_relation_map`（prod `cluster_id=317`），字段 `course_number`/`relation_number`/`calculate_renewal_type`。
   - **规则**：performance-attribution `RenewalSignTemplate#filterNotCanRenewalCourse` 会把 `calculateRenewalType=2（不计算）` 的关系**过滤掉** → 后置课程映射为空 → `AbstractRenewalSignStrategy#renewalSignCore` 判 `NOT_CAN_RENEWAL_NO_AFTER_COURSE(4)`。`CalculateRenewalTypeEnums`：`0=无 / 1=计算 / 2=不计算`。
4. 其它 reason 按 `AbstractRenewalSignStrategy#renewalSignCore` 的分支对照（过可续时间、已退款、老学员、灰名单…）。
5. **某辅导班学员全判不可续、同班其它辅导班正常** → 该辅导班在 `performance_regular_can_renewal_sign_x` 0 条，学员的标记锁在**其它辅导班**（常见于转班后未重算）。按辅导班/学员维度查（cluster 259 / `gaotu_stat`，`subclazz_number` 有索引；`user_id` 侧数据量大要收窄）：
   ```sql
   -- 本班各辅导班的标记分布：某辅导班若整列为 0 就是它
   SELECT subclazz_number, can_renewal_status, COUNT(*) FROM performance_regular_can_renewal_sign_x
   WHERE subclazz_number IN (<本班全部辅导班号>) GROUP BY subclazz_number, can_renewal_status;
   -- 该辅导班学员的标记实际落在哪个辅导班
   SELECT subclazz_number, can_renewal_status, COUNT(*) FROM performance_regular_can_renewal_sign_x
   WHERE user_id IN (<该辅导班学员 userId>) AND subclazz_number IN (<本班全部辅导班号>)
   GROUP BY subclazz_number, can_renewal_status;
   ```
   - 判据：该辅导班无记录、而学员在**别的辅导班**有记录 → 可续锁在旧辅导班。
   - 大班花名册 ES（`ads_large_clazz_user_<year>`）的 `largeCanRenewal` 由 `CanRenewalStatusQueryServiceV2` 按学员**当前 subclazz** 取 performance-attribution，取不到 dto 时**置 0** → 页面展示「不可续」。
   - **小班同理**：小班花名册 ES `ads_small_clazz_user`（`smallCanRenewal`/`smallRoundIdx`）按学员当前 subclazz 取不到标记时也置 **0**（`OdsSmallCanRenewalSyncService` `useExternal` 取不到外部维度即写 0）。**不一定整班**——转班/调课后可能只是个别「在班(调课)」学员的标记锁在旧辅导班（案例 [`../案例/2026-10-16-可续标记锁在旧辅导班导致不可续.md`](../案例/2026-10-16-可续标记锁在旧辅导班导致不可续.md)）。
   - 取该辅导班学员列表：`dws_fuwu_course_clazz_user`（cluster 336 / `student_dw_data`，**64 个物理分片**，按 `clazz_number`/`subclazz_number` 查询要并扫全部分片）。
   - 交叉：「可续锁在别的订单」见 [`不算可续分母或可续锁在别的订单.md`](不算可续分母或可续锁在别的订单.md)。
6. **当天调课/调班/课程转移后显示不可续 → 大概率是 T+1 时滞，非缺陷**（次日自动修正）。判据：`performance_regular_can_renewal_sign_x` 里该学员**当前 subclazz 已有** `can_renewal_status ∈ {1,2,8}`（可续），但 ES `ads_small_clazz_user.smallCanRenewal=0`、ES `updateTime` 停在调课之前 → 只是 ES 未同步。
   - 机制：调课/调班的可续标记修正 `RenewalSignRegularStrategy#correctTransferCanRenewalStatus` **非实时**、且**只修正当天**的调课调班订单，由每日定时任务跑（performance-attribution，jobGroup 293）：`3295`【可续】长期班数据同步(04:00) → 链式触发 `3297`【可续】长期班可续标记 → `4319`【可续-修正】长期班 `RenewalOrderCorrectHandler`；短期班 `3299`→`4320`，入口班 `3296`→`3298`/`4321`。⚠️ `3297`/`4319` 自身 `triggerStatus=0`，靠父任务链式触发，别误判「没在跑」。
   - 修正后发 MQ `canRenewalChangeEvent` → student-data 写 ES。故次日 04:00 后页面自动恢复可续。案例 [`../案例/2026-10-17-调课后当天续班状态显示不可续.md`](../案例/2026-10-17-调课后当天续班状态显示不可续.md)。
   - 要当天生效（需授权）：手动触发 xjob `RenewalOrderCorrectHandler`（`param={"clazzType":1}`）或 `RenewalOrderSignHandler`。

## 验证

- `canRenewalSignReason` 的 `signResult`/`reason` 与 ES `ads_small_clazz_user.smallCanRenewal` 及页面对得上。
- **改配置后不会自动进 ES**：需重算可续标记 —— xjob `RenewalOrderSignHandler`（`RenewalSignTemplate#doSign`，param `{"clazzNumbersStr":"<班号>","clazzType":<班型码>}`）→ 发 MQ `canRenewalChangeEvent`（topic `gaotu_performance_renewal`）→ student-data `OdsSmallCanRenewalSyncConsumer` 消费写 ES。只改配置不重算，ES 仍是旧值。
