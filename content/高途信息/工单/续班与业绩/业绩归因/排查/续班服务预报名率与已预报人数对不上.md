# 业绩归因 · 续班服务「预报名率」与运营数的「已预报人数」对不上

> **只解决**：续班服务页顶部「预报名率 / 未预报名率」与运营在列表里数出的「已预报人数」差 1 人或几人（常见说法「可续 263、已预报 195，应该 74.14%，页面却是 73.76%」）。
> 可续学员数比在读列表多走 [`续班服务可续学员数比在读列表多.md`](续班服务可续学员数比在读列表多.md)；某学员为什么被判不可续走 [`可续状态判不可续.md`](可续状态判不可续.md)。

## 判定入口

先认清两个数**不是同一人群**，直接相除必然对不上：

| 数 | 来源 | 口径 |
|---|---|---|
| 率分子 / 分母 | student-center 续班指标接口 `/roster/(small/)renewal/(subclazz/)statistic` | ES 文档口径：`canRenewal ∈ {1,2,8}`（小班 `smallCanRenewal`）算可续；分子再加 `presaleStatus=1`（小班 `smallPresaleStatus`）。**不按 `clazzStudentStatus` 过滤** → 分母含「已退班但仍留可续标记」的文档 |
| 页面「可续学员数」 | 同上 `canRenewalCount` | 与率分母是同一批文档，所以「可续数 / 率」自洽 |
| 运营「已预报 195」 | 列表 `/roster/(small/)renewal/page` + 「预报名情况=已预报」 | 只 `presaleStatus=1`、默认「在读且本人辅导班」，**不按可续过滤**，也不含退班文档 |

代码：大班 `RenewalService#subclazzStatistic → batchQueryStudentInfo`（canRenewal 过滤）→ `getSubclazzRenewalStatisticVO`（`presaleCount` 计 `presaleStatus==1`，`depositPreRegistrationRate = calculatePerCapita(presaleCount, canRenewalCount)`）；小班同构，字段是 `smallCanRenewal` / `smallPresaleStatus`。ES：大班 `ads_large_subclazz_user_index`（ees 集群 `es-cn-smw4b9m200004w3hn`），小班 `ads_small_clazz_user`（studentServe 集群 `es-cn-4xl3gu6ls0007l185`）。

结论方向：**率本身按自己的口径没算错**；差的 1 人 = 列表里有、但 `canRenewal` 不在 {1,2,8} 的在班已预报学员（通常是调课/退款链导致可续标记异常）。

## 排查

1. **复现率分子/分母**（PROD 走 SRE `runDslAction`，见 skill `es-apply`）。大班 DSL 模板（`CAN` 为 `{"terms":{"canRenewal":["1","2","8"]}}`，`ROUND` 为 `{"terms":{"roundIdx":["1","3"]}}`（一轮），小班换成 `smallCanRenewal`/`smallRoundIdx`）：

   ```jsonc
   // 分母 canRenewalCount
   {"size":0,"query":{"bool":{"filter":[
     {"bool":{"should":[{"term":{"assistantAccountId":"<登录人>"}},{"term":{"salesAccountId":"<登录人>"}}],"minimum_should_match":1}},
     {"terms":{"clazzNumber":[...]}},{"terms":{"subclazzNumber":[...]}},
     {"terms":{"canRenewal":["1","2","8"]}},{"terms":{"roundIdx":["1","3"]}}]}}}
   // 分子 presaleCount：再加 {"term":{"presaleStatus":"1"}}
   ```
   `size:0` 的 `hits.total.value` 即人数（文档数）。注意 `subclazzNumber` 要传**登录人自己的辅导班**（`rosterCommonService.batchQuerySubclazzNumbers` 按登录老师映射）。
2. **复现运营数的「已预报」**：同一批 clazz/subclazz + `presaleStatus=1` + `subclazzStudentStatus=1`（在读且本人辅导班）+ 轮次。这个数通常正好等于列表 total。
3. **取差集**：拉两份文档（`_source` 带 `_id`/`userId`/`studentName`/`clazzNumber`/`canRenewal`/`clazzStudentStatus`/`subclazzStudentStatus`），本地按 `_id` 比对。`已预报列表 \ 率分子` 的**用户**就是被率漏掉的人；`率分子 \ 已预报列表` 多为「退班但仍留可续」文档。
4. **对每个人拉跨班全部文档**（同一 clazzNumber 集合）：调课过的人会同时有「旧班退班（clazzStudentStatus=0/subclazzStudentStatus=2）」和「新班在读（1/1）」两条；旧班可续、新班不可续时，率按文档把旧的算进去、列表按在读只显示新的 → 看起来「人数对不上」但按文档是平的。
5. **查漏掉那人的可续来源**（`gaotu_stat`，cluster 259）：
   - `performance_regular_can_renewal_sign_x`：按 `user_id` + `subclazz_number` 查。若**当前调课新单 0 行**、只有旧退款单的 `can_renewal_status=5` → ES 只能取到 5。
   - `performance_regular_can_renewal_config`：按新单 `order_number` 查。若 **0 行**，即「订单晚于班级可续时间才转入，T+1 同步只取 `can_renewal_time >= 昨天0点` 的班级 → 晚转入单补不到配置」→ 可续标记不生成。处置见 [`可续状态判不可续.md`](可续状态判不可续.md)「按订单可续回溯失败」：带班号触发 xjob `3295 RenewalOrderSyncHandler` 重建订单级 config → `3297 RenewalOrderSignHandler` / `4319 RenewalOrderCorrectHandler` 重算 → MQ `canRenewalChangeEvent` → student-data 写 ES。
   - `can_renewal_status=7`（不可续-调课可续修正）：是调课链路去重结果——同一调课链只保留一个可续单，其余可续单被改成 7，属预期，不是缺标记。
6. **修正前后都要重新取数**：修正某人后分子/分母**同时 +1**（该人由不可续变可续），预期值应重算，不要拿旧的「已预报/旧可续」直接套。

## 验证

- 率 = 分子 / 分母 = 页面展示值（保留 2 位、HALF_UP），且分母 = 页面「可续学员数」。
- 差集里的 `userId` 能被 `performance_regular_can_renewal_sign_x`/config 缺失或 `can_renewal_status ∉ {1,2,8}` 解释。
- 「可续」修正后回读 ES `canRenewal` 与页面/指标一致，才算生效；只改 config、不发 MQ 不算。
