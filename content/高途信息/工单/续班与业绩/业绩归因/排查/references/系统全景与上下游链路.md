## 系统一句话

业绩归属中台，回答「一笔订单的业绩算谁的」。判单最早嵌在 finance-server（财务）里，看板来自 performance-management，git 迁移记录 `d72d4a0f4` / `ff1460107` 后收敛为本服务。判单结果直接决定绩效工资，所以独立成「裁判」。

## 判单核心语义（对口径用）

**三层策略模型**，全由 `performance_attribution_rules_config` 一张表驱动（bizLine/productType/operationMode/priority + 三段 JSON）：

| 层 | 回答 | 配置字段 | 策略枚举 |
|---|---|---|---|
| ① 归因类型 | 这是哪种功劳？ | typeConfig | 续班/扩科/召回/拉新/无归属 + 线下 1v1、1vN、课时包（`PerformanceAttributionStrategyEnums`） |
| ② 唯一前置订单 | 基于哪笔历史订单？ | preOrderNumberConfig | 筛选链（`UniquePreOrderStrategyEnums`） |
| ③ 归属人 | 归到哪个人？ | employeeConfig | 12 种（`EmployeeIdStrategyEnums`） |

**三个闸门**：保护期（前置订单支付后的窗口，窗口内新单才可能判续班）→ 续班关系（前置班与当前班有可续计划关系）→ 唯一前置订单收敛（班型 → 优先同辅导 → 最早开课 → 最早支付 → 兜底最大班 ID 保证幂等）。筛选链每步都写判单原因，争议可回放。策略命中即断，一笔订单只有一个归属结论。

**金额口径**：`performance_price = price × price_ratio`；order_ratio 单数口径 / price_ratio 金额口径 / user_ratio 人数口径；多前置班命中按行拆分、合计 ≤ 1。**退款冲抵不重算金额，只按原业绩行比例反向生成扣减行**——支付怎么分、退款怎么扣。

**退款 = 追加冲抵不删历史**（按退款类型置 trade_status，原行保留，重复投递不产生第二组冲抵行）。**调班 = 继承类型与归属人、金额按新单重算**（transferFlag + 父订单号；父业绩可能在 K12 表也可能在 physical 表，必须跨表定位；白名单组合才继承）。

**可靠性三道防线**：① 待支付凭证校验——已支付单判单前必须查到建单时落的待支付凭证（sellerId 快照，认下单时归属），查不到 return false 交 MQ 重试（`judgePerformanceAttribution`，回溯/申诉/调课/赠课场景豁免）；② 延迟监控消息 `gaotu_attribution_monitor_event` → `DelayOrderEventConsumer` 到期查漏补判；③ XXL-Job 回溯族，走 BACKTRACK 场景复用同一判单引擎。

## 下游被调（判单取数，任何一个抖动都影响判单时效）

订单（ORDER-B 回写销售归属 tag、CAL-AWESOME-WIDGETS 辅导订单）；商品/课程（PRODUCT-B SKU/SPU 分流、ces-teach-product-server、gaotu-ols OMO 校区/花名册/续报周期）；CRM 线索（leads-management 线索/公海 → 拉新召回归属人）；用户组织（USER/STAFF/ucenter/student-center）；教师（TEACHER-BASIC/TEACHER-TOOL）。已做 Redis/Caffeine 缓存。

## 产出

- MySQL gaotustat：明细（主表/_adult/_no_pay）+ 汇总（_total）+ 配置/判因/可续/异常记录（表分工见各 runbook）
- ES `performance_dashboard_v2` 看板宽表（`PerformanceDashboardSynchronizer`）；可续标记同步 student-data 侧 ES
- feignPerformance（client SDK `PerformanceAttributionRemoteService`）：按订单查归属/归属人/退款是否扣绩效/判单原因/可续灰名单，供 CRM、退款/售后、财务反查（调用方为推断，未在对方仓库验证）

## 坑速查（细节进对应 runbook）
