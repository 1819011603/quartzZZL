# 业绩归因 · 续班服务「可续学员数」比列表多（在读且本人辅导班）

> **只解决**：大班续班服务页顶部「可续学员数」比列表实际条数 / 勾选数多 1~几个（两个数字对不上、疑似多算），而判单与花名册都是对的。
> 「在班」学员在列表查不到、可续数比花名册**少**走 [`大班续班服务漏在班学员.md`](大班续班服务漏在班学员.md)。
> 「某学员为什么被判不可续」走 [`可续状态判不可续.md`](可续状态判不可续.md)。

## 判定入口

页面 = 大班**班级花名册 / 续班服务** tab（cronus `clazzRosterOL`，identification `continuationService`），读 ES **`ads_large_subclazz_user_index`**（ees 集群 `es-cn-smw4b9m200004w3hn`，文档 `_id = subclazzNumber-userId`）。

**关键：顶部指标和列表不是同一套过滤**（本问题的根因）：

| 数字 | 接口 / 代码 | ES 过滤 |
|---|---|---|
| 顶部「可续学员数」 | `/roster/renewal/subclazz/statistic` → `RenewalService#batchQueryStudentInfo` | `canRenewal ∈ queryCanRenewal(){1,2,8}` ∩ 登录老师的辅导班(`subclazzNumber`) ∩ 轮次。**不含 `clazzStudentStatus` / `subclazzStudentStatus` 过滤** |
| 列表条数 / 勾选数 | `/roster/renewal/page`（默认筛「学生辅导班状态 = 在读且本人辅导班」，`filter.studentSubStatus=[0]`） | 上面再 ∩ `clazzStudentStatus=1` 且 `subclazzStudentStatus=1` |

→ 指标**不筛在班状态**、列表**筛在班** ⇒ 只要有人「可续标记还在、但已退班 / 转班（非在读且本人辅导班）」，指标就会比列表大。

## 排查

1. 取参数：登录二讲 accountId（页面按**登录人**统计，不是「带班老师」下拉）、所选 `clazzNumber[]`、`renewalRoundFilter`（一般 `[1]`=一轮）。
2. 找登录老师在这几个班的 `subclazzNumber`（一个 clazz 对应该老师的 1 个辅导班），或直接按 `clazzNumber` 在 ES 聚合。
3. 直查 ES（PROD 走 `es-apply` skill 的 `es_workorder.py dsl --method GET`）：
   - 指标数 = `terms(canRenewal,[1,2,8])` ∩ `terms(subclazzNumber,<登录老师的辅导班>)` 的文档数（可选再 ∩ `terms(roundIdx, 轮次映射)`）。
   - 列表数 = 上面再 ∩ `term(clazzStudentStatus=1)` ∩ `term(subclazzStudentStatus=1)`。
4. 差集（指标 − 列表）= 列表看不到、指标却计入的学员。逐个取 `userId` 看：
   - `clazzStudentStatus=0`（退班）/ `subclazzStudentStatus=2`（非本人辅导班）→ 指标多算这人。
   - 再查该 `userId` **同一课程(`courseNumber`)** 的文档：若在**别的班/辅导班**有 `clazzStudentStatus=1` 且 `joinClazzTime` 较新的记录 ⇒ **转班/调班**，旧班文档仍留 `canRenewal∈{1,2,8}` = 「可续标记锁旧班」（与 [`../案例/2026-10-16-可续标记锁在旧辅导班导致不可续.md`](../案例/2026-10-16-可续标记锁在旧辅导班导致不可续.md) 同族，方向相反：那边新班取不到标记判不可续，这边旧班留标记多算）。
   - 顺带看是否真退款：文档 `hasCourseRefund`/`hasPendingRefund`/`latestRefundStatus`（=-1 即无退款）。

## 处置 / 说明

- 该现象**多数不是「在班状态被误清」**：学员确实已退班/转班，`(clazzStudentStatus=0, subclazzStudentStatus=2)=退款` 是**合法态**。差别来自**指标不筛在班状态**这个口径。给业务的话：把「学生辅导班状态」筛选项去掉即与指标一致（唐稳 2026-11-08）。
- 若要「指标 = 在读可续人数」，需产品确认给 `/roster/renewal/subclazz/statistic` 口径加在班过滤（代码改动，非临时处置）。
- 若确认是**转班后旧班可续标记未清**，要修按班**重算可续标记**（xjob `RenewalOrderSignHandler`，param `{"clazzNumbersStr":"<班号>","clazzType":<班型码>}` → MQ → student-data 写 ES）；属线上写操作，需授权，且只改「标记落哪个班」，改不了「指标是否筛在班」这个展示口径。

## 验证

- 指标数 = ES `canRenewal∈{1,2,8}`（本辅导班）计数值；列表数 = 其 ∩ `(clazzStudentStatus=1,subclazzStudentStatus=1)` 计数值；两者差 = 差集学员数。
- 别只看接口 200 / 页面刷新；要回读 ES 文档确认差集学员的 `clazzStudentStatus`/`subclazzStudentStatus`/`canRenewal` 取值。
