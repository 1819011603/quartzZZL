# 业绩归因 · 订单业绩被扣减（退款 / 调课冲抵负行）

> **只解决**：某人 / 某订单业绩出现扣减（负数行），要查「为什么扣、扣的是什么、谁触发的」。
> 业绩表查不到这单 / 归属人为空走 [`查不到归属人.md`](查不到归属人.md)；判单正常但排行榜显示 0 走 [`判单正常但排行榜显示0.md`](判单正常但排行榜显示0.md)；可续分母/可续锁别处走 [`不算可续分母或可续锁在别的订单.md`](不算可续分母或可续锁在别的订单.md)。

## 判定入口

业绩扣减**不是改原行金额**，而是**追加冲抵行**：原支付行保留，系统按规则反向生成一条负向行（`performance_price` 为正数，展示为扣减）。所以看到一个负数，先去业绩表按 `order_number` 把该单**所有行**拉出来，用 `trade_status` 区分来源：

| trade_status | 含义 | 来源 |
|---|---|---|
| 1 | 支付 | 正常判单（原业绩行） |
| 2 | 部分退款（退款不退课） | 退款 |
| 3 | 全部退款（退款退课） | 退款 |
| 4 | 调出退款 | 调课 / 调班 |

其它列：`trade_type` 1=正常订单 / 5=调课调班订单（退款带 transfer 标记时也为 5）；`price`（分）= 本行冲抵金额；`refund_order_number` = 关联退款单号；`employee_email` = 被扣减的归属人。

证据源（prod，服务实际读写的是 cluster_id **259 = gaotu-stats-prod**，73/332/339 是 ETL/ADB/腾讯侧副本）：

- 业绩明细：`gaotu_stat.performance_order_attribution`（K12）/ `..._adult`（成人）；汇总 `..._total`。成人 biz_line=2。
- 订单库 cluster_id **298 = gaotu-order-prod**，db `gaotu`：`refund_record`、`transfer_apply`、`order_info`。

## 排查

### 1. 退款扣减（trade_status 2 / 3）

1. 冲抵行 `refund_order_number` 就是退款单号。
2. 订单库 `gaotu.refund_record` 按 `refund_order_number` 查：`refund_reason` 即退款原因（如「调课」「用户申请」），`price` = 实退金额，`create_time` = 退款时间。
3. 扣减金额 = 退款金额 × 原业绩行 `price_ratio`（成人见 `DefaultAdultOrderRefundSuccessStrategy`，K12 见 `K12OrderRefundSuccessStrategy` 等）。

### 2. 调课扣减（trade_status = 4 调出退款）

调课调班时，原订单被「调出」的价值会在**原（父）订单**上生成一条 trade_status=4、trade_type=5 的负行，扣掉原单归属人的业绩。

1. 扣减金额 = **调课新单 `(price - realPrice)`**（新单标价 − 实付），即从原订单调出、带入新单的那部分价值。代码：`AdultCallOutRefundStrategy:91`（`inheritPrice = transferOrder.getPrice() - transferOrder.getRealPrice()`）、`K12CallOutRefundStrategy` 同式。
2. 定位调课动作：订单库 `gaotu.transfer_apply`，按 `origin_order_number` 或 `old_order_number` = 原订单号查：
   - `target_order_number` = 调课后的新单；`target_clazz_number` = 新班；
   - `origin_order_price` = 从原单调出的价值（= 扣减金额）；
   - `delta_price` = 学员补款；`operator` = 操作人 accountId；`reason` 通常是「调课」；
   - `status`：3/4 等，多次尝试时以成功那条为准。
3. 配套现象：原单还会有一条 trade_type=5、`price=0` 的「全退」标记行（退款策略在 `transfer=true` 时写，实退 0 元，仅作状态标记）。
4. 新单业绩：`gaotu_stat.performance_order_attribution_total` 查 `target_order_number`，通常继承为 续班(21)/新签 归到**新单归属人**（可能与原单归属人不同）。调课 = 把这部分价值从原单归属人挪给新单归属人。

## 验证

- 扣减金额对得上来源：退款 = 退款单 `price` × 原行 `price_ratio`；调课 = 新单 `(price - realPrice)` = `transfer_apply.origin_order_price`。
- 调课必须能同时定位到 `transfer_apply` 记录 + 新单的业绩行，且新单金额 ≈ 调出价值 + 补款。
- 一笔订单只有一个支付原行；若同一 refund_order_number 出现多组同状态冲抵行，才怀疑重复投递（正常替换式写入应幂等）。
