# 业绩归因 · 业绩统计看不到某人的商品（住宿费等）业绩

> **只解决**：业绩看板「业绩统计」里看不到某员工的**商品/实物**业绩（如住宿费、场地使用费等商品中心 SKU），甚至该员工整行不出现。
> 判单没跑 / 归属人为空走 [`查不到归属人.md`](查不到归属人.md)；
> 判单正常但**排行榜**显示 0 走 [`判单正常但排行榜显示0.md`](判单正常但排行榜显示0.md)；两者与本文无关。

## 判定入口

先分清两种「看不到」：

1. **该员工整行不出现**（列表里根本没有这个人）——本文主因。
2. 员工行在，但「实物业绩」列为空/0 —— 先查数据是否真的落在 `performance_physical_attribution`，再看本文。

关键事实来源：

- 「业绩统计」员工/部门列表 = `performanceStatisticsPayDtos`（**只由课程业绩的 ES 聚合桶填充**），见
  `PerformanceStatisticsServiceImpl#aggregateEmployeePerformanceStatisticsWithStaff:1152`、
  `getAttributionStatisticsDtoListByStaff:993`；ES 分桶只在 `#queryESPerformanceStatistics:321` 里写入 DTO。
- 课程 ES 聚合按 `termQuery(BIZ_LINE, bizLine)` 过滤，bizLine 只会是 `K12=1` / `ADULT=2`
  （`#convertQueryBuilderForStatistic:1771`）。
- 商品中心 SKU（住宿费=8028、场地使用费=8019、水/电费等）判单落 `performance_physical_attribution`，
  **`biz_line=0`**；镜像进 `performance_order_attribution_total` 后 ES 文档的 `bizLine` 也是 0
  （`PerformanceDashboardAttributionDocumentConstructor` `document.put(BIZ_LINE, ...)`）。

⇒ 只统计课程业绩的聚合里永远不含 `biz_line=0` 的商品行；而员工列表又派生自课程聚合。
**所以某区间内只有商品（住宿费）业绩、没有课程业绩的员工，根本不会进入列表，商品列也随之不显示。**

## 排查

1. 确认商品类型编码：`SELECT type_name, product_code FROM product_type_tree WHERE type_name='住宿费'`（住宿费=8028）。
2. 确认业绩已落库（cluster 259 / db `gaotu_stat`）：
   ```sql
   SELECT sku_type, biz_type, type, trade_status, COUNT(*), SUM(performance_price)
   FROM performance_physical_attribution
   WHERE employee_email='<邮箱前缀>' AND isdel=0 GROUP BY sku_type, type, trade_status;
   ```
3. 确认该员工在**查询区间内只有商品行**（无 `sku_type=2` 的课程行）——即会触发「整行消失」：
   ```sql
   SELECT DATE_FORMAT(trade_time,'%Y-%m') ym, sku_type, biz_line, COUNT(*), SUM(performance_price)
   FROM performance_order_attribution_total
   WHERE employee_email='<邮箱前缀>' AND isdel=0 GROUP BY ym, sku_type, biz_line ORDER BY ym DESC;
   ```
   商品行是 `sku_type=8028, biz_line=0`；课程行是 `sku_type=2, biz_line in (1,2)`。
4. 确认归属人本人**在本主管下属范围内**（不是权限问题）：调 staff
   `POST https://fuwu.baijia.com/bgwApi/staff/listByAccountIdWithDot?accountIds=<accountId>`（GET），
   比对管理员的 `type in (1,2)` orgNumber 是否是该员工 orgPath 的祖先。
   `permission.staff.switch=true` 时「业绩统计」走 staff 主岗下属，不是门神。

## 验证

- 用 `performance_order_attribution_total` 的月度分布证明：该区间只有 `sku_type=8028`（biz_line=0）行、没有 `sku_type=2` 行
  ⇒ 课程 ES 聚合为空 ⇒ 员工列表为空 ⇒ 结论成立。
- 反证：把区间挪到该员工有课程业绩的月份（如 puguanyu 的 2026-09），行会出现，商品列也有值。

## 备注（取数架构缺口，非数据丢失）

- 修的方向：员工/组织列表不要单靠课程聚合派生（或让 `biz_line=0` 的商品镜像行也参与「列表人群」），
  属需求改动，回溯补数不能解决。判单与落库本身是正确的。
