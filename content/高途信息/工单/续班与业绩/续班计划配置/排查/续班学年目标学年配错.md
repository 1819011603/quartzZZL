# 续班计划配置 · 续班学年（目标学年）配错 / 续班商品搜索不到

> **只解决**：OES 续班计划里「续班学年/学期」配错、计划商品列表按联报ID（或班号）搜不到、以及计划创建/发布后页面改不了。
> 若是 **C端续班推荐**看不到某学员/某班（联报 status=3 停止招生被 cart 过滤），走 [`../../续班推荐加购/排查/在读学员纯续推荐缺失或提示未报名.md`](../../续班推荐加购/排查/在读学员纯续推荐缺失或提示未报名.md)，与本页无关。

## 判定入口

- 先拿「续班计划ID」（页面「续班计划ID」= `gaotu.renew_master.number`）。飞书/前端复制常被 JS 精度截断（17 位末两位变 `00`），查不到先按前 15 位前缀找候选。
- 分流：
  - **B端「续班服务」/ 计划里按 联报ID 或 班号 搜不到商品** → 本 runbook（多半是计划目标学年/学期配错）。
  - C端推荐缺课 / 提示非在读 → 续班推荐加购模块。

## 排查

1. 读计划 + 目标学年（prod `gaotu` 集群）：

   ```sql
   SELECT number, name, status, isdel FROM gaotu.renew_master WHERE number=<计划number>;
   SELECT relation_type, relation_value FROM gaotu.renew_master_ext
   WHERE renew_master_number=<计划number> AND isdel=0;
   ```

   关注 `SCHOOL_YEAR`(当前学年)、`SCHOOL_TERM`(当前学期)、`TARGET_SCHOOL_YEAR`(续班/目标学年)、`TARGET_SCHOOL_TERM`(目标学期)、`COURSE_GRADE`/`COURSE_SUBJECT`/`DEPARTMENT`。

2. 学年/学期 id 的口径（`course_center.course_center_dictionary`，集群 317）：
   - `schoolYears`：`2026`→`2026-2027`、`2027`→`2027-2028`……（id = 学年起始年，页面显示「起始-结束」）
   - `schoolTerms`：`Q` 秋季 / `D` 寒假 / `C` 春季 / `X` 暑假（还有 `QD`/`CU` 等上下半学期）

3. 对照同批计划的正常值：同 `SCHOOL_YEAR`+`SCHOOL_TERM` 的其它计划，`TARGET_SCHOOL_YEAR`/`TARGET_SCHOOL_TERM` 应一致。**只有一个不同 → 就是它配错**。例：26秋(`SCHOOL_YEAR=2026/Q`)计划普遍 `TARGET_SCHOOL_YEAR=2027`、`TARGET_SCHOOL_TERM=D`。

4. 确认影响链（product-server，即网关 `/product-b`）。**全库仅 product-server 读 `TARGET_SCHOOL_YEAR`**——cart / student-center / student-data / order / course-center / promotion 的 Feign 适配器虽能拿到 `targetSchoolYearList`，但全仓无一处消费（搜 `getTargetSchoolYearList`/`getTargetSchoolYear` 为 0；cart `CourseUtils#targetSchoolYear` 只是局部变量重名）。读取点共 5 处：

   | # | 位置 | 影响接口/行为 | 性质 |
   |---|---|---|---|
   | 1 | `RenewalProductServiceImpl#buildProductQueryDTO:383-394` | `/b/renewMaster/productList`——**既用于计划里搜/绑定商品，也用于「续班服务 → 创建订单」下单页的「联报/班课范围」**（FE `continu-clazz-order`：`sceneAttributeList` 出学年/学期/年级/学科下拉→`productList` 查商品，见 `chain.mermaid` API5/API6）。联报 `listClazzSet`→`buildClazzSetQuery:348-363`（另固定 `courseCategoryIdList=[30,40]` 专题/系列、`newSaleStatus=1` 可售卖）、班级 `listClazz`→`buildClazzQuery`，都调 `buildProductQueryDTO` 把计划 `TARGET_SCHOOL_YEAR/TERM` 与请求筛选**求交**（请求为空则直接用计划值）→ **目标学年 2026 时，学年 2027-2028 的联报不在下拉/结果里，搜不到**（与上架/售卖状态无关；此即"下单的联报范围"）。下游 course-setting `ActivityClazzService#selectForPage:642` 按 `schoolYearIdList/schoolTermIdList/grades/subjects/newSaleStatus` 查 ES（`:1598-1604`） | **功能性** |
   | 2 | `RenewSceneAttributeStrategy#getRenewAttributeMap:82` | `/b/renewMaster/sceneAttributeList` 续班场景属性中目标学年/学期的可选值 | **功能性** |
   | 3 | `RenewalServiceImpl#setRenewalMasterDTO:2762` | 计划详情(`detail`)/列表/Feign 返回的「续班学年」展示（`setTargetSchoolYearList`） | 仅展示 |
   | 4 | `RenewalMasterListQueryBO:107-110` + `RenewMasterBizMapper.xml:113-121/223-231` | `/b/renewMaster/list` 按「目标学年」筛选 | 筛选条件 |
   | 5 | `RenewalMasterDomainServiceImpl:230-235` | 创建计划时写库（`RenewalMasterCreateRequest.targetSchoolYearId/List`） | 写入 |

   **不受影响**：C端续班推荐、花名册可续/在读科目、判单/业绩归属、问卷绑定、续班关系校验（`checkRenewCourseRelation:1488` 用的是 `SCHOOL_YEAR`**当前学年**不是目标学年）、已绑定的前后置关系。故改它 = 只动 B端计划配置（核心是搜品），C端与已绑数据不动。

   ⚠️ **别把"目标学年"和"目标学期"混为一谈**：计划的**学期**字段（当前 `SCHOOL_TERM` + 目标 `TARGET_SCHOOL_TERM`）另有消费方——cart `RegistrationService#dealGrade`（**预报名落地页** `preRegistration(...)` + **xjob `PreRegistrationJobHandler`**）和 product-server `InspectService#dealGrade`（**预报名巡检/告警**）。两处都用 Apollo 白名单 `preRegistration.schoolTerm.list`（当前学期）+ `preRegistration.targetSchoolTermList.list`（目标学期）判断是否做**年级升级映射**（`preRegistration.grade.map`，如初三→高一），不匹配就不升级；预报名商品名 `termName` 也直接取 `getTargetSchoolTermList()`。**所以预报名跟计划学期有关，跟目标学年无关**——改学年不动预报名，改学期才会。排查预报名问题时先看计划 `TARGET_SCHOOL_TERM`，不要只看学年。

5. 上下游 / 看板核对（全 `~/IdeaProjects`，确认无其他消费方）：
   - `renew_master_ext` 表**只有 product-server 运行时引用**（`wt-20261001/` 是副本、`qa-data-agent-service` 是造数工具，非线上链路）；`TARGET_SCHOOL_YEAR` 常量仅在 product-server 4 类 + enum。
   - 全仓 `getTargetSchoolYear*` **0 命中**；`cart`/`promotion-app` `CourseUtils#targetSchoolYear`、`study-report` `StageStudyReportFacadeImpl:316` 都是重名局部变量（比的是**课程**学年），与计划字段无关。FE `gaotu-fe-promotions` 用 `targetSchoolYearList` 只做列表列/详情展示 + 编辑表单（上游，本就该跟着变）。
   - **续班看板 / 续班过程看板**：数据源 Doris `student_data_renewal.sub_clazz_renewal_process_snapshot`（xjob `RenewalDashBoardHandler` 从 ES `ads_large_subclazz_user_index` 聚合），学年列来自 `course-center` 的 `CourseDO`（`handler:694` `courseVO.getSchoolYearId()`），**不读续班目标学年**；handler 只用计划 `getName()`（`handler:800`）。
   - student-data 其余读计划处（`WideSmallClazzRenewalBinder`/`RenewMasterDataClaimer`/`SmallClazzUserRenewalInfoQueryService`/`RenewalMasterAclService`）只用 `getNumber/getName/getBeginTime/getEndTime/getPreCourseList`；`performance-attribution` 不引用续班计划。

5. 页面「续班学年」对应 `TARGET_SCHOOL_YEAR`（`RenewalMasterExtEnum`）：**计划发布后基础信息不可编辑**（`RenewalMasterManageController` 无对应编辑接口），只能改库。

## 修复（生产 DML，须先获授权）

```sql
UPDATE gaotu.renew_master_ext
SET relation_value='<正确学年，如 2027>', update_time=NOW()
WHERE renew_master_number=<计划number> AND relation_type='TARGET_SCHOOL_YEAR' AND isdel=0;
```

- 影响面：只改「搜索/绑定商品」的筛选维度；已绑定的前后置续班关系（`renew_master_course_relation` / `course_center.course_relation_map`）与 C端已有推荐**不变**。
- 回滚：把 `relation_value` 改回原值即可。

## 验证

- 回读 `renew_master_ext`，`TARGET_SCHOOL_YEAR` 已为目标学年；
- 用该计划编号 + 联报ID 调 `/b/renewMaster/productList`（或页面「续班场景商品」重搜）能返回商品；
- 页面「续班学年」显示正确。
- `UPDATE` 成功 / 页面刷新 ≠ 业务生效，必须回读 + 重搜为证。
