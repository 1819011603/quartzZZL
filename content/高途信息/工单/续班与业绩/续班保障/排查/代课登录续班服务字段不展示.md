# 续班保障 · 代课登录大班续班服务，字段列不展示 / 报「代课用户无访问该接口权限」

> **只解决**：以**代课(cosplay)**身份打开大班续班服务（`clazzRosterOL?tabKey=continuationService`）等 B 端页面时，
> 某些字段列（如「小班在读科目」）**不展示/为空**，并弹出红色提示「**代课用户无访问该接口权限**」。
> 字段值本身不对（非代课也错）走 [`小班在读科目为空或陈旧.md`](小班在读科目为空或陈旧.md)，与本文无关。

## 机制（已在代码确认 + 账号所有者定性）

- **场景（账号所有者定性）**：代课登录后**自己加某列/字段**（如「小班在读科目」，即自选列/字段配置）——前端**乐观地**当作已加并展示，
  但**后端把这次请求拦截了**：因为该**代课没有开这个（写）接口的权限**，配置实际**没保存成功** → 该列**不展示**。
- student-center `LoginInfoFilter#doFilter`：仅当请求头 `gaotu-cas-authorization` 的 `casAccount.isCosplay()==true`（即**代课模式**）时，
  对**每个请求 URI** 调 `PermissionComponent#hasPermission` → teacher-tool `checkInterfacePermission`
  （`permissionGroup=student-center`，`projectCode` = 3(EES) / 4(GPS，`B_client=GPS` 或 host 含 `os.baijia.com` 时)）。
- 命中未登记 → 返回 `BusinessErrorCode.COSPLAY_PERMISSION_FAIL`，前端弹「代课用户无访问该接口权限」（文案来自 Apollo `cosplay.permission.check.fail.msg.set`），该接口**当次请求被拦**。
- 即：**"加列"是一个写接口**，代课模式下它的（写）权限没开 → 被拦 → 列不生效（表现成"自己加了也不展示"）。
- 开关 Apollo：`cosplay.permission.check.switch`（总开关）、`cosplay.permission.check.fail.notice.switch`（飞书告警）。

## 排查

1. **确认是代课模式**：非代课登录不该触发此校验（`isCosplay()` 才走）。
2. **定位被拦的写接口**（关键）：浏览器 Network 里找"加列/保存字段配置"那个请求，看它返回该错误文案 / 非 0 code（就是它没存上）。
   - 备用：SLS（student-center，prod，`logType=app`）搜 `LoginInfoFilter#doFilter,cosplay has no permission`，报文含 `account <账号>,uri <路径>`。
3. **核该 URI 的代课登记**：到 `sd.baijia.com`「代课接口录入」页（schema id `bd8ec9d7-c4eb-46d2-8bbf-49681dd82604`），按 `permissionGroup=student-center` 看该 `<path>` 的登记与读写类型。

## 处置

- 按业务需要为该接口/该代课**开放（写）权限** —— 用 skill `cosplay-interface-perm` 到 `sd.baijia.com` 登记（`--permission-group student-center`）。**是否应给代课开写权限属业务决策**，需确认。
- 或（更稳）把该字段放进**基础列配置**，让这类用户**不用自加**也能看到（走 GAIA 字段配置，业务决策）。

## 验证

- **算生效**：以**代课身份**重新请求被拦的那个保存接口 —— 应正常返回（不再被拦）；刷新页面该列出现值。
- **不算通过**：登记接口回执 success；页面无 toast 但列仍空（保存仍未生效 / 字段配置未开）。
