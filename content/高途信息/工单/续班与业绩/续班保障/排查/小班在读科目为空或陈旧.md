# 续班保障 · 大班续班服务页「小班在读科目」为空 / 陈旧

> **只解决**：大班班级花名册「**续班服务**」tab 的「小班在读科目 / 续班小班科目」列，与学员实际小班在读不一致——
> 要么**空**（实际有小班在读），要么**陈旧**（小班已退课仍显示）。
> 大班**本班**「在读科目 / 在读科目数」比实际多走 [`在读科目比实际多.md`](在读科目比实际多.md)，与本文无关。

## 判定入口

先固定：**大班 userId、大班班级（clazzNumber）、大班辅导班（subclazzNumber）、学年+学期**。

- 字段来源：ES 索引 `ads_large_subclazz_user_index`（EES 集群 `es-cn-smw4b9m200004w3hn`）**大班辅导班文档**（`_id = subclazzNumber-userId`）的 `smallStudyingSubject` / `smallStudyingSubjectCnt`。**大班花名册 default tab（`ads_large_clazz_user_<年>`）没有这份字段**——两端看的不一致时先排除 tab 差异。
- 口径：小班在读表 `ees_data.dws_small_clazz_user_subject` 里与该大班**同学年+学期+同年级**（年级取大班文档 `courseGrades`）的科目；**卡年级**，且**大班表用 OES 学期、小班表用 CES 学期**（`SmallClazzOesCesSchoolTermEnums`，CES 3=秋）。
- 写方：`SmallRenewalSubjectService#calRenewalInfo`（大班分支 `getLargeRenewalSubjectInfo` → `collectSmallStudyingSubjects`）；DQ `LargeRelationSmallRenewalSubjectQueryService`（`largeRelationSmallRenewalSubject`）/ MQ `OdsSmallRenewalSubjectSyncService`（小班进 / 退班 `SMALL_SUB_CLAZZ_ENTER|QUIT`）。门控 Apollo `SmallRenewalSubjectService.needHandleLarge`（false 时该组恒空）。
- **该字段不随查看人（代课身份）变化**：它是文档级 ES 字段。两人看到不同值，只可能是看的**班/行不同**或**tab 不同**，不是按登录人过滤。

## 排查

1. **读大班页字段**（权威现值）：查 `ads_large_subclazz_user_index` 文档 `_id=<subclazzNumber>-<userId>` 的 `smallStudyingSubject` / `Cnt` / `courseGrades`（ES skill `es-apply`）。
2. **读小班侧对照**：
   - 源表 `ees_data.dws_small_clazz_user_subject`（prod，`WHERE user_id=?`）：看有无 `is_del=0`、其 `grade_id` / `school_term_id`（CES）/`subject_id`；用 `course_center.clazz`（cluster `gaotu-course-prod`）按 `number=` 取小班班级名 / 年级。
   - 小班页索引 `ads_small_clazz_user`（studentServe 集群 `es-cn-4xl3gu6ls0007l185`）同班文档 `smallStudyingSubject`（C 组口径，应同为"无"）。
3. **判定**：
   - 大班页有值、且汇总后与小班侧"在读（`is_del=0`）+ 同年级"科目一致 → **正常**；
   - 大班页有值、小班侧已无在读（`is_del=1`）/ 小班页为空 → **大班侧陈旧**（小班退课事件漏刷该大班文档），回溯重算；
   - 大班页为空、但有小班在读 → 先看**小班班级年级**是否与大班 `courseGrades` 有交集（不交即空，口径如此、回溯不改变）；再看 `needHandleLarge`；再看源表有没有该学员行。

## 常见根因：退课后字段残留（「剩余为空即 return」）

- 该字段是**事件快照**：小班进/退班 MQ → `calRenewalInfo` 重算 → 写 ES（大班分支 `upsertLargeEs`）；页面只读快照，**不是实时算**。退课/退款后要变空，必须有「重算 + 回写空值」。
- **`OdsSmallRenewalSubjectSyncService#dealMsg` 退班分支的边界 bug**：置删后查「剩余在班小班记录」`queryDeleteClazzInfo`（`listByUserId` is_del=0 去掉本班），**为空（退的是该学员最后一个在班小班）时直接 `return`** → 不重算、不回写（连 `handleQuitSmallRelationLarge` 也跳过）→ 大班 / 小班 ES 的 `smallStudyingSubject` **保留退班前旧值**。→ 表现：小班已退（源表 `is_del=1`、小班页空），大班页仍显示旧科目。
- 只要该学员退**最后一个**在班小班就会中招；退的若不是最后一个（还剩别的在班小班）会正常重算。排查时看源表该学员是否**已无 `is_del=0` 小班记录**即可判断。

## 验证

- 大班页 `smallStudyingSubject` 去重集合 == 小班在读表（`is_del=0`）里同年级科目集合 → 一致即正确。
- `updateTime` 很新**不能**证明该字段新（部分更新也会刷新 `updateTime`，见上）；陈旧判定以源表为准。
- 回溯入口（重算文档、源表不用补）：大班续班服务索引 = quickBack **type=13** `QuickBackAdsSubClazzUserWorker` / `POST /gps/manual/back/largeSubClazz`（`{"clazzNumbers":[...]}`）。生产写需 RD 授权。
