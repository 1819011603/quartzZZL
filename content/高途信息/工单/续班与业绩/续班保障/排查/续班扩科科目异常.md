# 续班保障 · 花名册「续班扩科科目」异常（出现非后置的已发生科目）

> **只解决**：花名册 / 续班服务页「续班扩科科目」（小班课花名册上文案近似「大小班扩科科目」）列出现了不符合预期的科目 —— 典型如**寒春尚未开售却有值**、出现学员**暑假/更早学期**的在读科目。
> 若症状是「在读科目数多算」走 [`在读科目比实际多.md`](在读科目比实际多.md)；本文只管**扩科科目**这一列。

## 字段与口径

| 页面 | ES 字段 | 索引 / 集群 |
|---|---|---|
| 大班花名册 | `renewalExpansionSubject` | `ads_large_clazz_user_<年>`（studentServe `es-cn-4xl3gu6ls0007l185`） |
| 大班续班服务 | `renewalExpansionSubject` | `ads_large_subclazz_user_index`（EES `es-cn-smw4b9m200004w3hn`） |
| 小班课花名册 | `smallRenewalExpansionSubject` | `ads_small_clazz_user`（studentServe） |

**代码口径（小班 `SmallRenewalSubjectService#getRenewalSubjectInfo` / 大班 `RenewalInfoServiceImpl#groupGradeCurrentRenewalSubjectMap`）**：

```
扩科 = 学员在「后置课程的 学年+学期+年级」维度下的 小班在读 + 大班在读
        − 小班续班 − 大班续班 − 小班在读 − 大班在读
```

- **后置课程** = course-center 续班关系：`CourseNotNormalAclService#mapPostCourseNumberCache(courseNumbers)`（内部 `listBeContinuationCourseInfoByNumberList`，取 `calculateRenewalType=1` 的关系课程）。
- 取学员在读用的 key 是 **后置课程的 `schoolYearId` + `schoolTermId` + grade**（`queryYearTermGradeKey(CourseDO,grade)`）。
- ⚠️ **关键**：只要「后置课程列表」里含一门**学年学期 ≤ 本班**的课，就会把学员**已发生（当前/过去学期）的在读科目**当成扩科。寒春未开售 ≠ 扩科为空，取决于后置课程的学年学期。

## 排查

先固定：**班级 ID（clazzNumber 或 bizNumber）、出现异常的学员 userId**。

1. 班级 → 课程：`ClazzSyncAclService#listByNumbersFromCache([clazzNumber])`（注意大数字传字符串）。
2. 课程 → 后置课程号：`CourseNotNormalAclService#mapPostCourseNumberCache([courseNumber])`。
3. 后置课程详情（重点看 `schoolYearId` / `schoolTermId` / `grades` / `subjects`）：`CourseSyncAclService#listByNumbersFromCache([...])`。
   - **看有没有后置课程的学年学期 ≤ 本班**（如 2026秋 班的后置里出现 `schoolYearId=2026, schoolTermId=X` 的暑假课）。
4. 学员在读：小班 `DwsGpsClazzUserSubjectDao#listByUserId(userId)`；大班 `DwsFuwuClazzUserSubjectDao#listClazzInfo(userId)`（看 `schoolYearId/schoolTermId/subjectId`）。
5. 实时复算对照：小班 `SmallRenewalSubjectService#calRenewalInfo(userId,true)`（返回 `smallRenewalSubjectInfoList[].renewalExpansionSubjectSet`，含每条在读班级的明细）；大班 `RenewalInfoServiceImpl#calRenewalInfo`。
6. 也可以直接从 ES 反查有值的文档：
   ```bash
   cd ~/.claude/skills-cold/es-apply
   python3 es_workorder.py search --instance-id es-cn-smw4b9m200004w3hn \
     --index ads_large_subclazz_user_index --query '{"query":{"bool":{"must":[{"term":{"clazzNumber":"<clazzNumber>"}},{"exists":{"field":"renewalExpansionSubject"}}]}},"_source":["userId","renewalSubject","renewalExpansionSubject"],"size":10}'
   ```

## 判定

- 扩科科目 ∈ 学员在「某后置课程的学年学期年级」下的在读科目（且不属于续班/在读）。
- 若该后置课程的学年学期落在**当前班同学年或更早**（例如后置列表里混进一门**暑假/上学期**的课），则扩科是**假象** —— 把学员已发生的报名当成了"后置扩科"。
- 根因通常在 **course-center 续班关系配置**（某门非后置课被配成 `calculateRenewalType=1` 的后置课程），或口径本身未要求"后置课程学年学期必须晚于本班"。

## 处置注意

- ⚠️ **改/删 course-center 续班关系后，student-data 不会立即看到**：后置课程列表走 Redis 缓存 `gaotu::course::renewal::mapPostCourseNumberCache::<courseNumber>`（`CourseNotNormalAclService#mapPostCourseNumberCache`），TTL = Apollo `student-data/renewal.course.cache.seconds`（**PROD 现值 3600s**）。**删配置后直接回溯仍会算出旧值**，须先清缓存或等 TTL。
  - 一个已删后置课可能挂在同系列**多门课**的缓存里（学员同时在读多门课时尤其明显）——清一个 key 不够，按 `course_relation_map` 里 `course_number=该后置课` 的 `relation_number` 全集清。
  - 清法（prod，需授权）：pod-terminal + arthas OGNL `@com.gaotu.student.data.util.RedisCacheUtil@redisTemplate.delete("gaotu::course::renewal::mapPostCourseNumberCache::<course>")`（可传 `@java.util.Arrays@asList(...)` 批量）；先 `sc -d com.gaotu.student.data.util.RedisCacheUtil` 取 classLoaderHash 供 `ognl -c <hash>`。
- **回溯只重算当前值，不改变口径**：若是口径/配置问题，回溯后仍会再出现；应先与产品/课程关系侧确认"后置课程能否是同学年/更早学期""专题课(30)/系列课(40) 是否计扩科"，再决定改代码（过滤后置课程学年学期）还是改配置。
- 生产回溯入口（需授权）：大班 `quickBack` type=13 / `POST /gps/manual/back/largeSubClazz`；小班 quickBack type=14/15（见 skill `clazz-roster-es-backfill`）。
- 字段口径全貌见知识库 [`续班科目/大班与小班续班科目字段口径.md`](../../../../知识库/续班科目/大班与小班续班科目字段口径.md)。
