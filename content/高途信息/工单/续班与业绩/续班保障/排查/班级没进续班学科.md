# 续班保障 · 某班级/学员没进续班学科

> **只解决**：续班学科表 `dws_fuwu_clazz_user_subject` 里查不到某班级/学员，判断是「事件没消费」还是「被 `checkFilter` 拦掉」。
> 两门课之间有没有续班关系配置，走 [续班关系配置](../../续班关系配置/README.md)，与本文无关。

## 判定入口

先分清是「消费侧没写」还是「上游没发」：

1. 该班级/学员是否有进班事件（topic `gaotu_subclazz_student_event`，tag `TAG_Subclazz_Enter`）。
2. 有事件但表里没数据 → 看是否被 `DwsRenewalSubjectConsumer#checkFilter` 拦掉（见下）。
3. 无事件 → 上游（服务域）问题，不在本模块。

## 排查

**链路**：进/退班事件 → `DwsRenewalSubjectConsumer` 过滤 → 写 `dws_fuwu_clazz_user_subject` → 计算续班信息 → 落 ES。

**`checkFilter` 过滤顺序**（`student-data-dws`，`DwsRenewalSubjectConsumer` :311），任一「拦」即不写学科表：

| # | 条件 | 结果 |
|---|---|---|
| 1 | 命中白名单 `dws.renewal.subject.check.clazz`，且开关 `dws.renewal.subject.check.switch`=true | 直接放行 |
| 2 | course 查不到 | 拦 |
| 3 | `bizType`=成人(2)，或 非付费课（非专题课 30 / 系列课 40） | 拦 |
| 4 | 命中赠课标签 `studying.subject.course.tag.exclude.list` | 拦 |
| 5 | 纯预售课（`PresaleSubjectServiceImpl#isPresaleCourseNumberCache`） | 拦 |

排查动作：

- 查班级白名单与开关（Apollo `student-data` / 对应 env）：
  - `dws.renewal.subject.check.clazz`（JSON 数组，班级 `clazzNumber`）
  - `dws.renewal.subject.check.switch`
- 查该班级对应课程（`CourseSyncAclService#listCourseDOByNumbers`）的 `courseTypes` / `bizType` / `courseTags`。
- 查 `studying.subject.course.tag.exclude.list`（PROD=`13`，TEST=`27,13`）。
- 查是否纯预售：`PresaleSubjectServiceImpl#isPresaleCourseNumberCache(courseNumber)`。
- 日志：`DwsRenewalSubjectConsumer#checkFilter,...`（`amount filter` / `courseType or bizType filter` / `courseTags filter` / `presale filter`）。

> ⚠️ **金额校验已不存在**：`checkFilter` 里「订单金额 ≤ 0 就拦」的代码已于 commit `76ec559d2`（2025-12-15）删除（`origin/master` / `origin/release` 均包含）。代码 :182 的注释「订单金额、课程系列、预售课程过滤」是**残留注释**。所以对能过上面第 2~5 条的班级，白名单只省一次 `queryCourseDO`，**无行为差异**。

## 验证

- 白名单命中（第 1 条）→ 该班级无论课程类型如何都会写学科表，事件一旦消费即可见。
- 不命中白名单时，只有第 2~5 条全部通过才会写；命中等价于强制放行。
- 「事件已消费」不等于「学科表有数据」：仍要回查 `dws_fuwu_clazz_user_subject`。
