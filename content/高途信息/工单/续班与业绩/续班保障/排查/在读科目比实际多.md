# 续班保障 · 花名册在读科目比实际多（在读科目数偏大）

> **只解决**：花名册 / 续班服务页（clazzRosterOL，tab `continuationService`）的「在读科目数 / 在读科目」比学员实际在读科目多（多算 1 科或多科）。
> 某班级/学员**根本没进**在读科目表（查不到、少算了）走 [`班级没进续班学科.md`](班级没进续班学科.md)，与本文无关。

## 判定入口

先固定三件事：**学员 userId、学年+学期（页面筛选器口径，如 2026 秋季 = 学年 2026 / 学期 Q）、当前登录班级**。

页面「在读科目数」的直接来源是**花名册 ES 索引** `ads_large_subclazz_user_index`（**EES 集群** `es-cn-smw4b9m200004w3hn`）文档里的 `studyingSubjectCnt` 字段（`studyingSubject` 是科目 id 数组）。**它不等于**源表 `dws_fuwu_clazz_user_subject` 的实时值。

口径（PRD「在读科目」字段说明）：当前学季（学年+学期）学员报名的**正价课**班级对应科目，**相同科目去重**；范围 = 不含课程标签「赠课」、订单未全部退款、专题课(30)/系列课(40)、非纯预售、大班课、业务类型非成人。

**判据**：以源表（`is_del=0`，当前学年学期）去重后的科目数为准；若 **源表数 < 索引 `studyingSubjectCnt`**，就是索引陈旧。

## 排查

### 1. 查权威源（在读科目表，prod）

表 `dws_fuwu_clazz_user_subject` 按 user_id 分 16 片（`_0`..`_15`），库 `student_dw_data`（cluster `gaotu-student-dynamic-prod` / id `336`）。跨片取：

```sql
-- 16 片 UNION ALL，再按 is_del=0 + 当前学年学期去重
SELECT DISTINCT subject_id, clazz_number, is_del, price, create_time, update_time
FROM (SELECT * FROM student_dw_data.dws_fuwu_clazz_user_subject_0 WHERE user_id=<userId>
      UNION ALL ... UNION ALL SELECT * FROM student_dw_data.dws_fuwu_clazz_user_subject_15 WHERE user_id=<userId>) t
WHERE school_year_id=<year> AND school_term_id='<C/X/Q/D>' AND is_del=0;
```

### 2. 查索引（读 ES）

EES 集群 `es-cn-smw4b9m200004w3hn`（Apollo `student-data/PROD` namespace `es` key `ees.serve.es.cluster.host`）；索引 `ads_large_subclazz_user_index`（bean `eesServeClient`，`AdsSubclazzUserSyncUpdateService`）。文档 `_id = <subclazzNumber>-<userId>`：

```bash
cd ~/.claude/skills-cold/es-apply
python3 es_workorder.py search --instance-id es-cn-smw4b9m200004w3hn \
  --index ads_large_subclazz_user_index \
  --query '{"query":{"term":{"userId":<userId>}},"_source":["userId","clazzNumber","subclazzNumber","schoolYearId","schoolTermId","studyingSubject","studyingSubjectCnt","updateTime"],"size":50}'
```

同时可对照**新索引**（studentServe 集群 `es-cn-4xl3gu6ls0007l185`，Apollo key `student.serve.es.cluster.host`）：`ads_large_clazz_user_<学年>`（如 `ads_large_clazz_user_2026`），字段同为 `studyingSubject`/`studyingSubjectCnt`，按班级号分年。两份索引对同一学员应一致；不一致时以源表为准。

### 3. 判定

- 源表去重 < 索引 → **索引文档陈旧**：多出来的科目通常是该学员**已退班（`is_del=1`）的旧科目**（转班/换科时新旧科目短暂并存被写入，之后未重算该索引文档）。
- 排查中常见迹象：同一学员的**多个索引文档 `studyingSubject` 互相不一致**（有的含旧科目、有的不含）→ 说明是逐文档陈旧，不是全量算法错。

## 圈定受影响范围（按班，从源表圈，不用比 ES）

两个索引**在不同 ES 集群**（`ads_large_clazz_user_<年>` 在 studentServe、`ads_large_subclazz_user_index` 在 EES），**不能 join**；两边都是百万级文档、读工具不支持 scroll，全量导出不现实。所以「哪些班受影响」从**源表**圈：

> 受影响学员 = 同一 `school_year_id`+`school_term_id` 下，**既有 `is_del=1`（退/换掉的科）又有 `is_del=0`（在读）** 的学员；其 **`is_del=0` 记录对应的 `clazz_number`** 就是「续班服务页可能多算」的班。**这是超集**（退过科的在读班都会进来）。

逐片查（整段 16 片 UNION 会超时，必须分片；`dws_fuwu_clazz_user_subject` 按 user_id 分 16 片）：

```sql
SELECT DISTINCT clazz_number FROM student_dw_data.dws_fuwu_clazz_user_subject_<n>
WHERE school_year_id=2026 AND school_term_id='Q'
  AND FIND_IN_SET('31', grades)>0          -- 年级过滤；grades 无索引，勿用 '%31%'（会多匹配到 131/310…）
  AND is_del=0
  AND user_id IN (
    SELECT user_id FROM student_dw_data.dws_fuwu_clazz_user_subject_<n>
    WHERE school_year_id=2026 AND school_term_id='Q' AND FIND_IN_SET('31', grades)>0 AND is_del=1)
```

- 表上索引只有 `PRIMARY(id)`、`idx_user_clazz(user_id,clazz_number)`、`idx_user_year_term(user_id,school_year_id,school_term_id)`；**`grades`/`year`+`term` 单独过滤走全表扫**（`EXPLAIN` type=ALL），单片约 5~10s，16 片总量可控。要更省可只跑有问题的年级/产品切片。
- 实测（2026-10-16，**高一 grade=31 + 2026Q**）：16 片 union 后 **272 个班**（含已知的 4 个 `539048464767006720 / 539048466379716608 / 539048467904346112 / 539048474959165440`）。为超集，非逐条确诊。
- 用 CLI：`cd ~/.local/mcp-servers && ./mcpcli.py mysql_query mysql_query -k fmt=csv -k cluster_id=336 -k db_name=student_dw_data -k env=prod -k "sql=<上面 SQL 换分片号>"`。

## 验证

- 源表 `is_del=0` 去重科目数 == 用户反馈的「实际」；且索引 `studyingSubjectCnt` 比它大 → 结论成立。
- 「索引文档 updateTime 很新」**不能**证明 `studyingSubject` 是新的：部分更新（如员工/销售归属变更）也会刷新 `updateTime`，但不一定重写 `studyingSubject`。
- 回写手段（**重算索引文档，源表不用补**）：大班花名册索引走 manual 接口
  `POST /gps/manual/back/largeSubClazz`（`GpsManualController#backLargeSubClazz` → `AdsSubclazzUserBackService#dealClazz`，按 `clazzNumber` 逐学员重算并 `batchUpsert` 到 `ads_large_subclazz_user_index`；参与字段由 Apollo `student-data/application` `ads.back.subclazz.user.fieldNames` ∩ `ads.large.subclazz.user.fieldNames` 决定，PROD 两份都含 `studyingSubject`/`studyingSubjectCnt`）。body：`{"clazzNumbers":[<clazzNumber>...]}`。
  在读科目表本身的重建入口（源表兜底）：大班 XXL-Job `BackClazzUserSubjectHandler`、`backStudyingSubjectHandler`；小班 `POST /gps/manual/back/smallClazzUser/subject`。
  ⚠️ 索引重算只修「当前值」，**不修写入链路**；若根因是链路漏刷（见下），回溯后仍会在下次调班/转班复发。
