# 报名/下单弹「课程时间冲突」——判真假的排查链

> 适用症状：C 端报名/支付时弹「下单课程时间冲突」，用户认为两个班时段不冲突。软提示，点「立即报名」仍会生成待支付订单。

## 结论先行

弹窗名单 = 校验算出的**对手班级号**对应班名。冲突是**课节级**（每节课的 begin/end 时间戳两两比对），不是页面展示的班级固定时段；「班级时段不冲突」≠「课节不冲突」，收心课/点睛课/调课补课这类特殊课节最容易撞。

## 校验链路（两条，个人链接走 ①）

### ① 个人链接报名：promotion → 老 course（本次案例路径）

```
C端报名 → promotion PersonalLinkDomainService#commodityGroupCheck
  → commodityGroupCheckForActivity：重复校验(REPEAT) → 分层考试校验(HAS_EXAM)
  → choiceProductList 非空且 !force 时 → getTimeConflictClazzNumbers
  → 老 course POST /feignCourse/lecturesTimeConflict
      LecturesTimeConflictAtProductSelectDto{userId, clazzNumber|activityNumber, productsInCart[{type,productNumber}]}
      （type：PRICED=2 单课，CLAZZ_SET=23 联报；promotion ProductTypeEnum 同码）
  → 返回 conflict=[班号...] → getConflictClazzMsgList 查班名 → ChangeCommodityErrorTypeEnum.TIME_CONFLICT 弹窗
```

老 course 内部算法（`com.gaotu.service.compositeservice.impl.CourseServiceImpl`，course-service jar，jad 可验）：
- select 侧 = clazzNumber/activityNumber（activity 会展开 clazz_set 全部成员班）
- aim 侧 = productsInCart 展开班 + **用户已购班级**（getAimClazzNumbers：order listbyExample 权益）
- 课节双指针比对：`aBegin <= bEnd && aEnd >= bBegin`（**端点相等也算冲突**）；跳过 PARENT_MEETING 类型课节
- **类直播/拟直播不跳过**：过滤只在 getLectureMap 一处、只排 `type==PARENT_MEETING`；类直播是课节交付形态属性（liveType/property=2，非课节 type），照常参与比对——两节类直播课节时间一致必然报冲突（2026-11-26 jad course-service-2.5.70 验证）
- 返回 conflictMap.values() = **aim 侧撞车的班号**（弹窗列的是这些班名，不是 select 侧）

### ② 购物车/订单侧（预报名等场景，见 2026-11-02 案例）

- cart `CartAggregatorServiceImpl#validateProductTimeConflict`：购物车班(1) 内部相邻比对 + 购物车班(1) vs 已购班(2)，跳过已结束课节；开关 `cart.course.time.conflict.skip`
- order `BatchCanCreateOrderCmdExe#getTimeConflictClazzNumbers`（`order.time.conflict.valid.swtich`，默认 true）→ 同样转调老 course `feignCourse/lecturesTimeConflict`

## 判真假步骤

1. **拿班号**：弹窗班名 → `course_center.clazz` 按 `biz_number`/`name` 反查 number。
2. **拉课节**：`course_center.clazz_lesson`（`clazz_number IN (...) AND isdel=0 ORDER BY begin_time`）——重点看**特殊课节**：收心课、期中/期末点睛、拓展精讲、调课补课（节假日把常规课挪位）。
3. **复算**：按 `aBegin <= bEnd && aEnd >= bBegin` 两两比对 select×aim；端点相等即冲突。
4. **确认订单/用户**：`gaotu.order_info`（cluster 298，`user_id` 有索引）看待支付单构成；userId 用 student-center acl 桥 `StudentMdmAclService#getStudentInfoDetail(手机号,1,n)` 反查。
5. **判责**：
   - 课节真撞 → 排课数据问题（跨科目/跨联报包排了同一时段），转排课调整；弹窗行为正确。
   - 课节不撞仍弹 → 查 course 老服务缓存/`RawLectureDTO` 时间戳与 DB 是否一致（arthas `mapByClazz` 对比），再查是否命中"端点相等"或 PARENT_MEETING 之外的特殊 type。

## 取数/复现入口

- prod 老 course 无 acl 桥（网关 `/internal/course/**` 要 CAS）：arthas 进 `gaotu_course` pod，`vmtool` 调 `CourseFeignServiceImpl#lecturesTimeConflictAtProductSelect`（DTO 用反射构造，Long 传参用 `new java.lang.Long(<n>L)`、setter 形参是包装类 `@java.lang.Long@class`）。
- prod cart acl 桥返回"ACL服务对比功能未启用"，不可用；cart 视图课节可 arthas 调 `com.gaotu.facade.clazz.ClazzFacadeImpl#mapByClazz` 对比。
