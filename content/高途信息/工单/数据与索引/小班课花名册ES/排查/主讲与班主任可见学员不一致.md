# 小班课花名册 ES · 同班主讲与班主任可见学员不一致

> **只解决**：同一个小班班级，主讲看到一批学员、班主任只看到其中一部分（业务表述「班主任看不到学员」/「只能看到某科数据」）。
> 班级完全搜不到、字段缺失走 [`班级搜不到或花名册字段缺失.md`](班级搜不到或花名册字段缺失.md)，与本文无关。

## 判定入口

拿到「看不到」的账号后，先分清两件事，别急着当数据丢失：

1. 登录人是谁、是哪个角色 —— 主讲（`mainTeacherAccountIds`）还是班主任（`assistantAccountId`）。
2. 看的是哪个 tab —— 花名册（`identification=smallClazzRoster`）还是续班服务（`microContinuationService`）。两个 tab 权限过滤器相同。

## 核心口径（先确认是不是这类）

小班花名册/续班服务的权限过滤在 `SmallClazzUserPermissionFilterService#build`
（`student-center-service/.../domain/service/es/filter/special/small/SmallClazzUserPermissionFilterService.java:56`）：

- 过滤条件 = **OR**：ES 文档里 `accountFieldNames` 任一字段 ∈ {登录 accountId + 兼职 accountId}。
- `accountFieldNames` 在 PROD `es_query_config`（type=permission，command=account）里配置，实测含 **`assistantAccountId` + `mainTeacherAccountIds`**（另 postTag 走 `mainTeacherMainPostTag` 通配）。即：`accountId ∈ assistantAccountId` **或** `accountId ∈ mainTeacherAccountIds` 可见。

字段语义（子需求2「小班续班适配主讲」口径，2026-09 已定、上线准备中，见 `需求/【A-续班-20260902】续班优化`）：

- `mainTeacherAccountIds` 是**班级级**派生 → 主讲（含双角色）看到**整个班级下所有辅导班**的学员。
- `assistantAccountId` 是**辅导班级**单值 → 班主任只看到**自己辅导班**的学员。

因此「同一个班，主讲看到的比班主任多」在班级被拆成多个辅导班时（如 青藤9阶各「善思班-N/智源班」各有自己的班主任）是**设计口径**，不是数据丢失。9年级这类多辅导班拆分明显，故先被业务发现。

## 排查

1. 定位班级号：学员在 `ads_small_clazz_user`（物理 `ads_small_clazz_user_v1`，PROD `es-cn-4xl3gu6ls0007l185`）里按 userId/`clazzName` 查对应 `clazzNumber`。ES 只读走 `es-apply` skill 的 `es_workorder.py search`。
2. 核对源数据：确认目标学员的 `assistantAccountId`、`mainTeacherAccountIds` 是否分别等于该班主任/主讲 accountId。相等却「看不到」才可能是权限 bug。
3. 页面级复现（同一份数据分别以两个账号调，最能定位）：按 `microClazzRoster/continuationService.md` 的三步——`cosplay_login` 成当事人 → 带 `b_client: EES` 直调 → 用完 `cosplay_logout`：
   - 续班服务：`POST <fuwuBase>/bgwApi/component/student-center/roster/small/renewal/page`
   - 花名册：`POST <fuwuBase>/bgwApi/component/student-center/smallClazz/clazzStudentList`
   - 入参要点：`identification` 对应 tab；`filter.clazzNumber[]`（字符串）、`filter.clazzStudentStatus`（如 `["1","3"]` 在班/在班调课，字符串数组）、续班服务还必给 `filter.smallRenewalRoundFilter[1]`（整数，一轮）。**`b_client` 按页面所属端**（EES 页 = `EES`），否则报 `{"code":42,"msg":"调用staff失败"}`。
4. 比对两次返回的 `userId` 集合：主讲 = 全班各辅导班并集；班主任 = 仅 `assistantAccountId=自己` 的部分。

## 另一个更常见的来源：班级筛选范围过大（2026-10-16 实测）

业务反馈的「同一个人学员状态不一致」，多数是**筛选条件**问题，不是数据字段错：

- 一个续班计划下约 **300 个班级**，页面「班级」选择器可全选/多选（`showSelectAll`、`maxTagCount=1` → UI 只显示「青… +99」）。全选后，**同一学员在多个班级/辅导班的新旧记录会同时出现**（转班/调课后：旧辅导班=退班(调班)、新辅导班=在班(调课)），看起来就是「同一人状态不一致」。缩小班级范围即对齐。
- 同名班级会加剧：同一 `courseNumber` 下可能有多个**班级名相同**的 `clazzNumber`（如 `562246331247640580` 与 `562246331247640582` 都叫「【2026/秋】青藤9阶思维（苏科版）善思班」），选中它们会同时命中新旧两条。
- **学员状态（`clazzStudentStatus`）是按「班级×学员」文档存的**，同一条文档任何角色看到的值都一样（后端 `SmallClazzService#setClazzStudentStatus` = ES 原始 `clazzStudentStatus`(0/1) + `changeClazzStatus`×2 → 0退班/1在班/2退班(调班)/3在班(调课)）。**不存在"同一条记录两种角色状态不同"**，差异只来自各自落到的 clazzNumber 不同。
- 复核判据：把同一批 clazzNumber 分别以两个账号调，若同一 `(userId, clazzNumber)` 的状态逐条一致 → 不是状态字段 bug，是范围/口径。

## 验证

- **属口径**：班主任返回的每个学员，其 `assistantAccountId` 都等于班主任自己，且主讲返回包含这些；主讲多出的学员其 `assistantAccountId` 为**别的**班主任。→ 差异来自权限维度，不是丢失。
- **属数据/权限 bug**：存在学员 `assistantAccountId=该班主任` 却不在班主任结果里（或主讲也不在），或该学员在源表属于其辅导班但 ES 值陈旧（常见于转班/调课后，参见 `续班与业绩/业绩归因`「可续标记锁在旧辅导班」同源问题）。此时按班级回填 `ads_small_clazz_user`。
- 只看到「主讲能看、班主任不能看」不能判定为 bug —— 需先排除上面第 1 条口径差异。
