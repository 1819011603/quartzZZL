# GPS1v1首call任务 · 天工里没有业务表，怎么同步、找谁

> **只解决**：某张 MySQL 业务表在大数据/天工没有对应 ODS 表，或新表要加同步。
> 「1v1首call任务为什么没生成」走 [`1v1首call任务没生成或查不到.md`](1v1首call任务没生成或查不到.md)。

## 天工 ODS 表怎么来的：两种同步

天工 ODS 层（库 `data_lake_ods`，Iceberg 外表、全量表）的表**不是一种机制**，先判清楚走哪条：

1. **天工「数据同步(DS)」任务**（`taskType=1`）—— 经典 DataX/Flink JDBC 整表同步。任务名一般 `sync_*`，`ds-get <taskId>` 能读到 `sourceTableConfig`/`targetTableConfig`。
2. **数据湖 Iceberg「多表同步」**（本文重点）—— 由一个**独立于天工的"多表同步"项目**统管一批 `gaotu.*` 表实时同步到 `data_lake_ods.ods_*_rt`；天工侧只放一个 **Shell 任务**（`taskType=5`）来**触发/对账**，脚本就一行：
   ```sh
   java -jar /apps/scripts/check-iceberg.jar --projectId 2143324536142675968 --taskId <uuid> -dbTableName gaotu.<源表名>
   ```
   - `projectId 2143324536142675968` 是**数据湖多表同步项目 id**（**不是天工项目**，天工 `listProjects`/`ls` 查不到；同一个多表任务里挂着十几张 `gaotu.*` 表）。
   - `taskId <uuid>` 是那个多表同步任务；`-dbTableName` 指定本 Shell 任务负责校验/触发的源表。

## 怎么判某张 ODS 表走哪条

1. 天工搜表：`tiangong_cli.py table <表名>` → 拿 tableId → `table-detail <tableId>` 看 DDL / 类型（Iceberg 外表、`_rt` 后缀的多半是第 2 种）。
2. 天工搜同名任务：`search <表名> 270`（`data_lake_ods` 层项目 id=270）→ 命中一个 `taskType=5` 的 Shell 任务就是第 2 种。
3. 读它的脚本：`POST /api/dp/dataDevelop/getShell` form `taskId=<taskId>` → 看是不是 `check-iceberg.jar ... -dbTableName <源表>`；再看最近执行的 `stage-log`（`periods <270> <nezhaId>` → `executions` → `execution-detail` → `stage-log`），返回的 `DescribeTaskTableMetricOverview…` 里会列出该项目名下所有同步的 `DatabaseName/TableName → TargetTableName`。

## 样例：GPS 1v1 首call 表

| 项 | 老表（高中首call） | 新表（GPS 1v1） |
|---|---|---|
| 源（MySQL） | `gaotu.first_call_task` | `gaotu.first_call_task_1v1` |
| 目标（ODS） | `data_lake_ods.ods_gaotu_first_call_task_rt`（tableId 30940） | `data_lake_ods.ods_gaotu_first_call_task_1v1_rt`（tableId 37599） |
| 天工触发任务 | `ods_gaotu_first_call_task_rt`（taskId 38534 / nezhaId 47711） | `ods_gaotu_first_call_task_1v1_rt`（taskId 52779 / nezhaId 72911） |
| Shell | 同款 `check-iceberg.jar --projectId 2143324536142675968 --taskId g73002ad6-337a-41c6-8b8d-6a883037f3be -dbTableName gaotu.first_call_task` | 同款，`-dbTableName gaotu.first_call_task_1v1` |

## 要加一张新表的同步，怎么做

1. **建目标 Iceberg ODS 表**（DDL 按**新源表**结构，别照抄别的表——同名前缀表字段可能不同，如 1v1 表无 `subclazz_number`、多 `sub_teach_product_number`）。
2. **在数据湖多表同步项目 `2143324536142675968` 里给源表加一路同步**（定向到上面那张目标表）。
3. **天工侧照老表建同款 Shell 任务**：`java -jar /apps/scripts/check-iceberg.jar --projectId 2143324536142675968 --taskId <uuid> -dbTableName <新库.表>`，再配调度 + 依赖。

## 找谁

- **数据湖 ODS 层 / 多表同步：卫华飞**（`data_lake_ods` 这批 `ods_gaotu_*_rt` 表的创建人；第 2 种同步的项目和表清单都在数据湖那套，天工改不了）。
- 天工侧的 Shell 触发任务可自行照建（用 `tiangong_cli.py new-task/ds-save/publish`，见 `tiangong-datawork` skill）。

## 验证

- 表 `table-detail` 的 DDL 列与源表逐列对得上（列名/顺序/类型）。
- 目标表有数据：元数据平台 `preview <tableId>` 有样本；或看天工 Shell 任务最近 `stage-log` 的 `exit_code: 0`。
- ⚠️ 新建后到出数有延迟（Shell 任务是按周期跑的，如整点/每 5 分钟）；`preview` 空先看任务是否已跑过那个周期（`periods` 里 `status` / `startTime`），别急着说"没同步"。
