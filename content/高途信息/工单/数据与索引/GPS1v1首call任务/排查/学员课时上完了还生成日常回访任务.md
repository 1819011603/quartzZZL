# 学员课时上完了还生成日常回访任务（剩余课时多算）

只解决：老链路日常回访（辅导班维度，`first_call_task`）对「已退款的报名」课时多算，导致真实剩余课时为 0 的学员仍每批次生成任务。新链路（容器，`first_call_task_1v1`）课时口径不同，见文末。

## 排查路径

1. **拿生成时的计算值**：SLS `serviceName=student-data, logType=app`，queryStr `"<userId>" AND messages: 学生未课消课时数`。日志行 `hour: X, clazzNumbers: [...]` 即老链路当时的剩余课时（>0 才生成）。
2. **逐班对课时**（cluster `gaotu-course-prod` / 库 `course_center`）：
   ```sql
   SELECT clazz_number, total_hour, cost_hour, frozen_hour, status, isdel
   FROM course_center.clazz_hour WHERE user_id = <userId>;
   ```
   - 老链路口径 = Σ(`total_hour − cost_hour`)，只统计该班主任名下有效 1v1 辅导班。
   - **退款不回减 total_hour，而是进 `frozen_hour`（冻结）**；真实剩余 = `total_hour − cost_hour − frozen_hour`（= course-center 返回的 `availableHour`）。
3. **定性判据**：Σ(total−cost) > 0 但 Σ(total−cost−frozen) ≤ 0 → 属本问题（退款冻结课时虚增）。退款凭证：`course_center.clazz_hour_order_after_sale_record`（按 `clazz_hour_number` 查，`after_sale_type=2` 退课时）。

## 根因位置

`student-data` `TaskBizCommonQueryService#calculateUserTotalAvailableHourBySubclazz`：取 course-center `/feign/clazzHour/getClazzHourDetailDirectly` 返回行的 `totalHour − costHour` 求和，**未减 frozenHour / 未用 availableHour**。调用方：`AbstractScheduledTaskJob#processAccount`（日常回访老链路 + 日常家长会共用，改动需评估家长会）。

## 常见误判

- 只看 `total/cost` 会得出「还有剩余课时、生成正常」的结论——漏看 `frozen_hour`（2026-11-12 首次排查即漏于此）。
- 「同班报名两次、退掉一次」的两次报名在 `clazz_hour_order_detail` 是两行订单；退款行 `status=3`，但课时仍留在 `clazz_hour.total_hour` 里。

## 新链路（容器）对照

新链路 `DailyVisit1v1ScheduleJob` → `UserContainerHourPackageQueryService`：按 GPS 课时包（非 clazz_hour）且只统计 `status=2(正常)` 的包，退款包非正常状态被排除，口径不含冻结虚增问题。
