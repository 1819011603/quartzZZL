# 触达通知 · 没收到企微进班提醒

> **只解决**：顾问/二讲（员工）反馈收不到企微「进班提醒」类通知（文案形如「【进班提醒】18x****xxx学员报名了xx班级，已分配到您的辅导班，请跟进~」）。
> 企微侧边栏问题走 [`../../企微侧边栏/`](../../企微侧边栏/README.md)，个人中心绑定企微不显示走 [`../../个人中心企微/`](../../个人中心企微/README.md)，与本文无关。

## 判定入口

先拿到两件事，再分流：

1. **接收人是员工**：`gaotu.employee` 按 email_prefix 查 accountId（同 prefix 多行属正常，accountId 相同）。
2. **是哪条链路的「进班提醒」**（文案能区分）：
   - 「已分配到您的辅导班，请跟进~」+ CallPage 链接 → **线索分配链路**（主链路，量大）：leads-management-assign 分配成功 → `ss-official-wk-agent` 发企微应用消息（touser=企微账号）。
   - 「服务单已分配给您，请跟进」→ reach-service 场景 13「二讲通知-进班提醒」（ReachScene 13，瓦力云 WK 通道，量极少）。
   - 灵犀文案（分班中心 clazz-distribution-server，`enter.clazz.remind.desc`，百灵 channel=32）——仅灰度内类目触发，PROD 灰度 `enter.clazz.remind.config` 目前只有类目 `810525` + `courseTypes ["40"]`。

## 排查

核心判据：**分配没发生，消息就不会发**。员工账号正常（employee.status=1）时，按顺序查：

1. **该人是否出现在任何链路日志里**（SLS 全量日志，`logType=app`，7 天窗）：
   ```
   queryStr: <emailPrefix>          # 如 yuanxinyi02
   queryStr: messages: <emailPrefix>
   ```
   前缀 token 唯一，跨服务命中即顺藤摸瓜；完全零命中 → 大概率没配进分配规则（下一步确认）。
2. **分配校验失败证据**（leads-management-assign 的两条校验日志）：
   ```
   queryStr: "<emailPrefix>" AND "failItem"      # ItemValidatorManager 批量名单
   queryStr: "<emailPrefix>" AND "applyValidate" # AbstractStrategy 单人失败原因
   ```
   failReason 对照：`分配规则达到上限`（assignCount==ceilingCount）、`顾问已禁用`（注意：item 的 isEnable=1 也可能报禁用，禁用是分配系统侧顾问状态，不是员工表 status）、`顾问已离职`、`没有服务范围`。日志里 item 形如 `AssignItemEntity(ruleId=..., groupId=..., itemId=..., planId=..., accountId=..., accountDomain=..., assignCount=..., ceilingCount=...)`。
3. **完全零命中**（不在 failItem 也不在 applyValidate）→ 该人不在分配规则成员里或所在规则无线索流量，用下面「分配配置核查」确认。
4. **分配配置核查**（leads B端接口，网关路由 `/leadsManagement` → leads-management-customer，经 baijia 代理带 Cookie）：
   - 规则详情（含全部成员 count/ceilingCount/isEnable/priority）：
     `GET https://fuwu.baijia.com/bgwApi/leadsManagement/assign/rule/v2/detail?ruleId=<ruleId>`
   - 按人查是否在规则：`POST .../assign/rule/v2/searchAdviserByRuleId`，body `{"ruleId":206875,"name":"袁欣怡"}`（返回 `[]` 即不在）。
   - 规则总量消耗：`GET .../assign/rule/v2/getRulePlanOverView?ruleId=<ruleId>`（assignCount/ceilingCount/adviserCount/assignRatio）。
   - 失败原因枚举 `AssignFailReasonEnum`（leads-management-api jar）：`顾问已禁用=NO_ENABLE`（成员项 isEnable=0）、`分配规则达到上限=ASSIGN_CEILING`（count≥ceilingCount）、`顾问已离职=LEAVE_OFFICE`、`没有服务范围=NO_SERVICE_RANGE`、`不在接量时间范围=NO_PLAN`。CEILING_RATIO 模式下成员到量会自动 isEnable=0（满员自动禁用），所以「满员+禁用」成对出现属预期。
5. ** reach-service 场景 13 侧**（文案是「服务单已分配给您」才走这）：
   - 发送日志：`queryStr: "发送企微消息参数为param"`（WaLiYunWkNoticeTaskReacher，bizMap 含 `email_prefix_map` 候选池）；接收人过滤在 teacherTypeHandler（目标条件 type=15 老师角色）。
   - 触达明细接口/数据源见 [`references/reach-service调用入口与数据源.md`](references/reach-service调用入口与数据源.md)。
6. **分班中心灵犀路径**（如涉及）：PROD Apollo `clazz-distribution-server` key `enter.clazz.remind.config` 看灰度类目；发送日志 `send enter clazz remind person:<emailPrefix>`。

## 验证

- failItem/applyValidate 命中该人 → 分配侧实锤，处置走分配配置（调 ceilingCount / 恢复顾问启用 / 补配成员）。
- 发送链路（wk-agent「Post to Api send application message info」PARAM 里 touser=该人企微账号）命中 → 分配成功且已发，若人还说没收到再查企微侧（免打扰/账号主体）。
- 「日志没搜到」≠「没发生」：SLS `scanLimit` 上限 100、limit 100，高流量服务只覆盖分钟级窗口，零命中要换 `queryStr AND` 组合收窄再下结论。
