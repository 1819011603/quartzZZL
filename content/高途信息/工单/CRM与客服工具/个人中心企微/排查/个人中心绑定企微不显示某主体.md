# 个人中心企微 · 个人中心-绑定企微不显示某主体

> **只解决**：微信助手/个人中心"绑定企微"里整条主体（或其企微、二维码）不出现。
> 字段回显、绑定状态不对走其它文件；本文只针对"主体/企微整条缺失、没有弹码"。
> 完整接口清单、链路、配置项与关键代码见 [`references/个人中心企微接口与链路.md`](references/个人中心企微接口与链路.md)。

## 判定入口

- 症状：个人中心-绑定企微的主体/企微列表缺某主体，或该主体"没有弹码"。
- 关键接口：teacher-basic `POST /personCenter/qiweiOptionList`（"企微配置选项列表"），过滤逻辑在 `TeacherServiceImpl#qiweiOptionList`。
- 先排除"压根没绑定/没上线"：调 `POST /crmApp/scrm/wechat/account/multiInfo`，能看到该主体 corpId 的企微才算真的绑定过。
- ⚠️ 别把 `crmApp multiInfo`（号列表）和 teacher-basic `qiweiOptionList`（绑定企微主体/弹码）当成同一个接口，前者通常正常、后者才是"不显示/没弹码"的落点。

## 排查

1. 代课当事人后实调 `invoke_http(project="teacher-basic", route="/teacher-basic", path="/personCenter/qiweiOptionList", traffic_env="prod")`，看返回里有没有目标主体、`qiweiQrCode` 是否为空（`qiweiQrCode` 就是"弹码"）。
2. 白名单：Apollo `teacher-basic.gaotu100.com` / PROD / `waliyun.corp.idName.map`，其 keySet = 支持的主体集合（`WaliyunService#getSupportedCorpIds`）。缺目标主体 → 整条被过滤不显示。
3. corpId 口径（决定白名单 key 写哪种值）：
   - `WaliyunService#getQiweiIdsByLogicIds` 调瓦力云 `/open/api/wk/queryRobotInfo`；瓦力云以 `um.storm_sun_device` 的逻辑主体 corpId 为基，用 `CORP_ID_ENCRYPT_MAP`（Apollo `tech-yingxiao.ss-lib-constant` 的 `ss.lib.constant.corp.id.hook.official.map`）转成企微 corpid（`ww...`/`wxe...`）返回。
   - teacher-basic 再用 `waliyun.corpID.decode.map` 把少数企微 corpid 解码回逻辑 id（如 `wxe9347c2f779b96ca`→`1970324992993271`）。
   - 因此白名单 key 要写"最终 corpId"：多数主体是企微 corpid（`ww...`），高途/途途等被解码的写逻辑 id（`1970...`）。逻辑 id ↔ 企微 corpid 对照见 `ss.lib.constant.corp.id.hook.official.map`。
4. 二维码/成员：`TeacherServiceImpl#relation2Option` 对每个候选调瓦力云 `getQiweiInfoByCorpAndUser(corpId, wechatId)`（→ `/open/api/wk/official/getUserInfo`，底层走企微官方 API）取 `qiweiQrCode`；瓦力云查不到该主体/成员时返回 null，该条被丢弃 → "没有弹码"。
5. **直连瓦力云确认主体是否真的接入**（host `https://ss-waliyun.umeng100.com`；token 用 teacher-basic Apollo `waliyun.wechat.clientId`/`clientSecret`）——白名单只是必要条件，这步才是"选项出不出来的真正原因"：
   - 取 token：`POST /open/api/oauth/token?grant_type=client_credentials&scope=all`，头 `Authorization: <clientId>:<clientSecret>` → `data.access_token`/`data.token_type`；
   - 查机器人：`POST /open/api/wk/queryRobotInfo`，头 `Authorization: <token_type> <access_token>`，body `{"logicIdList":[<逻辑id>]}` → 正常返回 `corpId`(企微 corpid)/`corpName`/`acctId`（读本地 um 表，一般 OK）；
   - 查成员：`POST /open/api/wk/official/getUserInfo` body `{"corpId":"<企微 corpid>","userIdList":["<acctId>"]}` → **`code=48002 api forbidden` = 该主体未把自建应用（微信助手）加入企微后台"客户-可调用接口的应用"、未授权"外部联系人"权限**（加白名单也救不了；需企微管理员在"客户"页授权后重试）；返回带 `qrCode` 才算接入。

## 验证

- 配置发布后**重调 `qiweiOptionList`**，返回里出现目标主体且 `qiweiQrCode` 非空，才算生效。
- 仅接口 200、Apollo 配置项已存在，都不等于该主体已显示。
- 若加了白名单仍无码，查瓦力云侧是否已接入该主体（`getQiweiInfoByCorpAndUser` 有无数据）。
