## 结论

非数据/权限缺陷，是**侧边栏 webview 会话残留 + 登录识别 cookie 优先**共同导致：

- 机器人宝体C01 跑在虚拟 windows 微信助手上，李月艳01 之前操作时（CAS 扫码）留下的登录态没被清理，杨登峰继承了这个 webview 会话；
- `WkAuthController#account` 只在 cookie 账号被 CAS 标记（status==1，离职/停用）时才走企微 OAuth code 重新识别，
  liyueyan01 在职 status=0 → 永远复用 cookie 里的 239371，code（会解析出现归属人杨登峰）从不被消费；
- 写跟进落库创建人取登录态（`LoginInfoUtils.getLoginUser().getAccountId()`）→ 动态显示李月艳01。

瓦力云归属、avatarMap、robotInfo 映射均已排除，不是问题来源。

**补充（2026-11-16 下午）：邮箱配置也核实了——即使清 cookie 走 OAuth code，当前配置下也解析不出任何账号**：
宝体C01 的企微成员（corp `wxe9347c2f779b96ca`，userId=`13266517974`，手机号形态）邮箱是占位邮箱
`13266517974@baijia.com`，CAS `getAccountByName("13266517974")` 为空 → userId 分支失败 → 邮箱前缀

是因为她走的是 CAS 扫码登录（不经过 code 解析）。**要让重登后 code 分支能解析出杨登峰，需先把企微通讯录里
该成员的邮箱改成 `yangdengfeng@gaotu.cn`**（linkup prod `wk.queryAccount.emailFirst=true`，
userId 非纯英文 → userId 查 CAS 失败后按邮箱前缀匹配 CAS）。
