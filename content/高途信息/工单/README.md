# 线上问题案例索引

这里保存高途线上问题的当前案例快照，与 `需求/` 分开。

收录范围不限于正式工单：飞书反馈、群里随口一问、自己验证时踩到的坑都收，判据是“以后再遇到时这条记录会不会改变排查判断”。目录名 `工单/` 是历史命名，不是收录门槛。目录结构是 `<业务域>/<模块>/README.md`：业务域是稳定的大类，模块是具体功能；每个模块只有一份 `README.md`，同一根因更新原案例，只有独立根因才新增日期小节。

## 使用规则

- 收到“查问题、查工单、帮我看看线上反馈、这个之前遇到过吗”时，先使用全局 `gaotu-ticket-triage` skill 搜索本目录。
- 检索直接全库搜关键词，不要先靠目录名逐层翻；业务域只用于归位和缩小范围，不是检索入口。
- 按原始报错、字段名、接口名、userId、班级号、traceId 等高区分度信息检索；命中记录只作线索，当前对象、现象和证据链一致后才能复用结论。
- 只有用户明确同意保存或更新时才写入。写前先检查同模块、同现象、关键 ID 和根因，避免重复案例。
- 每条记录只保留当前可确认的现象、证据、结论和处置状态；被推翻的假设、失败尝试、完整聊天和失效下一步直接删除。
- 模块特有的排查步骤、SQL、回溯命令放该模块 `Scripts/README.md`；案例 README 只写「发生过什么」，Scripts 写「怎么做」，两边不重复。
- 跨业务通用能力（`traceid-debug`、`mysql-query`、`pod-terminal`、`xjob-admin` 等）仍在全局 skill，手册里引用名字即可，不要复制其内容。
- 新独立案例按 `gaotu-ticket-triage/references/record-format.md` 写入对应模块 README。写完同步所属业务域 README 和本索引。
