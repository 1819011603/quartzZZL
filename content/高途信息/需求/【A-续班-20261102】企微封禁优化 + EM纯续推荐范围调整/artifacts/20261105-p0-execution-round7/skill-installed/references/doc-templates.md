# 简洁用例与执行记录模板

主流程见 [SKILL.md](../SKILL.md)。适用于生成用例、已有 case 重写、飞书 P0 和执行记录。采用测试侧简洁表达：正文可直接执行判断，证据集中且可追溯。

## 范围与证据组织

按主入口查清需求、已有用例及确认规则，保留原需求点与 case 的映射。多个小场景可合并一张卡，但正向、反向、边界不能因精简消失；不为对齐数量抄录 P1/P2 或范围外业务。已有授权内自主准备必要 TEST 数据，准备成功不等于被测行为通过；具体权限仍按主入口和当前会话。

正文只保留必要前置、简短操作、关键预期及已有实际结果。原始请求/响应、SQL、DB/ES 全量值、trace、日志、详细推导和造数过程集中放附录或证据包，每卡引用证据编号/链接。共用环境、对象和原值可用一张简短对应表，各卡准确引用对应行，不重复粘贴背景或强制填一套无关字段。

## P0 信息完整性清单

- **真实对象**：涉及选择班级、学员或消息目标时，正文写明班级 bizId、班级名称和学员 ID；多班/多人/未选对照用简洁对应关系标明谁被操作、谁应保持。需要区分权限或好友时补登录身份/角色及必要关系。姓名源值为空可直接按 ID 定位，不编造姓名。
- **编号语义**：从实际页面/接口及数据映射核实 bizId 是哪一个业务编号，与数据库主键、班级编码、商品/课程/辅导班编号分别标注；不能靠都叫 ID 就混用。接口没有同名字段时写实际业务字段与映射依据，无法确认则标“bizId 未核实”，不能把主键补上充数。
- **关键条件**：保留能解释结果的在读/已购、主从、好友、状态、时间等条件。规则筛选得到的范围用一句话说明纳入和排除依据，不强写数学公式；详细筛选原件集中引用。
- **计算**：涉及金额、数量等计算时，保留实际输入值、规则或公式、简短代入过程及结果。影响结论的单位、时间边界、去重或取整口径按需说明；不得自编计算示例或省掉会改变结论的中间值。详细推导链接到证据区。
- **操作与结果**：短步骤写清动作及必要输入，预期与实际分别列。结果写关键业务值和证据引用，不写“正常/HTTP200”充当通过；未执行、失败、阻塞或未知保持真实状态。
- **版本与复用**：集中说明采样时间、环境、版本及观察层；每卡只标本次适用范围或例外。历史证据仅在版本、环境、对象、规则未变且原件完整时复用为明确子集，不能冒充本轮新执行；样本已购/已消费后写明顺序或重建前置。
- **边界与恢复**：仅记录本卡实际覆盖、未覆盖及必要恢复结论/引用；不把接口结果替代页面、局部替代整卡，也不因为提到消息目标而实际发消息。

## 简洁执行卡

```markdown
## CASE-xxx｜<行为>
**前置**：<必要环境/登录角色与规则条件>。<班级 bizId＋班名；学员 ID，选中/对照对应关系；需要时引用共用对象表>。
**操作**：1. <短动作与输入>。2. <核对/反向/恢复动作>。
**预期**：<关键业务结果；规则筛选的纳入和排除依据>。<涉及计算时：真实输入 → 规则/公式 → 简短代入 → 结果及必要单位/边界>。
**实际**：<已有结果、观察层、未测/阻塞项；必要恢复结论>。证据：<集中证据编号或链接>。
```

仅在多步实际结果不同、顺序影响结论时按步简短列出“预期/实际”；不要求每步重复环境、完整对象关系、原始响应和日志。非页面型或不涉及班级/学员的用例只填适用对象并说明不适用原因，不造 UI 路径。尚无真实样本的草案明确标缺；步骤和预期仍保留，不能宣称可直接现场执行。

## 集中证据区

按 case/证据编号提供可定位引用，包含必要的原值、输入和完整返回、时间/环境/版本、DB/ES 落值、trace 或页面记录、计算推导及恢复回读。共用原件只存一次，正文引用；凭据不落文档。单测、接口、任务终态、DB/ES、页面分别说明覆盖层，平台“通过”也须核原始证据才能复用。

## case-record.md 与 data-requirements.md

执行记录开头简述环境和实际覆盖，按上面简洁卡记录；信息完整性和实际验证结果分别统计，末尾集中列剩余缺口及临时状态。造数需求只列自主查找/准备后仍缺的必要前置：缺什么、已尝试范围、最小构建条件、怎样验和清理边界；不把可自行完成的准备转交用户。

## 交付自检

逐卡回读正文，确认对象可定位、动作可执行、预期与实际分开、真实输入可复算；班级 bizId/班名/学员 ID 未因精简遗漏，业务编号未混成主键。核对精简前后需求映射、正反/边界、未测与失败状态、证据引用均保留；打开集中证据确认版本/环境/对象/规则及原件可追溯。写飞书或平台后回读确认生效；没有平台写授权时不改原集。结构检查和语义走读不能冒充业务实际通过。
