# 主从续班计划「纯续」全量回归测试方案

> 适用需求：【A-续班-20261102】企微封禁优化 + EM纯续推荐范围调整（子项2 = 主从续班计划【纯续关联】）。
> 被测仓：cart（主）/ product-server（关联下发）/ order（已回滚，不在本方案被测范围）。
> 一句话：验证「主计划+有效从计划，只合并**纯续**」在**商品类型全覆盖**下，**预热（写）**与**实时计算（读）**结果无损、与单计划旧行为兼容、开关/缓存失效可控。

## 0. 术语与口径

- **计划形态 `type`**：`1`=大班计划，`2`=小班计划（cart `RenewalService` :395/:493/:1661）。主/从均可为大班或小班。
- **商品类型 `productType`**（推荐条目，`com.gaotu.clientv4.enums.ProductTypeEnums` / `small.context.ProductType`）：
  | code | 含义 | 归类 | 本需求处置 |
  |---|---|---|---|
  | 2 | 班级（大班课）`CLAZZ` | 班级类 | clazz 链路（查课程中心补全） |
  | 6004 | 教学产品-小班课 `NEW_SMALL_CLAZZ_PRODUCT` | 班级类 | clazz 链路 |
  | 51 | 组合商品 `COMBINE_PRODUCT` | 非班级类 | `convertCombineResultToDTO` 权威解析 |
  | 23 | 联报 `CLAZZ_SET` | 非班级类 | `convertClazzSetResultToDTO`；**联报计划(productType=23)专属 `processClazzSet`** |
  | 6003 | 1v1/1vN `SMALL_CLAZZ_PRODUCT` | 边界 | 非班级兜底/互斥，需确认是否出现在续班条目 |
  | 7001 / 50 / 券 | 课时包 / 实物 / 优惠券 | 边界 | 兼容兜底 `resolveFallbackEntryGrade`；通常不参与纯续 |
- **缓存键**：历史完整键 `renewal:preheat:{renewalNumber}:{userId}`（不带关联版本后缀）；值前缀 `@mergedRenewal@` 表示「主+全部有效从」合并纯续 map，TTL=`preheat.cache.time`（默认 26h）。
- **开关**：`renewal.pure.relation.enabled`（总开关，默认 true）、`renewal.pure.relation.cache.invalidate.enabled`（关联缓存版本隔离，默认 true）、`preheat.cache.enabled`（预热读写，默认 true）、`small.renewal.enabled`。

## 1. 被测改动面（对应 cart `origin/release..HEAD`）

1. **关联合并（推荐）**：主计划在线推荐合并「有效从计划」的纯续结果，只并纯续、不并扩科（`getRenewalDetail` :281-323；`RenewalRelatedResultMerger.merge`）。
2. **预热合并缓存（写）**：`preheat(userId, renewalNumber)` 把「主 + 全部有效从（含大小班）」纯续一次性算好成一份 `Map<前置课号, ClazzDetailDTO>`，写入口老 key，前缀 `@mergedRenewal@`（:1622-1655）。单计划纯续映射 `preheatSinglePlanPureMap`（大班 `coreHandle`；小班 `smallPlanPureMap`）。
3. **批量预热（计划级）**：xjob `RenewalJobHandler` → `preheatByRenewalNumber` → `preheatPlanUsers`（大班逐用户 `preheat`；小班先 `SmallRenewalPreheatService.preheatByRenewalNumber` 再逐用户 `preheat`）。
4. **在线读取（读）**：
   - 大班入口：`corePreheatCache` 命中且 `hasMergedRenewalCache` → 只算主计划（扩科/加购/年级/价格在线算），不再另算从计划。
   - 小班入口：`smallMergedCacheConsumed`（:286-299）+ `buildRelatedPureVOFromCache` 无损消费缓存里的从计划纯续。
5. **商品类型分派**：`splitPureEntriesByProductType`、`isClassProductType`（null/2/6004=班级类）、`resolveCachedPureEntry`/`resolveNonClassPureEntry`、`appendOtherEntries`、`processClazz`/`processClazzSet`；联报入口只「自身联报条目」走 `processClazzSet`（`53d1cbc1`）。
6. **缓存失效**：`RenewalRelationCacheService.getVersion`（版本+`:on:sale-v2`）、`invalidateUserPreheat`。

## 2. 触发入口（全部只读或 TEST 内可逆）

| 编号 | 入口 | 调用 | 作用 |
|---|---|---|---|
| E1 | xjob `RenewalJobHandler` | `execute("[\"<planNumber>\"]")`（空则全量计划） | **计划级**预热：该计划全部已付用户 `preheat(userId,plan)` |
| E2 | HTTP `GET /web/renewal/preheat` | `renewalNumber=&userId=` | **单用户（UserId）**预热 |
| E3 | HTTP `GET /web/renewal/cart` | `renewalNumber=&userId=`（`fromBCart=false`） | C端实时计算（**读**合并预热缓存） |
| E4 | HTTP `GET /web/renewal/operation/cart` | `renewalNumber=&userId=`（`fromBCart=true`） | B端实时计算（**跳过**预热，不读缓存） |
| E5 | HTTP `POST /web/renewal/productSelectData`、`POST /web/renewal/price` | 按页面入参 | 选品/价格（读缓存口径一致性，抽验） |
| E6 | Redis 直读 | `GET renewal:preheat:{plan}:{user}` | 校验写入值前缀/TTL/内容 |

## 3. 覆盖矩阵

### A. 计划形态组合（主 → 从）
- A1 单计划（无关联，回归基线）
- A2 大主 + 大从
- A3 大主 + 小从（核心：大小班混合）
- A4 小主 + 大从
- A5 小主 + 小从
- A6 一主多从（≥3 个从，大小班混排）
- A7 互为主从/环状（预热去重、不漏不重）
- A8 从计划中该学员无课（合并为空，不单独缓存）
- A9 从计划非「待开始/进行中」或已删/停售（应被过滤，不推荐）

### B. 商品类型（后置推荐条目，**要全**）
- B1 大班班级 2
- B2 小班班级 6004
- B3 组合 51
- B4 联报 23
- B5 同链接多类型混排（2+6004+51+23）
- B6 边界：6003 / 券 / 未知类型（兜底解析不 NPE、取不到年级则跳过不崩）

### C. 数据链路
- C1 计划级预热（E1）→ 全量已付用户写合并 map
- C2 单用户预热（E2）
- C3 实时计算命中预热缓存（E3，命中后只算主计划）
- C4 实时计算未命中（清 key / `preheat.cache.enabled=false` → 现算）
- C5 **无损对照**：同入参「命中缓存 vs 未命中现算」结果一致
- C6 B端 `fromBCart=true` 不读合并缓存、仍现算
- C7 MISS 不写缓存（只预热写）

### D. 缓存与开关
- D1 关联变更（增/删从计划）→ 版本变化 → 旧预热不命中
- D2 总开关 `renewal.pure.relation.enabled=false` → 只回单计划（不恢复已写关系）
- D3 `preheat.cache.enabled=false` → 全走实时计算
- D4 历史值兼容：无前缀单计划 map / `@mergedCart@` 历史整份结果 → 当未命中
- D5 换班/换年级 → `invalidateUserPreheat` 清键
- D6 TTL=26h、键无版本后缀（`getCacheKey` 契约不变）

## 5. 判据（通过标准）

1. **无损**：同一 `(renewalNumber, userId)`，`preheat.cache.enabled` 命中与未命中（或 E4 现算口径对齐）下，后置商品集合/年级/`signUp`/`allSignUp`/默认年级/排序一致（沿用 verify.md「未命中现算 vs 命中缓存」口径）。
2. **从计划不丢**：主+全部有效从的纯续条目都在；同年级同商品**只展示一次**。
3. **只并纯续**：扩科/加购仍为主计划自身逻辑，不被从计划污染（`recommendType` 过滤）。
4. **商品类型分派正确**：班级类(2/6004)走 clazz 链路；51/23/未知走类型分派；无 NPE、无「按班级回查非班级 SKU」。
5. **不误用**：B 端 `fromBCart=true` 不读合并缓存；MISS 不写。
6. **失效可控**：关联版本变化隔离旧预热；开关关闭可回退单计划。
7. **提速（非功能）**：命中缓存显著快于现算（历史实测 0.36~0.47s vs 0.94~3.81s）。
