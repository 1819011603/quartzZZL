1. **defaultdict**：`defaultdict` 是 `collections` 模块中的一个类，它是字典（`dict`）的一个子类。与普通的字典不同，`defaultdict` 在初始化时可以指定一个默认的数值类型，当访问不存在的键时，会自动创建该键，并将其对应的值初始化为指定的默认值。这样可以避免了在使用字典时频繁进行键的检查，提高了代码的简洁性和可读性。
    
2. **OrderedDict**：`OrderedDict` 也是 `collections` 模块中的一个类，它是一个有序字典，即在插入元素时会按照插入顺序进行排序，并且保持元素的顺序不变。与普通字典不同，`OrderedDict` 可以记录元素的插入顺序，因此在迭代时，其顺序是可以预测的。
    
3. **ChainMap**：`ChainMap` 是 `collections` 模块中的一个类，它提供了一个可以同时查找多个字典的方法。它将多个字典链在一起形成一个链表，并且在查找键值对时，会按照链表的顺序依次查找，直到找到对应的键值对或遍历完所有链表。
    
4. **Counter**：`Counter` 是 `collections` 模块中的一个类，它用于统计可迭代对象中各元素出现的次数，返回一个字典形式的计数结果。常用于统计词频、字符频率等。`Counter` 可以接受任何可迭代对象作为输入，包括列表、元组、字符串等。

Python2中使用**使用开放地址法解决冲突。**

CPython使用伪随机探测(pseudo-random probing)的[散列表](https://so.csdn.net/so/search?q=%E6%95%A3%E5%88%97%E8%A1%A8&spm=1001.2101.3001.7020)(hash table)作为字典的底层数据结构。由于这个实现细节，**只有可哈希的对象才能作为字典的键。**字典的三个基本操作（添加元素，获取元素和删除元素）的平均事件复杂度为O(1)。


在python中一个key-value是一个entry，

entry有三种状态。

1. Unused： me_key == me_value == NULL
    
    Unused是entry的初始状态，key和value都为NULL。插入元素时，Unused状态转换成Active状态。这是me_key为NULL的唯一情况。
    
2. Active： me_key != NULL and me_key != dummy 且 me_value != NULL
    
    插入元素后，entry就成了Active状态，这是me_value唯一不为NULL的情况，删除元素时Active状态刻转换成Dummy状态。
    
3. Dummy： me_key == dummy 且 me_value == NULL
    
    此处的dummy对象实际上一个PyStringObject对象，仅作为指示标志。Dummy状态的元素可以在插入元素的时候将它变成Active状态，但它不可能再变成Unused状态。
    

为什么entry有Dummy状态呢？这是因为采用开放寻址法中，遇到哈希冲突时会找到下一个合适的位置，例如某元素经过哈希计算应该插入到A处，但是此时A处有元素的，通过探测函数计算得到下一个位置B，仍然有元素，直到找到位置C为止，此时ABC构成了**探测链**，查找元素时如果hash值相同，那么也是顺着这条探测链不断往后找，当删除探测链中的某个元素时，比如B，如果直接把B从哈希表中移除，即变成Unused状态，那么C就不可能再找到了，因为AC之间出现了断裂的现象，正是如此才出现了第三种状态---Dummy，Dummy是一种类似的伪删除方式，保证探测链的连续性。


#### 伪随机探测

伪随机探测（pseudo-random probing）是一种解决哈希冲突的方法，通常用于实现哈希表。在这种方法中，冲突解决的过程不再是简单的线性递增，而是通过一种伪随机的方式来计算下一个槽位。

具体来说，伪随机探测会使用一个哈希函数和一个随机化的增量序列。当发生哈希冲突时，不再简单地递增到下一个槽位，而是根据当前槽位和随机化的增量序列来计算下一个槽位。这个增量序列在一开始就确定，但具有随机性质，因此称为“伪随机”。

伪随机探测的目的是尽可能地减少聚集（clustering）现象，因为使用简单的线性探测可能会导致连续的槽位被占用，增加后续发生冲突的概率。通过引入随机性，可以更均匀地分布冲突的元素，减少聚集的发生，提高哈希表的性能和稳定性。

主要是，链表最重要那些特性，需要"侵入式"链表才可以实现。  
而linkedlist恰好是非侵入式的，不暴露节点操作的，那这不就是扯淡么。。


- **“链表最重要那些特性，需要'侵入式'链表才可以实现。”**  
    指的是如果你想充分利用链表的优势（例如高效的节点操作、直接修改链接等），理想的设计是让数据对象自己带有指针信息（即侵入式设计）。这种设计能使得节点操作非常高效且灵活。
    
- **“而LinkedList恰好是非侵入式的，不暴露节点操作的。”**  
    指出 Java 的 `LinkedList` 实现采用了非侵入式的方式，它将节点封装在内部，不对外暴露。因此，开发者无法直接对节点进行操作，这样就限制了一些链表固有的优势（如在节点级别进行高效拼接、删除等操作）。
    
- **“那这不就是扯淡么。”**  
    表达了一种批评或不满的情绪，意思是如果一个链表的实现不允许直接操作节点，那么它就不能充分体现出链表应有的高效性和灵活性。这种观点认为，只有侵入式设计才能真正发挥链表的优势，而 Java 的 `LinkedList` 由于采用非侵入式设计，可能在某些场景下显得“缺乏说服力”或“不够高效”。


### 总结

- **侵入式链表**允许数据对象直接包含链接信息，便于高效操作，但耦合性较高。
- **非侵入式链表**通过内部封装节点来实现链表功能，降低了数据对象的耦合，但牺牲了一部分灵活性和高效的节点操作能力。
- 这段话的批评在于：如果我们想利用链表所有高效操作的特性（如快速拼接、拆分等），理论上需要侵入式链表的支持，而 Java 的 `LinkedList` 实现并不支持这一点，因此“达不到”理想状态。
