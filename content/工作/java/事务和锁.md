

1. `@DS("gaotuiProdDataSource")`: 这个注解来自于 `dynamic-datasource-spring-boot-starter` 库。它的核心作用是在方法执行**之前**，将当前线程的数据源切换到你指定的 `gaotuiProdDataSource`。在方法执行**完毕后**，再恢复到之前的数据源。
2. `@Transactional(rollbackFor = Exception.class)`: 这是 Spring 框架自带的标准事务注解。它的作用是在方法执行**之前**，开启一个数据库事务。在方法执行**完毕后**，根据方法是否抛出异常来决定是提交（commit）还是回滚（rollback）事务。


3. **`@DS` 切面先生效**：
    
    - 方法 `saveOrUpdateStudentScoreInfo` 被调用。
    - `@DS` 的 AOP 拦截器首先执行，它会将当前线程绑定的数据源切换为 `gaotuiProdDataSource`。
4. **`@Transactional` 切面后生效**：
    
    - 接着，`@Transactional` 的 AOP 拦截器执行。
    - 它向事务管理器请求开启一个新事务。
    - 事务管理器会从当前线程获取数据库连接来开启事务。由于上一步数据源已经被切换了，所以它获取到的是 `gaotuiProdDataSource` 的连接，并在这个连接上开启事务。




### 什么时候需要使用 `@DSTransactional`？

`@DSTransactional` 是 `dynamic-datasource` 库提供的用于**分布式事务**的注解。

你需要使用它的场景是：**当一个方法内需要操作多个不同的数据源，并希望这些操作能够统一成功或统一失败时。**


单库 ➜ 直接 `@Transactional` 就好  
多库混用 ➜ 上 `@DSTransactional` 或自己引入分布式事务方案（Seata、JTA 等）





- ✅ 使用 @DS 指定数据源

- ✅ 使用 @Transactional 管理事务

- ✅ 事务会自动在指定的数据源上执行

您不需要指定特定的事务管理器，因为主事务管理器已经配置为使用动态数据源，会自动跟随 @DS 注解的数据源切换。

## 注意事项

1. **继承性**：`@DS` 注解在类级别时，该类的所有方法都会使用指定数据源
2. **覆盖性**：方法级别的 `@DS` 会覆盖类级别的设置
3. <mark class="hltr-red">**事务传播：在事务传播过程中，数据源选择以事务开始时的为准**</mark>








**synchronized锁的是这个方法**，而@Transactional是Spring的AOP在开启时自动锁定的。在进入这个方法前，**AOP会先开启事务，然后进入方法**，此时会加锁。**当方法结束后，锁被释放，然后才会提交事务**。如果在锁释放和提交事务之间有其他线程请求并再次加锁，这可能导致程序不安全。


问题原因是： 锁的粒度太小。 有可能上一个事务未提交， 下一个事务就已经进入事务并开始等待锁，导致上一个事务对下一个事务不可见


解决：  增大锁粒度， 事务的开启和提交都在锁内。


但是不能偷懒锁住整个方法！！！！  因为此时锁在事务里面!!!
