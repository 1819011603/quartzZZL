4. 🔀 字段映射：不同的fieldNames集合

### **组合 vs. 继承的选择**

- 如果一个类**需要复用并扩展另一个类的行为**，且它们具有明确的“is-a”关系（如“Dog is an Animal”），则选择继承。
- 如果一个类**需要将多个独立的功能组合到一起**，或希望通过替换来增加灵活性（如“Car has an Engine”），则选择组合。





**策略模式**是一种行为设计模式，它的主要优点是将算法的使用和实现分离开来，使得算法可以独立于使用它的客户而变化。这种模式在实现时，会定义一系列算法，将每种算法封装到单独的策略类中，客户端可以在运行时动态选择不同的策略。

### 策略模式的优点

1. **开闭原则**：策略模式符合开闭原则（Open/Closed Principle），可以在不修改已有代码的情况下增加新的策略，方便扩展。
    
2. **代码复用和维护性**：将算法封装到不同的策略类中，使得每种算法实现相对独立，便于代码复用和后续的维护。
    
3. **消除条件判断**：如果没有策略模式，通常会用大量的条件语句（如 `if-else` 或 `switch`）来选择不同的算法。使用策略模式后，可以消除这些条件判断，使得代码更清晰。
    
4. **提高灵活性**：可以在运行时动态选择或切换策略，使得系统更具灵活性。
