```java
  /*

  STRONG {
```

### 关闭钩子方法

Java 原生的关闭钩子 **`Runtime.addShutdownHook()`**
Spring 提供的关闭钩子方法 `@PreDestroy` 注解


Spring 会在容器关闭时（`Context.close()` 或 `Context.stop()`）调用 `Lifecycle` 接口的 `stop()` 方法。

`Lifecycle.stop()` 的调用顺序取决于 `SmartLifecycle` 的 `phase` 值，`phase` 值越小越早执行，默认为 0。

- 由 Spring 的 Bean 销毁逻辑触发，发生在 Bean 生命周期的最后阶段。
- **当容器中的所有生命周期相关的操作（包括 `Lifecycle.stop()` 方法）完成后，Spring 会调用带有 `@PreDestroy` 的方法**。

### **为什么 `Lifecycle.stop()` 先调用？**

1. Spring 的 `LifecycleProcessor` 是在容器关闭时优先触发的组件，用于管理实现了 `Lifecycle` 接口的所有 Bean。
    - 它会在容器关闭之前调用所有组件的 `stop()` 方法。
2. `@PreDestroy` 是在 Spring 销毁 Bean 阶段触发的（由 `DefaultLifecycleBeanPostProcessor` 实现），发生在 `stop()` 方法调用之后。

```java
public class ScheduledThreadPoolExectuorWithDynamicSize extends ScheduledThreadPoolExecutor {  
  
    private final Thread shutdownThread;  
      
    public ScheduledThreadPoolExectuorWithDynamicSize(final DynamicIntProperty corePoolSize, ThreadFactory threadFactory) {  
        super(corePoolSize.get(), threadFactory);  
        corePoolSize.addCallback(new Runnable() {  
            public void run() {  
                setCorePoolSize(corePoolSize.get());  
            }  
        });  
        shutdownThread = new Thread(new Runnable() {  
            public void run() {  
                shutdown();  
                if (shutdownThread != null) {  
                    try {  
                        Runtime.getRuntime().removeShutdownHook(shutdownThread);  
                    } catch (IllegalStateException ise) { // NOPMD  
                    }  
                }  
            }  
        });  
        Runtime.getRuntime().addShutdownHook(shutdownThread);  
    }  
}

```

通过调用 Runtime.getRuntime().addShutdownHook(shutdownThread);，我们将这个 shutdownThread 注册为一个关闭钩子。这样，当JVM开始关闭时，这个钩子线程会被调用，确保 ScheduledThreadPoolExecutor 能够被正确地关闭，避免资源泄漏或未完成的任务。


使用 java.lang.Runtime.addShutdownHook 的替代方法： 可以创建一个自定义的关闭钩子管理器，集中管理所有需要在 JVM 关闭时执行的清理操作。

也可以使用 java.lang.Runtime.addShutdownHook 的替代方法： 可以创建一个自定义的关闭钩子管理器，集中管理所有需要在 JVM 关闭时执行的清理操作。
```java
import java.util.ArrayList;
import java.util.List;

public class ShutdownHookManager {
    private static final List<Runnable> hooks = new ArrayList<>();

    public static void addHook(Runnable hook) {
        hooks.add(hook);
    }

    private static void runHooks() {
        for (Runnable hook : hooks) {
            try {
                hook.run();
            } catch (Exception e) {
                // 记录异常或进行其他处理
                e.printStackTrace();
            }
        }
        hooks.clear(); // 清除所有的钩子
    }

    static {
        Runtime.getRuntime().addShutdownHook(new Thread(ShutdownHookManager::runHooks));
    }
}
```


### 静态属性 反射Field.get(obj) obj可以为null

在这段代码中，Field.get(null) 用于获取静态字段的值。根据 Java 反射机制，如果要获取一个静态字段的值，可以将 get 方法的参数设置为 null。这是因为静态字段属于类本身，而不是类的某个实例。因此，不需要提供具体的对象来获取静态字段的值

```java
for (Field f: CommonClientConfigKey.class.getDeclaredFields()) {

        } catch (IllegalAccessException e) {
            throw new RuntimeException(e);
        }
    }
}
```

### 单一Bean 初始化执行方法顺序

1. Bean对象的初始化方法; 初始化之后设置依赖的其他Bean
2. 调用有 `@PostConstruct` 注解的方法;
3. 如果实现了 `BeanNameAware`接口, 调用 setBeanName方法设置Bean的ID或者Name;
4. 如果实现了 `BeanFactoryAware`接口, 调用 setBeanFactory方法设置BeanFactory;
5. 如果实现了 `ApplicationContextAware`接口, 调用 setApplicationContext方法设置ApplicationContext;
6. 如果实现了 `BeanPostProcessor`接口, 调用 BeanPostProcessor的预先初始化方法;
7. 如果实现了 `InitializingBean`接口, 调用 InitializingBean的afterPropertiesSet方法;
8. 如果是 `@Bean` 方式注册，调用指定的init-method方法;
9. 如果实现了 `BeanDefinitionRegistryPostProcessor`接口, 调用 postProcessBeanDefinitionRegistry;  所有常规 bean 定义都已加载，但尚未实例化任何 bean。可以修改Bean定义。
10. 如果实现了 `BeanPostProcessor`接口, 调用 BeanPostProcessor的后初始化方法;
