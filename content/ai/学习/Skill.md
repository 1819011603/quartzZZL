
**Skill 本质上就是把一类重复任务，固化成“目标 + 输入 + 流程 + 约束 + 验收标准”**。


AI 最适合做三类事：

1. **把模糊输入变成结构化输出**  
    比如需求描述 → 接口文档、任务拆解、页面草图、测试用例。
    
2. **把固定流程自动化**  
    比如写 Dockerfile、生成 CRUD 页面、检查日志、生成发布文档。
    
3. **在约束下做探索**  
    比如排查 bug、优化 SQL、重构代码。这里不能完全放任 AI，要给边界和验证方式。


Prompt：一次性的指令
Template：可复用的提示模板
Skill：固定任务流程 + 约束 + 验收标准
Agent：能连续执行多个步骤、读文件、改代码、跑测试
Workflow：多个 Skill/Agent 组合成完整业务流程




1. 任务目标：最终要交付什么
2. 输入材料：需要哪些文件、接口、日志、配置
3. 执行流程：先看什么，再改什么，最后验证什么
4. 约束条件：不能动哪些文件，遵守什么规范
5. 验收标准：如何判断完成
6. 失败处理：遇到不确定时怎么问、怎么降级



第一阶段：Prompt 模板化
**第二阶段：Skill 化**  
把重复任务写成固定流程，比如：

- 日志排障 Skill
- Docker 部署 Skill
- CI/CD 生成 Skill
- OpenAPI 到前端页面 Skill
- SQL 优化 Skill
- 代码 Review Skill

**第三阶段：Agent 化**  
让 AI 不只是回答，而是：

```
读项目 → 修改文件 → 运行测试 → 根据报错继续修 → 总结结果
```

这一步效率提升最大。


**第四阶段：Workflow 化**  
把多个 Skill 串起来：

```
需求 → 接口设计 → 后端代码 → 测试 → 文档 → Docker → CI/CD → 发布
```

你可以把 AI 当成一个“不稳定但很快的初级同事”。  
你的价值不是亲手写每一行，而是设计流程、设约束、做验收。
